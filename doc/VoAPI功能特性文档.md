## 一、项目概述

### 1.1 项目简介

**VoAPI** 是一个全新的高颜值、高性能、高扩展的智能 AI 大模型 API 聚合分发系统。它基于 One API 的核心理念进行深度二次开发，参考 New API 的先进设计理念，致力于打造下一代 AI 网关与 AI 资产管理平台。

### 1.2 项目定位

| 定位维度 | 说明 |
|---------|------|
| **AI 网关** | 通过标准 OpenAI API 格式访问所有 LLM，屏蔽底层厂商差异 |
| **AI 资产管理** | 统一管理渠道、令牌、用户、计费等数字资产 |
| **多租户平台** | 支持多用户注册、分组管理、独立计费 |
| **商业化运营** | 内置完善的用户运营、支付、营销功能 |

### 1.3 核心价值

- **对开发者**: 一次接入，调用所有主流 AI 模型
- **对运营者**: 完整的用户管理、计费系统、数据看板
- **对管理者**: 丰富的监控日志、安全管控、数据分析

### 1.4 项目信息

| **当前版本** | v1.2.0 |

## 二、技术架构

### 2.1 整体架构图

```
┌──────────────────────────────────────────────────────────────┐
│                        客户端层                              │
│  Claude Code / ChatGPT Next Web / Cherry Studio / 自研客户端  │
└────────────────────────────┬─────────────────────────────────┘
                             │ HTTP / SSE
┌────────────────────────────▼─────────────────────────────────┐
│                     VoAPI 网关层                             │
│  ┌─────────────┐  ┌──────────────┐  ┌──────────────────┐    │
│  │  认证中间件  │  │  规则引擎    │  │  智能路由分发    │    │
│  │  Token 验证  │  │  JS 自定义   │  │  负载均衡        │    │
│  │  IP/UA 过滤  │  │  请求转换    │  │  故障转移        │    │
│  └─────────────┘  └──────────────┘  └──────────────────┘    │
│  ┌──────────────────────────────────────────────────────┐    │
│  │              协议转换与适配层                         │    │
│  │  OpenAI ↔ Anthropic ↔ Gemini ↔ 各厂商原生格式        │    │
│  └──────────────────────────────────────────────────────┘    │
└────────────────────────────┬─────────────────────────────────┘
                             │
┌────────────────────────────▼─────────────────────────────────┐
│                     上游渠道层                               │
│  OpenAI / Anthropic / Gemini / 通义千问 / 文心 / DeepSeek   │

└──────────────────────────────────────────────────────────────┘

数据持久化层:
  MySQL (主库) + MySQL-Log (日志库) + MySQL-Body-Log (请求体库)
  Redis (缓存 + 会话 + 限流)
```

### 2.2 技术栈

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| **后端** | Go (Golang) | 原生高并发，低内存占用 |
| **Web 框架** | Gin (推断) | 高性能 HTTP 框架 |
| **ORM** | GORM (推断) | 支持 MySQL / PostgreSQL |
| **缓存** | Redis | 连接池可配置，默认 CPU*100 |
| **主数据库** | MySQL 8.0+ / PostgreSQL | 可配置切换 |
| **日志数据库** | MySQL / PostgreSQL / ClickHouse | 支持独立部署 |
| **前端** | 现代前端框架 (推断 Vue/React) | 响应式设计 |
| **部署** | Docker / Docker Compose | 容器化部署 |
| **架构支持** | Linux amd64 / arm64 | 多平台支持 |

### 2.3 数据库架构

VoAPI 采用**三库分离**架构：

| 数据库 | 用途 | 说明 |
|--------|------|------|
| **voapi** | 主数据库 | 用户、渠道、令牌、配置等核心数据 |
| **voapi-log** | 日志数据库 | API 调用日志、操作日志 |
| **voapi-body-log** | 请求体日志库 | 完整的请求/响应体日志，数据量大 |

**数据库分表策略**：支持按 天/周/月/年 四个维度自动分表

## 五、渠道管理系统

### 5.1 渠道架构

```
                    ┌─────────────────┐
                    │   渠道分组 A     │
    用户请求 ────▶  │  渠道 1 (权重 3) │
                    │  渠道 2 (权重 1) │
                    └─────────────────┘
                    ┌─────────────────┐
                    │   渠道分组 B     │
                    │  渠道 3 (权重 2) │
                    │  渠道 4 (权重 2) │
                    └─────────────────┘
```

### 5.2 渠道管理功能

| 功能 | 说明 |
|------|------|
| **渠道 CRUD** | 创建、查询、编辑、删除渠道 |
| **渠道分组** | 将渠道按用途/价格/地域分组管理 |
| **多 Key 管理** | 一个渠道支持多个 API Key |
| **模型列表配置** | 每个渠道可配置支持的模型列表 |
| **BaseURL 自定义** | 支持自定义 API 地址（代理/镜像） |
| **优先级设置** | 高优先级渠道优先使用 |
| **权重设置** | 同优先级按权重分配流量 |
| **渠道测试** | 测试渠道连通性 |
| **余额同步** | 从上游渠道同步余额信息 |

### 5.3 渠道分组策略

| 策略类型 | 说明 | 配置方式 |
|---------|------|---------|
| **固定倍率** | 分组设置固定倍率 | 如分组倍率 1.5 |
| **定时倍率** | 按时间段设置不同倍率 | 如夜间 0.8 折，白天 1.0 |
| **负载均衡** | 组内渠道按权重分发 | 权重越高流量越大 |
| **故障转移** | 主渠道失败自动切换到备用 | 重试机制 |

### 5.4 渠道限流 (RPM/TPM)

VoAPI 提供三维度的限流能力：

| 限流维度 | 说明 | 配置 |
|---------|------|------|
| **渠道级 RPM** | 整个渠道每分钟最大请求数 | 全局配置 |
| **单密钥 RPM** | 渠道中单个 Key 每分钟最大请求数 | Key 级配置 |
| **用户级 RPM/TPM** | 每个用户每分钟请求数/每分钟 Token 数 | 用户配置 |

**RPM**: Requests Per Minute (每分钟请求数)
**TPM**: Tokens Per Minute (每分钟 Token 数)

### 5.5 渠道容错机制

| 机制 | 触发条件 | 处理方式 |
|------|---------|---------|
| **密钥错误禁用** | API Key 无效/过期 | 可禁用单个 Key，或仅禁用该 Key 中的当前模型 |
| **自动恢复** | 密钥被禁用后 | 定时检查并自动恢复可用 Key |
| **请求熔断** | 连续失败或超时 | 熔断该渠道，避免雪崩 |
| **超时机制** | 请求超过设定时间 | 终止请求并尝试其他渠道 |
| **自动重试** | 请求失败 | 按配置重试次数尝试其他渠道 |

### 5.6 代理配置

| 代理类型 | 支持协议 | 说明 |
|---------|---------|------|
| **全局代理** | HTTP / HTTPS / Socket5 | 所有渠道共用一个代理 |
| **独立代理** | HTTP / HTTPS / Socket5 | 每个渠道可配置独立代理 |

### 5.7 IP/UA 规则

| 规则类型 | 说明 |
|---------|------|
| **IP 白名单** | 仅允许指定 IP 访问渠道 |
| **IP 黑名单** | 禁止指定 IP 访问渠道 |
| **UA 过滤** | 根据 User-Agent 允许/拒绝请求 |

## 七、计费与支付系统

### 7.1 计费模型

VoAPI 提供灵活的计费体系：

| 计费模式 | 说明 | 示例 |
|---------|------|------|
| **固定价格** | 每次请求固定收费 | 如每次调用 0.01 元 |
| **基础倍率** | 基于上游价格乘以倍率 | 如上游价格 × 1.5 |
| **阶梯计费** | 不同用量区间不同价格 | 0-1000 tokens 一个价，1000+ 另一价 |
| **多条件计费** | 组合多个条件进行计费 | 模型+用户等级+时间段 |

### 7.2 倍率体系

VoAPI 采用**多优先级倍率**机制：

| 倍率类型 | 说明 | 计算公式 |
|---------|------|---------|
| **模型倍率** | 不同模型有不同的倍率 | 基础价格 × 模型倍率 |
| **分组倍率** | 不同渠道分组的倍率 | 上述结果 × 分组倍率 |
| **用户等级倍率** | 不同用户等级的优惠倍率 (推断) | 上述结果 × 等级倍率 |
| **定时倍率** | 不同时间段的倍率 | 上述结果 × 时段倍率 |

**最终价格 = 上游价格 × 模型倍率 × 分组倍率 × 其他倍率**

### 7.3 额度消费流程

```
1. 用户发起 API 请求
      │
2. 计算预估费用 (基于 prompt tokens)
      │
3. 预扣额度 (Pre-Consume)
      │
4. 转发请求到上游渠道
      │
5. 获取实际响应 (含 completion tokens)
      │
6. 计算实际费用
      │
7. 差额调整 (多退少补)
      │
8. 记录日志
```

## 八、规则引擎系统

### 8.1 概述

规则引擎是 VoAPI 的核心创新功能，允许用户通过 **JavaScript (ES5/ES6)** 代码自定义请求/响应处理逻辑。

### 8.2 规则引擎能力

| 能力 | 说明 |
|------|------|
| **请求转换** | 修改请求体、Header、URL 等 |
| **响应转换** | 修改响应体、状态码等 |
| **模型路由** | 根据请求内容动态选择渠道/模型 |
| **参数增强** | 自动添加/修改请求参数 |
| **条件过滤** | 根据条件拒绝或放行请求 |
| **日志记录** | 自定义日志输出 |

### 8.3 使用场景

| 场景 | 示例 |
|------|------|
| **模型映射** | 将 `gpt-4` 请求路由到 `claude-sonnet-4` |
| **参数覆盖** | 自动设置 `max_tokens`、`temperature` |
| **内容过滤** | 检测并拦截敏感词 |
| **格式转换** | Anthropic ↔ OpenAI 格式互转 |
| **动态定价** | 根据请求内容调整倍率 |
| **A/B 测试** | 随机分配流量到不同渠道 |

### 8.4 规则引擎示例

```javascript
// 示例 1: 完全透传 (不修改任何内容)
function onRequest(request) {
    return request;
}

// 示例 2: 修改模型名称
function onRequest(request) {
    if (request.model === "gpt-4") {
        request.model = "claude-sonnet-4-20250514";
    }
    return request;
}

// 示例 3: 添加系统提示词
function onRequest(request) {
    request.messages.unshift({
        role: "system",
        content: "你是一个专业的编程助手。"
    });
    return request;
}

// 示例 4: 根据内容路由
function onRequest(request) {
    const lastMessage = request.messages[request.messages.length - 1];
    if (lastMessage.content.includes("代码")) {
        return { ...request, targetGroup: "coding-models" };
    }
    return request;
}
```

### 8.5 规则引擎 vs 渠道映射

| 特性 | 规则引擎 | 渠道映射 |
|------|---------|---------|
| **灵活性** | 极高，可编写任意逻辑 | 低，仅支持固定映射 |
| **学习成本** | 需要 JS 基础 | 无需编程 |
| **适用场景** | 复杂业务逻辑 | 简单模型替换 |
| **性能影响** | 轻微 (JS 引擎执行) | 无影响 |

| **三库分离** | ❌ 不支持 | ❌ 不支持 | ✅ 主库+日志库+请求体库 |

### 13.3 VoAPI 的差异化优势

| 优势 | 说明 |
|------|------|
| **规则引擎** | 最大的差异化特性，可通过 JS 实现任意自定义逻辑 |
| **高颜值 UI** | 全新设计的现代化界面，远超 One API 和 New API |
| **日志分表** | 企业级日志管理，支持大数据量场景 |
| **多维限流** | 用户/渠道/单密钥三个维度精确控制 |
| **多余额/货币** | 灵活的财务管理体系 |
| **运营功能完善** | 签到、等级、兑换码等用户运营功能 |
