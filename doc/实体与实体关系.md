## 一、文档概述

本文档基于 LLM-Gateway 项目需求规格说明书，整合 APIPark 的实体设计，形成完整的实体模型与关系网络。本文档是 LLM-Gateway 项目的关键设计文档，用于指导数据库设计、代码实现和系统集成。

### 1.1 三大系统定位差异

| 维度 | LLM-Gateway | APIPark |
|------|-------------|---------|
| **目标用户** | 企业中台/大型团队/政企客户 | 企业 API 开放平台/多租户 SaaS |
| **核心差异** | 团队隔离/三级预算/安全合规 | API 生命周期管理/订阅审批 |
| **用户体系** | Team + Member + Role (多对多) | Team + Member + Role (系统级/团队级) |
| **计费模式** | 三级预算（团队/用户/模型） | 流量配额管理（Coming Soon） |
| **规则引擎** | 可视化策略编排 + 脚本扩展 | 自定义 Channel 接入 |
| **数据库架构** | 共享 Schema + team_id 行级隔离 | 共享 Schema + 行级隔离 |
| **服务类型** | AI Service + REST Service | AI Service + REST Service |
| **订阅审批** | 令牌级订阅 | Consumer + Subscription + 审批流程 |

### 1.2 实体域划分

根据业务领域，将实体划分为以下六大域：

```
┌─────────────────────────────────────────────────────────────┐
│                      实体域划分                              │
├─────────────────────────────────────────────────────────────┤
│  ① 身份与访问控制域    │  用户、角色、权限、团队(Member)     │
│  ② 渠道与模型域        │  供应商、模型、渠道、渠道分组、密钥  │
│  ③ 令牌与认证域        │  API令牌、令牌额度、访问记录         │
│  ④ Token额度域     │  TokenLimit、TokenUsage、TokenLimitAlert   │
│  ⑤ 日志与监控域        │  调用日志、请求体日志、审计日志      │
│  ⑥ 安全与风控域        │  敏感词、PII规则、IP黑白名单、限流   │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 实体清单总览

| ③ 令牌与认证 | 3 | ApiToken, TokenQuota, TokenAccessLog |
| ④ Token额度 | 3 | TokenLimit, TokenUsage, TokenLimitAlert |

| **合计** | **30** | |

## 二、核心实体详解

### 2.1 身份与访问控制域

#### 2.1.1 Team（团队）

**定义**: 隔离边界单元，代表一个团队或组织。所有业务数据通过 team_id 字段进行隔离。

| 属性 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | BIGINT | 主键 | PK, AUTO_INCREMENT |
| team_code | VARCHAR(64) | 团队编码 | UNIQUE, NOT NULL |
| team_name | VARCHAR(128) | 团队名称 | NOT NULL |
| description | TEXT | 描述 | NULL |
| admin_id | BIGINT | 团队管理员ID | FK → User.id, NULL |
| status | ENUM | 状态 | ACTIVE / SUSPENDED / DELETED |
| created_at | TIMESTAMP | 创建时间 | NOT NULL, DEFAULT CURRENT_TIMESTAMP |
| updated_at | TIMESTAMP | 更新时间 | NOT NULL, ON UPDATE CURRENT_TIMESTAMP |
| deleted_at | TIMESTAMP | 删除时间 | NULL（软删除） |

**APIPark 对应**: APIPark 的 Team 实体，功能一致。

#### 2.1.2 Member（成员）

**定义**: 用户与团队的多对多关联表，记录用户所属团队及其角色。

| 属性 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | BIGINT | 主键 | PK, AUTO_INCREMENT |
| user_id | BIGINT | 用户ID | FK → User.id, NOT NULL, INDEX |
| team_id | BIGINT | 团队ID | FK → Team.id, NOT NULL, INDEX |
| team_role | VARCHAR(32) | 团队内角色 | 如 "管理员"、"开发者"、"观察者" |
| joined_at | TIMESTAMP | 加入时间 | NOT NULL |

**唯一约束**: `(user_id, team_id)` 联合唯一。

**APIPark 对应**: APIPark 的 Member 实体，功能一致。

#### 2.1.3 User（用户）

**定义**: 系统用户实体，支持多角色绑定和多团队访问。用户通过 OAuth 或用户名密码认证。

| 属性 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | BIGINT | 主键 | PK, AUTO_INCREMENT |
| user_code | VARCHAR(64) | 用户编码 | UNIQUE, NOT NULL |
| username | VARCHAR(64) | 用户名 | NOT NULL |
| email | VARCHAR(128) | 邮箱 | UNIQUE, NOT NULL |
| password_hash | VARCHAR(256) | 密码哈希 | BCrypt 加密，cost≥12 |
| phone | VARCHAR(32) | 手机号 | NULL |
| avatar_url | VARCHAR(512) | 头像URL | NULL |
| status | ENUM | 状态 | ACTIVE / DISABLED / LOCKED / DELETED |
| email_verified | BOOLEAN | 邮箱已验证 | DEFAULT false |
| oauth_providers | JSON | OAuth提供者列表 | GitHub / Gitee / LinuxDO |
| pii_salt | VARCHAR(64) | PII脱敏盐值 | GDPR 删除权用 |
| last_login_at | TIMESTAMP | 最后登录时间 | NULL |
| created_at | TIMESTAMP | 创建时间 | NOT NULL |
| updated_at | TIMESTAMP | 更新时间 | NOT NULL |
| deleted_at | TIMESTAMP | 删除时间 | NULL |
| version | INT | 乐观锁版本号 | NOT NULL, DEFAULT 0 |

#### 2.1.4 Role（角色）

**定义**: 权限集合，用于简化权限管理和批量授权。角色分为 SYSTEM（预定义）和 CUSTOM（自定义）两种类型。

| 属性 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | BIGINT | 主键 | PK, AUTO_INCREMENT |
| role_code | VARCHAR(64) | 角色编码 | UNIQUE, NOT NULL |
| name | VARCHAR(64) | 角色名称 | NOT NULL |
| description | TEXT | 角色描述 | NULL |
| role_type | ENUM | 角色类型 | SYSTEM / CUSTOM |
| scope_type | ENUM | 权限范围 | SYSTEM / TEAM |
| scope_id | BIGINT | 范围ID | 当 scope_type 为 TEAM 时必填 |
| is_active | BOOLEAN | 是否启用 | DEFAULT true |
| created_at | TIMESTAMP | 创建时间 | NOT NULL |
| updated_at | TIMESTAMP | 更新时间 | NOT NULL |
| deleted_at | TIMESTAMP | 删除时间 | NULL |

**预设角色**（SYSTEM 类型）:

| 角色 | 编码 | 权限范围 | 说明 |
|------|------|----------|------|
| 团队管理员 | TEAM_ADMIN | TEAM | 团队级全部权限 |
| 开发者 | DEVELOPER | TEAM | 创建令牌、查看日志、调用API |
| 观察者 | OBSERVER | TEAM | 仅查看用量和日志 |
| 财务管理员 | FINANCE_ADMIN | TEAM | 预算配置、费用查看 |

#### 2.1.5 Permission（权限）

**定义**: 细粒度权限码，定义到具体的操作级别。权限是 RBAC 系统的最小授权单元。

| 属性 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | BIGINT | 主键 | PK, AUTO_INCREMENT |
| permission_code | VARCHAR(128) | 权限编码 | UNIQUE, NOT NULL |
| name | VARCHAR(64) | 权限名称 | NOT NULL |
| description | TEXT | 权限描述 | NULL |
| category | VARCHAR(32) | 权限分类 | user / channel / budget / log / setting |
| created_at | TIMESTAMP | 创建时间 | NOT NULL |

**权限编码规范**: `resource:action` 格式。

示例权限码:
```
user:create    user:read    user:update    user:delete
channel:create  channel:read  channel:update  channel:delete
budget:create  budget:read  budget:update  budget:delete
token:create    token:read   token:revoke
log:read        audit:read
setting:read    setting:update
```

### 2.2 渠道与模型域

#### 2.2.1 Provider（供应商）

**定义**: 模型服务提供方，如 OpenAI、Anthropic、通义千问等。供应商是模型的上层分类单位。

| 属性 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | BIGINT | 主键 | PK, AUTO_INCREMENT |
| provider_code | VARCHAR(64) | 供应商编码 | UNIQUE, NOT NULL |
| name | VARCHAR(128) | 供应商名称 | NOT NULL |
| website | VARCHAR(256) | 官网URL | NULL |
| api_doc_url | VARCHAR(256) | API文档URL | NULL |
| logo_url | VARCHAR(512) | Logo URL | NULL |
| status | ENUM | 状态 | ACTIVE / INACTIVE |
| created_at | TIMESTAMP | 创建时间 | NOT NULL |
| updated_at | TIMESTAMP | 更新时间 | NOT NULL |
| deleted_at | TIMESTAMP | 删除时间 | NULL |

**APIPark 对应**: APIPark 称之为 Provider，功能基本一致。

#### 2.2.2 Model（模型）

**定义**: 具体的 AI 模型，是调用的最小单位。模型通过 Provider 归属供应商。

> **重要**: 网关不负责实际计费，模型定价由模型提供方管理。网关仅跟踪Token使用量。

| 属性 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | BIGINT | 主键 | PK, AUTO_INCREMENT |
| model_code | VARCHAR(128) | 模型编码 | UNIQUE, NOT NULL |
| provider_id | BIGINT | 所属供应商 | FK → Provider.id, NOT NULL, INDEX |
| name | VARCHAR(128) | 模型名称 | NOT NULL |
| description | TEXT | 模型描述 | NULL |
| context_length | INT | 上下文长度 | 单位：tokens |
| multimodal | BOOLEAN | 是否支持多模态 | DEFAULT false |
| tool_use | BOOLEAN | 是否支持工具调用 | DEFAULT false |
| thinking | BOOLEAN | 是否支持思考过程 | DEFAULT false |
| is_active | BOOLEAN | 是否启用 | DEFAULT true |
| created_at | TIMESTAMP | 创建时间 | NOT NULL |
| updated_at | TIMESTAMP | 更新时间 | NOT NULL |
| deleted_at | TIMESTAMP | 删除时间 | NULL |

**索引**:
```sql
INDEX idx_model_provider (provider_id)
INDEX idx_model_active (is_active)
```

**Model 与 Channel 的 M:N 关系**:
> **重要结论**: Model 与 Channel 是**多对多（M:N）**关系。
>
> - 一个 Model 可以通过多个 Channel 访问（如 GPT-4o 可通过 OpenAI Channel 和 Azure OpenAI Channel）
> - 一个 Channel 可以服务多个 Model（如 OpenAI Channel 服务 GPT-4o、GPT-4-turbo）
>
> 这通过 `Channel.models` JSON 字段和实际调用时的路由选择实现。

#### 2.2.3 Channel（渠道）

**定义**: 通往 Provider 的具体连接实例。渠道配置了连接上游服务商所需的信息，并可归属到特定分组参与负载均衡。

| 属性 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | BIGINT | 主键 | PK, AUTO_INCREMENT |
| channel_code | VARCHAR(64) | 渠道编码 | UNIQUE, NOT NULL |
| team_id | BIGINT | 所属团队 | FK → Team.id, NOT NULL, INDEX |
| provider_id | BIGINT | 所属供应商 | FK → Provider.id, NOT NULL |
| group_id | BIGINT | 所属分组 | FK → ChannelGroup.id, NULL, INDEX |
| name | VARCHAR(128) | 渠道名称 | NOT NULL |
| base_url | VARCHAR(512) | API地址 | 支持代理/镜像 |
| models | JSON | 支持的模型列表 | ["gpt-4o", "gpt-4-turbo"] |
| status | ENUM | 状态 | ACTIVE / DISABLED / ERROR |
| priority | INT | 优先级 | 数值越小优先级越高 |
| is_load_balance | BOOLEAN | 是否参与负载均衡 | DEFAULT false |
| load_balance_ratio | INT | 负载均衡权重 | 默认1 |
| circuit_breaker_threshold | INT | 熔断阈值 | 连续失败次数 |
| circuit_breaker_timeout | INT | 熔断恢复时间 | 单位：秒 |
| timeout_seconds | INT | 超时时间 | 单位：秒 |
| retry_count | INT | 重试次数 | 默认3 |
| proxy_type | ENUM | 代理类型 | NONE / HTTP / HTTPS / SOCKS5 |
| proxy_url | VARCHAR(512) | 代理地址 | proxy_type 不为 NONE 时必填 |
| auto_recovery_enabled | BOOLEAN | 自动恢复启用 | DEFAULT true |
| auto_recovery_interval | INT | 自动恢复间隔 | 单位：分钟 |
| rpm_limit | INT | 渠道级RPM限制 | 每分钟请求数 |
| tpm_limit | INT | 渠道级TPM限制 | 每分钟Token数 |
| created_at | TIMESTAMP | 创建时间 | NOT NULL |
| updated_at | TIMESTAMP | 更新时间 | NOT NULL |
| deleted_at | TIMESTAMP | 删除时间 | NULL |
| version | INT | 乐观锁版本号 | NOT NULL, DEFAULT 0 |

**索引**:
```sql
INDEX idx_channel_team_status (team_id, status)
INDEX idx_channel_team_priority (team_id, priority)
INDEX idx_channel_group (group_id)
```

#### 2.2.4 ChannelGroup（渠道分组）

**定义**: 渠道分组，用于负载均衡和路由策略。分组定义了组内渠道的路由策略和基础倍率。

| 属性 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | BIGINT | 主键 | PK, AUTO_INCREMENT |
| group_code | VARCHAR(64) | 分组编码 | team_id 内 UNIQUE, NOT NULL |
| team_id | BIGINT | 所属团队 | FK → Team.id, NOT NULL, INDEX |
| name | VARCHAR(128) | 分组名称 | NOT NULL |
| description | TEXT | 分组描述 | NULL |
| strategy_type | ENUM | 路由策略 | COST_OPTIMIZED / LATENCY_OPTIMIZED / LOAD_BALANCED / PRIORITY |
| base_ratio | DECIMAL(5,2) | 基础倍率 | 默认1.0 |
| status | ENUM | 状态 | ACTIVE / DISABLED |
| created_at | TIMESTAMP | 创建时间 | NOT NULL |
| updated_at | TIMESTAMP | 更新时间 | NOT NULL |
| deleted_at | TIMESTAMP | 删除时间 | NULL |

#### 2.2.5 ChannelKey（渠道密钥）

**定义**: 渠道下的单个 API Key，支持多 Key 管理实现 Key 级故障隔离和限流。

> **重要**: 敏感凭证（api_key）存储在 ApiKeySecret 实体中，ChannelKey 仅持有引用和业务状态。

| 属性 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | BIGINT | 主键 | PK, AUTO_INCREMENT |
| channel_id | BIGINT | 所属渠道 | FK → Channel.id, NOT NULL, INDEX |
| secret_id | BIGINT | 密钥存储引用 | FK → ApiKeySecret.id, NOT NULL |
| status | ENUM | 状态 | ACTIVE / DISABLED / ERROR / EXHAUSTED |
| rpm_limit | INT | 单Key RPM限制 | 覆盖渠道级限制，0表示继承渠道设置 |
| tpm_limit | INT | 单Key TPM限制 | 覆盖渠道级限制，0表示继承渠道设置 |
| error_count | INT | 连续错误次数 | 用于自动禁用 |
| consecutive_success | INT | 连续成功次数 | 用于自动恢复后验证 |
| disabled_at | TIMESTAMP | 禁用时间 | NULL |
| disabled_reason | VARCHAR(256) | 禁用原因 | NULL |
| last_success_at | TIMESTAMP | 最后成功时间 | NULL |
| last_error_at | TIMESTAMP | 最后错误时间 | NULL |
| created_at | TIMESTAMP | 创建时间 | NOT NULL |
| updated_at | TIMESTAMP | 更新时间 | NOT NULL |

**索引**:
```sql
INDEX idx_channel_key_channel (channel_id)
INDEX idx_channel_key_status (status)
```

#### 2.2.6 Strategy（策略）

**定义**: 路由/计费/限流等规则的配置集合。策略通过节点树结构定义复杂的业务流程。

| 属性 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | BIGINT | 主键 | PK, AUTO_INCREMENT |
| strategy_code | VARCHAR(128) | 策略编码 | team_id 内 UNIQUE, NOT NULL |
| team_id | BIGINT | 所属团队 | FK → Team.id, NOT NULL, INDEX |
| name | VARCHAR(128) | 策略名称 | NOT NULL |
| description | TEXT | 策略描述 | NULL |
| type | ENUM | 策略类型 | ROUTING / BILLING / RATE_LIMIT / CONTENT_FILTER |
| config_json | JSON | 策略配置 | 节点树结构 |
| version | INT | 策略版本 | 用于版本管理和回滚 |
| status | ENUM | 状态 | DRAFT / ACTIVE / SUSPENDED |
| created_at | TIMESTAMP | 创建时间 | NOT NULL |
| updated_at | TIMESTAMP | 更新时间 | NOT NULL |
| deleted_at | TIMESTAMP | 删除时间 | NULL |

#### 2.2.7 StrategyNode（策略节点）

**定义**: 策略编排中的单个节点配置。节点支持条件分支、路由选择、参数转换等操作。

| 属性 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | BIGINT | 主键 | PK, AUTO_INCREMENT |
| strategy_id | BIGINT | 所属策略 | FK → Strategy.id, NOT NULL, INDEX |
| node_type | ENUM | 节点类型 | CONDITION / ROUTE / TRANSFORM / RATE_LIMIT / BUDGET_CHECK / DEGRADE |
| node_config | JSON | 节点配置 | type-specific 配置 |
| parent_node_id | BIGINT | 父节点ID | FK → StrategyNode.id, NULL 表示根节点 |
| order_index | INT | 执行顺序 | 同父节点下按 order_index 升序执行 |
| created_at | TIMESTAMP | 创建时间 | NOT NULL |
| updated_at | TIMESTAMP | 更新时间 | NOT NULL |

**节点类型说明**:

| 节点类型 | 说明 | node_config 示例 |
|----------|------|------------------|
| CONDITION | 条件分支 | `{"field": "model", "operator": "in", "value": ["gpt-4"]}` |
| ROUTE | 路由选择 | `{"targetGroup": "group_code", "fallbackChannel": "channel_code"}` |
| TRANSFORM | 参数转换 | `{"temperature": 0.7, "max_tokens": 1000}` |
| RATE_LIMIT | 限流节点 | `{"rpm": 100, "tpm": 50000}` |
| BUDGET_CHECK | 预算检查 | `{"budgetId": 123, "action": "REJECT"}` |
| DEGRADE | 降级节点 | `{"targetModel": "gpt-3.5-turbo", "reason": "budget_exceeded"}` |

### 2.3 令牌与认证域

#### 2.3.1 ApiToken（API令牌）

**定义**: 用户 API 调用凭证，格式为 `sk-xxxxxxxxxxxxxxxx`。令牌是 API 访问的最小授权单元。

| 属性 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | BIGINT | 主键 | PK, AUTO_INCREMENT |
| token_key | VARCHAR(128) | 令牌Key | sk- 开头，UNIQUE，NOT NULL |
| token_key_prefix | VARCHAR(16) | Key前缀 | sk- 后 8 位，用于展示和索引 |
| user_id | BIGINT | 所属用户 | FK → User.id, NOT NULL, INDEX |
| team_id | BIGINT | 所属团队 | FK → Team.id, NOT NULL, INDEX |
| name | VARCHAR(128) | 令牌名称 | 用户自定义别名 |
| description | TEXT | 令牌描述 | NULL |
| status | ENUM | 状态 | ACTIVE / SUSPENDED / EXPIRED / DELETED |
| expire_at | TIMESTAMP | 过期时间 | NULL 表示永不过期 |
| last_used_at | TIMESTAMP | 最后使用时间 | NULL |
| last_used_ip | VARCHAR(64) | 最后使用IP | NULL |
| created_at | TIMESTAMP | 创建时间 | NOT NULL |
| updated_at | TIMESTAMP | 更新时间 | NOT NULL |
| deleted_at | TIMESTAMP | 删除时间 | NULL |

**索引**:
```sql
UNIQUE INDEX uk_token_key (token_key)
INDEX idx_token_user (user_id)
INDEX idx_token_team (team_id)
INDEX idx_token_status (status)
INDEX idx_token_expire (expire_at)
```

#### 2.3.2 TokenQuota（令牌额度）

**定义**: 令牌的使用额度配置和实时使用量。每个令牌有且仅有一个额度配置。

| 属性 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | BIGINT | 主键 | PK, AUTO_INCREMENT |
| token_id | BIGINT | 关联令牌 | FK → ApiToken.id, UNIQUE, NOT NULL |
| quota_type | ENUM | 额度类型 | UNLIMITED / LIMITED |
| max_quota | DECIMAL(20,6) | 最大额度 | quota_type 为 LIMITED 时必填，0表示无限制 |
| used_quota | DECIMAL(20,6) | 已使用额度 | NOT NULL, DEFAULT 0 |
| model_whitelist | JSON | 模型白名单 | [] 表示全部允许 |
| ip_whitelist | JSON | IP白名单 | CIDR 格式，支持 |
| created_at | TIMESTAMP | 创建时间 | NOT NULL |
| updated_at | TIMESTAMP | 更新时间 | NOT NULL |

**索引**:
```sql
UNIQUE INDEX uk_token_quota_token (token_id)
```

#### 2.3.3 TokenAccessLog（令牌访问日志）

### 2.4 Token额度域

#### 2.4.1 TokenLimit（Token限额）

**定义**: Token使用限额控制实体，支持团队/用户/令牌/用户×渠道四个层级。Token限额是用量控制的核心机制，不涉及实际费用计算。

| user_id | BIGINT | 用户ID | scope_type 为 USER_CHANNEL 时必填 |

**索引**:
```sql

INDEX idx_token_limit_user_channel (user_id, channel_id)
INDEX idx_token_limit_status (status)
```

**层级约束**: 下级限额Token之和不得超过上级限额总量。

```
Team Token Limit (10,000,000 tokens/月)
  │
  ├── User 1 Token Limit (4,000,000 tokens/月)
  │     ├── Token Limit: API Token A (2,000,000 tokens/月)
  │     └── User × Channel: User1 × ChannelX (1,000,000 tokens/月)
  │
  └── User 2 Token Limit (6,000,000 tokens/月)
        ├── Token Limit: API Token B (3,000,000 tokens/月)
        └── User × Channel: User2 × ChannelX (2,000,000 tokens/月)

周期类型示例:
├── DAILY:   每天重置 (如: 每天最多 100,000 tokens)
├── WEEKLY:  每周重置 (如: 每周一重置，每周 500,000 tokens)
├── MONTHLY: 每月重置 (如: 每月1日重置，每月 2,000,000 tokens)
└── TOTAL:   不重置 (累计总量限制)
```

**scope_type 说明**:
| 层级 | scope_id | user_id | channel_id | 说明 |
|------|----------|---------|------------|------|
| TEAM | 团队ID | - | - | 团队总限额 |
| USER | 用户ID | - | - | 用户配额 |
| TOKEN | 令牌ID | - | - | 令牌限额 |
| USER_CHANNEL | - | 用户ID | 渠道ID | 用户×渠道配额 |

## 四、团队数据隔离设计

### 4.1 隔离策略

LLM-Gateway 采用**行级逻辑隔离**策略，共享数据库和 schema，通过 `team_id` 字段实现数据分离。

```
┌─────────────────────────────────────────────────────────────┐
│                        MySQL                                │
│                                                             │
│   ┌─────────────────────────────────────────────────────┐ │
│   │                     Team 表                              │ │
│   │  id │ team_code │ team_name │ admin_id │ status   │ │
│   │  1  │    acme    │   Acme    │    1    │ ACTIVE   │ │
│   │  2  │   globex   │  Globex   │    5    │ ACTIVE   │ │
│   └─────────────────────────────────────────────────────┘ │
│                                                             │
│   ┌─────────────────────────────────────────────────────┐ │
│   │                    Channel 表                          │ │
│   │  id │ channel_code │ team_id │ base_url │ ...     │ │
│   │  1  │  acme-gpt-4 │    1    │ api.acme │ ...    │ │
│   │  2  │ globex-gpt4 │    2    │ api.glob │ ...    │ │
│   │  3  │  acme-claude│    1    │ api.acme │ ...    │ │
│   └─────────────────────────────────────────────────────┘ │
│                                                             │
│   team_id=1 的数据 ──────▶ Acme 团队可见                   │
│   team_id=2 的数据 ──────▶ Globex 团队可见                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 隔离层级

| 隔离层级 | 实现方式 | 说明 |
|---------|---------|------|
| **团队级** | `team_id` 字段 | 所有业务表均包含（除 Team 本身） |
| **角色级** | `Member.team_role` | 通过成员角色实现 |
| **令牌级** | `ApiToken.token_key` | API 调用凭证唯一 |

### 4.3 查询过滤规则

```sql
-- 规则 1: 所有业务查询必须包含 team_id 过滤
SELECT * FROM channel WHERE team_id = :currentTeamId;

-- 规则 2: 跨团队查询通过 Member 关联实现（同一用户可属于多个团队）
SELECT c.* FROM channel c
JOIN member m ON c.team_id = m.team_id
WHERE m.user_id = :currentUserId;

-- 规则 3: 索引策略 - 所有 team_id 相关查询使用复合索引
CREATE INDEX idx_channel_team_priority ON channel(team_id, priority);
CREATE INDEX idx_channel_team_status ON channel(team_id, status);
CREATE INDEX idx_member_team_user ON member(team_id, user_id);
CREATE INDEX idx_member_account_team ON member(account_id, team_id);
```

## 五、APIPark 与 LLM-Gateway 实体对照

### 5.1 功能对照

| APIPark 实体 | LLM-Gateway 实体 | 差异说明 |
|-------------|-----------------|----------|
| Account | User | 功能一致 |
| Role (SYSTEM/TEAM) | Role + Permission | LLM-Gateway 支持细粒度 RBAC，APIPark 分系统级/团队级 |
| Team | Team | 功能一致（均采用 team_id 行级隔离） |
| Member | Member | 功能一致（用户与团队的多对多关联） |
| Service (AI/REST) | — | LLM-Gateway v1.0 聚焦 AI 网关，APIPark 有完整生命周期管理 |
| ApiToken | ApiToken | LLM-Gateway 直接作为 API 调用凭证 |
| Channel | Channel | 功能一致 |
| ChannelGroup | ChannelGroup | LLM-Gateway/APIPark 均有分组概念 |
| APIKey 资源池 | ChannelKey + ApiKeySecret | LLM-Gateway 分离密钥存储更安全 |
| Provider | Provider | 功能一致 |
| Model | Model | LLM-Gateway 仅跟踪Token使用量，不管理定价 |
| Budget | TokenLimit + TokenUsage | LLM-Gateway 采用三级Token限额模型（Team/User/Token） |
| 自定义 Channel | Strategy + StrategyNode | LLM-Gateway 支持可视化编排 |
| RequestLog | RequestLog + RequestBodyLog | LLM-Gateway 单库 + 分表 |
| AuditLog | AuditLog | LLM-Gateway 增加链式哈希 |
| DataMaskingStrategy | PiiRule + SensitiveWord | APIPark 有统一策略，LLM-Gateway 分离实现 |
| IpBlacklist/IpWhitelist | IpBlacklist + IpWhitelist | 功能一致 |
| RateLimitRule | RateLimitRule | 功能一致 |
| Channel | Channel + ChannelKey | LLM-Gateway 更完善的自动恢复 |
| MCP Service | — | APIPark V1.7+ 支持，LLM-Gateway 未实现 |

### 5.2 APIPark 独有实体（LLM-Gateway 未实现）

| APIPark 实体 | 说明 | 未实现原因 |
|------------|------|-----------|
| Service | API 服务（AI/REST） | v1.0 聚焦核心网关功能 |
| API | 服务下的具体端点 | 生命周期管理非核心需求 |
| DataMaskingStrategy | 统一脱敏策略 | LLM-Gateway 通过 PiiRule + SensitiveWord 分离实现 |
| MCP Service | Model Context Protocol | Phase 2 规划 |

### 6.1 实体属性规范

#### 审计字段（所有业务表必须包含）

```sql
created_by    BIGINT       -- 创建人ID (FK → users.id, 系统生成填 0L)
created_at    TIMESTAMP    -- 创建时间 (NOT NULL, DEFAULT CURRENT_TIMESTAMP)
updated_by    BIGINT       -- 更新人ID
updated_at    TIMESTAMP    -- 更新时间 (NOT NULL, ON UPDATE CURRENT_TIMESTAMP)
deleted_by    BIGINT NULL  -- 删除人ID (软删除)
deleted_at    TIMESTAMP    -- 删除时间 (软删除标记)
version       INT          -- 乐观锁版本号 (NOT NULL, DEFAULT 0)
```

#### 时间戳规范

| 字段类型 | Java 类型 | 数据库类型 | 说明 |
|---------|----------|-----------|------|
| 创建时间 | Instant | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP |
| 更新时间 | Instant | TIMESTAMP | NOT NULL, ON UPDATE CURRENT_TIMESTAMP |
| 删除时间 | Instant | TIMESTAMP NULL | 软删除标记 |
| 过期时间 | Instant | TIMESTAMP NULL | 永不过期填 NULL |

| ChannelKey | ACTIVE, DISABLED, ERROR, EXHAUSTED |
