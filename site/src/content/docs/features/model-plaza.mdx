# 模型体验功能设计文档

## 1. 功能概述

### 1.1 背景

用户在配置供应商和 API Key 时，缺乏直观的方式来验证配置正确性和体验模型效果。当前连通性测试仅能验证 API Key 有效性，无法让用户感知模型的实际输出质量。

### 1.2 目标

提供一个模型体验功能，让用户能够：
1. **验证配置** - 通过实际对话验证 API Key 和模型配置正确
2. **体验模型** - 直观感受不同模型的输出风格和质量
3. **评估成本** - 了解 Token 消耗情况，预估生产成本
4. **辅助选型** - 对比不同供应商的模型，做出更好的选择

### 1.3 目标用户

| 用户类型 | 使用场景 |
|----------|----------|
| 运维人员 | 配置新供应商时验证配置正确性 |
| 开发人员 | 调试 API 集成问题 |
| 产品人员 | 评估不同模型的能力边界 |
| 决策者 | 对比成本和效果，选择合适的模型 |

### 2.3 两种使用模式

#### 模式一：使用已保存配置

- 从供应商列表选择已配置的供应商
- API Key 从数据库读取，用户无需输入
- 适合已配置供应商后的日常体验

#### 模式二：临时配置（不保存）

- 手动输入 API Key 和可选的 Base URL
- 仅在当前会话有效，刷新后清除
- 适合新增供应商前的预验证

### 3.2 核心类设计

#### 3.2.1 ModelExperienceService

```java
@Service
public class ModelExperienceService {

    private final AdapterBuilderFactory adapterBuilderFactory;

    /**
     * 流式聊天体验
     *
     * @param request 体验请求
     * @param callback 流式回调
     */
    public void chatStream(ExperienceChatRequest request, StreamCallback callback) {
        // 创建临时 Adapter
        LLMAdapter adapter = adapterBuilderFactory.createAdapter(
            request.getProviderType(),
            request.getBaseUrl(),
            request.getApiKey()
        );

        // 构建 LLM 请求
        LLMRequest llmRequest = LLMRequest.builder()
            .model(request.getModel())
            .messages(request.getMessages())
            .maxTokens(request.getMaxTokens())
            .temperature(request.getTemperature())
            .stream(true)
            .build();

        // 调用 Adapter 流式聊天
        adapter.chatStream(llmRequest, callback);
    }
}
```

#### 3.2.2 ExperienceChatRequest

```java
public record ExperienceChatRequest(
    /** 供应商类型 */
    @NotNull ProviderType providerType,

    /** Base URL（可选，使用默认值） */
    String baseUrl,

    /** API Key（必填） */
    @NotBlank String apiKey,

    /** 模型名称 */
    @NotBlank String model,

    /** 对话消息列表 */
    @NotNull List<ChatMessage> messages,

    /** 最大输出 Token（默认 1024） */
    Integer maxTokens,

    /** 温度参数（默认 0.7） */
    Double temperature
) {
    public record ChatMessage(
        String role,      // user, assistant, system
        String content
    ) {}
}
```

### 4.3 SSE 流式处理

```typescript
function useExperienceChat() {
  const [messages, setMessages] = useState<ChatMessage[]>([]);
  const [isStreaming, setIsStreaming] = useState(false);

  const sendMessage = async (content: string) => {
    // 添加用户消息
    const userMessage = { role: 'user', content };
    setMessages(prev => [...prev, userMessage]);
    setIsStreaming(true);

    // 添加助手消息占位
    const assistantIndex = messages.length + 1;
    setMessages(prev => [...prev, { role: 'assistant', content: '' }]);

    // 建立 SSE 连接
    const eventSource = new EventSource('/api/v1/experience/chat', {
      method: 'POST',
      body: JSON.stringify({ ... })
    });

    eventSource.addEventListener('content', (e) => {
      const data = JSON.parse(e.data);
      // 增量更新助手消息
      setMessages(prev => {
        const updated = [...prev];
        updated[assistantIndex].content += data.content;
        return updated;
      });
    });

    eventSource.addEventListener('usage', (e) => {
      const data = JSON.parse(e.data);
      // 更新 Token 统计
      setUsage(data);
    });

    eventSource.addEventListener('done', () => {
      setIsStreaming(false);
      eventSource.close();
    });
  };

  return { messages, sendMessage, isStreaming };
}
```

## 5. 安全与限制

### 5.1 安全措施

| 安全风险 | 措施 |
|----------|------|
| API Key 泄露 | 前端不持久化；传输使用 HTTPS；日志脱敏 |
| 恶意调用 | 登录认证；速率限制 |
| 费用滥用 | 单次请求 max_tokens 上限；每日调用次数限制 |
| 敏感内容 | 可选内容审核过滤 |

### 5.2 使用限制

| 限制项 | 默认值 | 说明 |
|--------|--------|------|
| 单次最大 Token | 2048 | 防止费用失控 |
| 单次最大消息数 | 20 | 限制上下文长度 |
| 每日体验次数 | 100 次/用户 | 防止滥用 |
| 请求超时 | 60 秒 | 避免长时间占用连接 |

          input: 0.0005

### 6.2 费用计算

```typescript
function calculateCost(usage: Usage, pricing: ModelPricing): number {
  const inputCost = (usage.promptTokens / 1000) * pricing.input;
  const outputCost = (usage.completionTokens / 1000) * pricing.output;
  return inputCost + outputCost;
}
```
