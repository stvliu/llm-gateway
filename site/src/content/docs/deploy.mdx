# 安装部署

LLM-Gateway 基于 Java 21 + Spring Boot 3.5，支持多种部署方式。开发期可用内嵌 H2 零依赖启动，生产环境推荐 PostgreSQL + Redis。

## 环境要求

| 组件 | 版本 | 说明 |
|------|------|------|
| JDK | 21+ | 推荐 Eclipse Temurin |
| Maven | 3.9+ | 仓库自带 `mvnw`，可直接用 `./mvnw` |
| PostgreSQL | 14+（生产） | 开发可用内嵌 H2 替代 |
| Redis | 7.x（生产） | 本地缓存模式可不依赖 |

## 一、源码运行（开发试用，最快）

仓库根目录执行：

```bash
./mvnw spring-boot:run -pl gateway-boot
```

默认 `local` profile：内嵌 H2 文件库 + 自动建表 + 示例数据，**无需 PostgreSQL / Redis**。服务监听 `http://localhost:8080`。

## 二、源码构建 + jar 运行

```bash
# 构建（跳过测试加速）
./mvnw clean install -DskipTests -pl gateway-boot

# 产物：gateway-boot/target/gateway-boot-1.0.0-SNAPSHOT.jar

# 运行（H2 开发模式）
java -jar gateway-boot/target/gateway-boot-1.0.0-SNAPSHOT.jar \
  --spring.profiles.active=local

# 运行（PostgreSQL 生产模式）
java -jar gateway-boot/target/gateway-boot-1.0.0-SNAPSHOT.jar \
  --spring.profiles.active=postgresql
```

## 三、PostgreSQL 生产部署

1. **准备数据库**：创建库 `llm_gateway`（PostgreSQL 不会自动建库）并安装扩展：

```sql
CREATE DATABASE llm_gateway;
\c llm_gateway
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
```

2. **设置环境变量并启动**：

```bash
export DB_URL="jdbc:postgresql://localhost:5432/llm_gateway"
export DB_USERNAME="llm_gateway"
export DB_PASSWORD="your_secure_password"
export GATEWAY_ENCRYPTION_KEY="$(openssl rand -base64 32)"  # 必填
export SPRING_PROFILES_ACTIVE=postgresql

java -jar gateway-boot/target/gateway-boot-1.0.0-SNAPSHOT.jar
```

启动后 Flyway 自动执行表结构迁移（无需手动建表）。

## 加密密钥（必读）

API Key 使用 AES-256-GCM 加密存储，密钥通过环境变量 `GATEWAY_ENCRYPTION_KEY` 注入：

```bash
# 生成 32 字节 Base64 密钥
openssl rand -base64 32
```

- **生产环境必须配置**，否则启动抛 `ENCRYPTION_KEY_MISSING`
- `local` / `dev` profile 允许使用临时密钥，但**重启后已加密数据无法解密**
- 密钥丢失 = 所有已存储的上游 Key 失效，请妥善备份

## Profile 对照

| Profile | 数据库 | Redis | 缓存 | 用途 |
|---------|--------|-------|------|------|
| `local`（默认） | H2 文件 | 关闭 | - | 本地开发，预置示例数据 |
| `dev` | H2 文件 | 关闭 | - | 开发调试 |
| `postgresql` | PostgreSQL | 启用 | - | 生产推荐 |
| `standalone` | 同上 | - | Caffeine | 标准版单机，本地限流 |
| `prod` | 同上 | 启用 | simple | 生产精简日志 |

## 关键环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `SPRING_PROFILES_ACTIVE` | `local` | 激活的 profile |
| `SERVER_PORT` | `8080` | 服务端口 |
| `DB_URL` | H2 文件 | 数据库 JDBC URL |
| `DB_USERNAME` / `DB_PASSWORD` | `sa` / 空 | 数据库账号 |
| `REDIS_HOST` / `REDIS_PORT` | `localhost` / `6379` | Redis 地址 |
| `GATEWAY_ENCRYPTION_KEY` | 空 | API Key 加密密钥（生产必填） |
| `OTEL_ENABLED` | `false` | OpenTelemetry 开关 |

完整清单见 `deployments/docker/.env.example`。

## 健康检查

```bash
curl http://localhost:8080/actuator/health
```

可用端点：`/actuator/health`、`/actuator/health/liveness`、`/actuator/health/readiness`、`/actuator/prometheus`、`/actuator/info`。

## Docker 部署

仓库提供 `deployments/docker/Dockerfile` 与 `docker-compose.yml`（含 PostgreSQL、Redis、Prometheus、Grafana、Jaeger、OTel Collector）：

```bash
cd deployments/docker
docker compose up -d
```

> ⚠️ **注意**：当前 Dockerfile / compose 中的构建路径针对多模块结构（`gateway/gateway-app/...`），与仓库单模块 `gateway-boot` 存在差异，使用前需将相关路径调整为 `gateway-boot`。健康检查端点也应由 `/api/v1/health` 改为 `/actuator/health`。

Kubernetes 部署可参考 `deployments/helm/llm-gateway/` Helm Chart。
