# 安全与风控

LLM-Gateway 遵循零信任安全架构，请求经过 IP 封禁、认证、限流多层检查，API Key 与上游凭证均加密存储。

## 安全拦截器链

请求按以下顺序检查（任一层拒绝即返回）：

| 顺序 | 拦截器 | 职责 | 失败响应 |
|------|--------|------|---------|
| 1 | IP 黑名单 | 封禁 IP 拦截 | 403 `Access denied: IP blocked` |
| 2 | API Key 认证 | `/v1/*` 路径校验调用方 Key | 401 `无效的 API Key` |
| 3 | 会话认证 | `/api/v1/*` 路径校验 Sa-Token | 401 未登录 |
| 4 | 限流 | API Key 级令牌桶 | 429 `RATE_LIMIT_EXCEEDED` |

## IP 黑名单

已实现。被封锁的 IP 访问受保护路径时返回 403。客户端 IP 提取顺序：`X-Forwarded-For` -> `X-Real-IP` -> `RemoteAddr`。

> ⚠️ IP 黑名单的领域服务（封禁/解封）已实现，但**管理 API 端点暂未暴露**，当前需通过管理后台操作。

## 密钥加密

所有上游 Provider Key 使用 **AES-256-GCM** 加密存储，密钥通过环境变量 `GATEWAY_ENCRYPTION_KEY` 注入：

```bash
# 生成 32 字节 Base64 密钥
openssl rand -base64 32
export GATEWAY_ENCRYPTION_KEY="<生成的密钥>"
```

- 生产环境（非 dev/local profile）必须配置，否则启动抛 `ENCRYPTION_KEY_MISSING`
- 调用方 API Key 不存明文：仅存前缀（`keyPrefix`）+ SHA-256 哈希，认证时按前缀查库再哈希比对

## 密钥脱敏

列表与详情接口不返回明文，仅返回脱敏后的 `key_hint` / `keyPrefix`（如 `sk-****abcd`）。

## PII 脱敏

启动时预置 8 条敏感数据规则（手机号、身份证、银行卡、邮箱、地址、密码、信用卡、SSN），支持正则匹配与掩码格式。

> ⚠️ 规则已定义入库，但**脱敏执行尚未接入请求链路**，当前版本暂不生效。

## 规划中（当前未实现）

以下能力为规划功能，当前版本尚未落地：

- IP 白名单（仅 DB 字段预留）
- UA 过滤
- 内容审核（`/v1/moderations`）
- 国密算法（SM2/SM3/SM4，当前使用 AES-256）
- 完整审计链（WORM）
