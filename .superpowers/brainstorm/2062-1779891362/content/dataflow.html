当前数据流 vs 目标数据流

当前实现
ChatDispatchService
│
├─ RoutingResolver.resolve(modelName)
│ ├─ ModelMatcher → Model
│ ├─ ChannelSelector → ChannelModel
│ ├─ CredentialResolver → apiKey
│ └─ EndpointResolver → endpoint
│
├─ RoutingContext ← {channelId, endpointUrl, apiKey...}
│ ✗ 不含 modelName / upstreamModelName
│
├─ OutboundTuner.tune(request, ctx)
│ ├─ 协议调谐 ✅
│ └─ 模型名替换 ✗ TODO
│
├─ 上游调用
└─ 后置处理
目标实现
ChatDispatchService
│
├─ RoutingResolver.resolve(modelName)
│ ├─ ModelMatcher → Model
│ ├─ ChannelSelector → ChannelModel
│ ├─ CredentialResolver → apiKey
│ └─ EndpointResolver → endpoint
│
├─ RoutingContext ← {channelId, endpointUrl, apiKey...,
│ ✓ modelName, upstreamModelName}
│
├─ OutboundTuner.tune(request, ctx)
│ ├─ 协议调谐 ✅
│ └─ 模型名替换: ctx.upstreamModelName → request.model
│
├─ 上游调用（已使用替换后的模型名）
└─ 后置处理

需实现的工作包

1

RoutingContext 增加模型名字段

在 RoutingContext record 中添加 modelName / upstreamModelName，由 RoutingResolver 组装时填入。

2

OutboundTuner 模型名替换逻辑

读取 RoutingContext.upstreamModelName，写入 request.model。null 时走默认（= modelName）。

3

Catalog 物化时预填 upstreamModelName

UPSTREAM_MODEL_NAME_RULES 内置映射表 + materializePlan 中设置值。

4

/v1/models 用户面接口

按 API Key 可见的 Model 列表（兼容 OpenAI 格式），去重后返回。

Written and pushed to your browser at **http://localhost:64309**.
