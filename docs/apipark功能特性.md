# APIPark 功能特性文档

> 本文档基于 APIPark 官方文档（docs.apipark.com）及 GitHub 仓库（github.com/APIParkLab/APIPark）梳理，详细介绍 APIPark 作为开源 AI 网关与 API 开放平台的核心功能特性。

---

## 一、项目概述

### 1.1 定位

APIPark 是一款**开源免费的一站式 AI 网关与 API 开放平台**，基于 Apache 2.0 协议，支持商业免费使用。由 Eolink（API 全生命周期治理解决方案公司，为全球超过 10 万家企业提供 API 研发管理、自动化测试、拨测监控、运维网关等产品）推出。

- **GitHub**: github.com/APIParkLab/APIPark
- **开源协议**: Apache License 2.0
- **技术栈**: TypeScript (56.4%), Go (39.3%)
- **定位**: 云原生、超高性能 AI&API 网关，LLM API 管理、分发系统、开放平台

### 1.2 核心价值

APIPark 致力于帮助企业更加轻松地**管理、整合并部署 AI 服务以及 API 的开放共享**，让企业高效安全畅享 AI 时代。

### 1.3 核心能力矩阵

| 能力维度 | 说明 |
|---------|------|
| **AI 模型集成** | 快速接入 100+ 主流 AI 大模型 |
| **统一 API 格式** | 统一使用 OpenAI API 规范，一次对接多模型无需修改代码 |
| **Prompt 封装** | 将 Prompt 与 AI 模型封装为 REST API，实现复用与共享 |
| **API 生命周期管理** | 从设计、发布、调用到下线的全流程管理 |
| **多租户与订阅审批** | 支持多团队/多租户管理，灵活订阅审批流程 |
| **日志与可观测性** | 详细日志记录、强大数据分析能力 |
| **高性能** | 性能超越 Nginx，支持集群部署 |

## 二、AI 网关核心功能（AI Service）

AI Service（AI 网关）是 APIPark 的核心功能模块，提供对多个 AI 模型的统一访问管理。

### 2.1 LLM 模型供应商集成

#### 2.1.1 内置供应商（100+ 模型）

APIPark 预集成了六大主流服务平台，支持 100+ AI 模型：

| 供应商 | 说明 |
|--------|------|
| **OpenAI** | GPT-4o、GPT-4-turbo、GPT-3.5-turbo 等 |
| **Anthropic** | Claude 3.5、Claude 3 等 |
| **AWS Bedrock** | Amazon Titan、Claude on Bedrock 等 |
| **Google Gemini** | Gemini Pro、Gemini Ultra 等 |
| **火山引擎（字节跳动）** | 豆包等国内模型 |
| **阿里云百炼** | 通义千问等 |
| **DeepSeek** | DeepSeek-R1、DeepSeek-V3 等 |
| **Hugging Face** | 开源模型社区 |
| **Ollama** | 本地大模型框架 |
| **LM Studio** | 桌面端模型工具 |
| **Xinference** | 分布式推理平台 |

#### 2.1.2 自定义供应商接入

- 支持将任何符合 **OpenAI 接口标准**的第三方 LLM 服务快速添加为新的 LLM 供应商
- 通过标准化配置流程，**5 分钟**即可完成新渠道注册
- 自动验证目标服务是否遵循标准 API 规范

#### 2.1.3 模型别名映射（Model Alias）

- 在任意已接入 AI 接口中，通过 `model=供应商ID/模型名称` 格式参数直接调用目标模型
- 示例：`"model":"volcengine/llama3-8b"` 调用火山引擎的 Llama3 模型
- 支持将简化的别名映射为原模型标识值，例如：将 `doubao` 映射为 `volcengine_maas/doubao-1-5-lite-32k-250115`
- 兼容历史配置，原有模型标识仍可正常使用

### 2.2 AI 服务创建与管理

#### 2.2.1 创建 AI 服务

步骤：
1. 进入**工作空间**模块
2. 选择**服务** → **创建服务**
3. 选择**服务类型**：AI Service（AI 网关）
4. 配置订阅审核方式：
   - **无需审核**：所有消费者可以直接订阅并调用服务
   - **手动审核**：消费者需等待管理员审批后才能调用

#### 2.2.2 创建 API

在服务内可创建多个 API：
- **统一 API**：系统自动创建的默认 API，可直接调用 AI 服务
- **自定义 API**：将 Prompt 与 AI 模型封装为自定义 API

配置项：
- **服务类别**：选择在 API 门户中发布的类别
- **API 名称**
- **API 请求路径**
- **Prompt**：定义 AI 需要执行的操作，如将 AI 封装为翻译 API、数据分析 API
- **变量**：使用 `{{param}}` 格式定义请求参数
- **超时时长**：避免大量超时请求影响 APIPark 性能
- **最大重试次数**：当 API 请求超时或 AI 模型返回错误时自动重试

#### 2.2.3 服务发布

- 每次对 API、API 文档、使用说明、上游进行变更后，需要**发布新版本**才能使新配置生效
- 发布时需填写版本号和版本描述

### 2.3 负载均衡与故障转移

#### 2.3.1 AI 模型负载均衡

AI 模型负载均衡是一种**智能调度机制**，确保 AI 服务的高可用性和稳定性。

- **主服务商故障时**：自动将请求切换到备用 AI 服务商
- **负载优先级配置**：支持按优先级排序，故障时按预设优先级顺序切换
- **模型级负载均衡**：支持模型级别的故障转移策略定义

#### 2.3.2 负载均衡可视化

在 AI 模型页面（已配置标签页），展示所有当前已配置 AI 模型提供商的负载均衡图：
- **Provider Card**：展示提供商的可用性状态和默认选中模型
- **API Key Card**：展示该提供商下的各个 API Key（绿色=正常，红色=异常）
- **API 关联数**：AI 服务与提供商卡片之间的连线数据，表示调用该提供商 AI 模型的 API 数量
- **API Key 数量**：提供商卡片与 API Key 卡片之间的连线数据

### 2.4 API Key 资源池

API Key 资源池是**集中管理和分配 API Key** 的功能，为 AI 服务的稳定运行提供强有力支持。

#### 2.4.1 核心能力

- 集中管理各厂商的 API Key
- 查看和管理 API Key 状态（正常/超出额度/过期等）
- 通过**拖拽**操作轻松调整 API Key 的优先级顺序
- 当 API Key 遇到超出额度或过期问题时，系统自动按优先级激活其他 API Key

#### 2.4.2 API Key 管理

- **默认 API Key**：在 AI 厂商设置弹窗中配置的 API Key，不可删除
- **添加更多 API Key**：在 API Key 资源池页面可添加更多 Key
  - 名称：便于管理，建议设置清晰易懂的名称
  - API Key：实际 API Key 参数配置
  - 过期时间：默认永不过期，可设置具体过期时间
- **启用/禁用**：禁用后该 Key 无法被调用，系统自动调用下一个
- **优先级调整**：拖拽调整，优先级高的 Key 会被优先调用

### 2.5 一键部署开源 LLM

APIPark 支持**一键部署**主流开源大模型（如 DeepSeek、LLaMA、ChatGLM、Qwen 等），通过可视化界面完成模型优化、服务部署和网关配置初始化。

#### 部署流程

1. 点击首页的"**本地部署 AI 并生成 API**"卡片
2. 输入供应商名称，选择对应模型，点击确认开始部署
3. 部署经历三个阶段：
   - "下载模型文件"
   - "部署模型"
   - "初始化配置"
4. 部署成功后，自动在服务列表中添加以模型名称命名的服务

## 三、统一 API 格式

### 3.1 统一 API 签名

- APIPark 统一使用 **OpenAI 的 API 接口规范**
- 可同时连接多个 AI 大模型，**无需对现有代码进行任何修改**
- 自动完成渠道路由、认证参数传递、响应格式标准化

### 3.2 格式转换

- 将不同 AI 模型的请求/响应格式统一
- 切换 AI 模型或修改 Prompt 不影响应用或微服务
- 降低 AI 使用和维护成本

## 五、消费者与订阅管理（Consumer）

### 5.1 消费者（Consumer）

在 APIPark 中，**消费者（Consumer）** 是订阅服务并调用 API 的实体。消费者通过订阅服务来获得调用服务内 API 的权限，确保数据安全性和访问合规性。

#### 创建消费者

- **消费者名称**
- **消费者 ID**：唯一标识符，保存后不可更改
- **描述**

#### 凭证（Credentials）管理

APIPark 使用凭证来限制消费者对 API 资源的访问：

| 认证类型 | 说明 |
|---------|------|
| **API Key** | API 密钥认证 |
| **Basic Auth** | 基本认证 |
| **JWT** | JSON Web Token 认证 |
| **AK/SK** | Access Key/Secret Key 认证 |

- **过期时间**：默认永不过期，可设置临时凭证
- **隐藏认证信息**：勾选后 APIPark 转发请求时将隐藏认证信息

### 5.2 订阅审批

#### 无需审核

- 消费者订阅申请自动批准
- 订阅成功后可立即调用服务 API

#### 手动审核

- 消费者订阅后需等待管理员审批
- 未审批通过前调用 API 将被拒绝
- 管理员可在服务详情页查看待审批列表

### 5.3 订阅管理

管理员可以：
- 查看服务的所有订阅者列表
- 审批或拒绝订阅申请
- 手动添加/移除订阅者
- 撤销订阅权限

## 六、API 开放门户（Developer Portal）

### 6.1 功能概述

APIPark 的 API 门户是**团队内共享 API 服务的统一平台**，帮助开发者轻松浏览和发现所需 API，减少搜索和选择时间。

### 6.2 核心特性

- **服务浏览**：查看所有公开可用的 API 服务
- **服务订阅**：申请订阅所需服务
- **API 调用**：订阅审批通过后使用消费者凭证调用 API
- **使用统计**：自动生成 API 使用统计，展示长期调用趋势和性能变化
- **API 导入 AI Agent**：支持将 API 服务无缝集成到各种 AI Agent 平台

### 6.3 API 订阅流程

1. 在 API 门户中选择要订阅的服务
2. 进入服务详情页，点击 **Subscribe** 按钮
3. 在弹窗中选择用于此次订阅的消费者
4. 如服务需要手动审核，需填写订阅用途以协助管理员审批
5. 等待订阅审批通过后，使用消费者凭证调用 API

## 八、安全与合规

### 8.1 数据脱敏（Data Masking）

APIPark 提供基于 Prompt 管理的数据脱敏安全机制，有效防御大模型攻击、滥用行为，杜绝内部敏感数据泄露风险。

#### 全局脱敏策略

- 在**系统设置** → **全局策略** → **数据脱敏**中配置
- 按优先级（数字越小优先级越高）执行

#### 服务级脱敏策略

- 在**工作空间** → **服务** → **服务策略**中配置
- 服务级策略优先于全局策略

#### 支持的数据格式

| 格式类型 | 说明 |
|---------|------|
| 姓名 | 姓名脱敏 |
| 电话号码 | 手机号脱敏 |
| 身份证号 | 身份证号脱敏 |
| 银行卡号 | 银行卡号脱敏 |
| 日期 | 日期脱敏 |
| 金额 | 金额脱敏 |

#### 匹配条件

- API 请求方法：GET/POST/PUT/DELETE/PATCH/HEADER/OPTIONS
- API 路径：使用正则表达式指定
- IP：IP 地址或 CIDR 范围
- 消费者：从消费者列表中选择

#### 处理日志

- 策略处理日志可查看当前策略如何处理目标对象
- 展示原始参数值与脱敏后参数值的对比

### 8.2 认证与授权

#### 身份认证

- API Key
- Basic Auth
- AK/SK
- JWT
- OAuth 2.0

#### 凭证管理

- 支持凭证过期时间设置
- 支持隐藏转发时的认证信息

### 8.3 订阅审批机制

- 确保只有授权用户才能访问特定 API 服务
- 保障系统安全和服务质量
- 支持手动审批和自动审批两种模式

## 九、可观测性与日志分析

### 9.1 服务概览仪表盘（V1.8+）

可视化图表展示服务使用统计：
- **调用量 Top API**：按调用量排序的 API 列表
- **消费者平均请求数**：每个消费者的平均请求量
- **Token 消耗**：总 Token 消耗和平均 Token 消耗
- **网络流量**：数据传输量统计
- **请求数量**：总请求次数

### 9.2 API/MCP 请求日志（V1.8+）

- 流式数据格式化，便于阅读
- 查看请求和响应参数
- 在**服务管理** → **日志**中访问 API 或 MCP 的历史请求日志

### 9.3 全局调用概览

#### REST 服务调用概览

- 总请求量
- 数据传输量
- 平均响应时间
- 支持自定义时间段筛选

#### AI 服务调用概览

- 请求数量
- Token 使用量
- 平均 Token 耗时
- 支持自定义时间段筛选

#### 多维调用统计

- 按**服务维度**统计
- 按**消费者维度**统计
- 按 **API 维度**统计

### 9.4 服务级概览

- 提供每个服务的调用统计
- 详细的使用和性能数据
- 支持深入分析和优化决策

### 9.5 数据源配置

APIPark 将 API 调用统计数据存储在外部数据库（InfluxDB）中以生成各种分析报告。

- 使用 APIPark 脚本部署时，InfluxDB 会默认安装
- 也可部署外部 InfluxDB 数据库并在系统设置中配置

### 9.6 日志输出

- 支持输出到文件
- 支持输出到 Loki（V1.8+ 默认）
- 支持输出到第三方日志平台

## 十一、MCP 支持（Model Context Protocol）

### 11.1 服务级 MCP（V1.7+）

- MCP 配置信息在服务详情页可用
- 方便在 AI Agent 中使用
- API 门户中标记启用 MCP 的服务
- 一键为 APIPark 上的任何 HTTP 或 AI API 启用 MCP 访问

### 11.2 平台级 MCP（V1.7+）

- 非常适合构建智能多模态 Agent
- 提供系统级 MCP 端点，通过统一接口访问所有公共 API

### 11.3 消费者级 MCP（V1.9+）

- 调用 MCP 能力时，只能访问特定消费者订阅的服务
- 提供更灵活的 MCP 调用范围配置

## 十二、API 生命周期管理

### 12.1 全流程覆盖

APIPark 支持 API 从**设计、发布、调用到下线**的全生命周期管理：

1. **设计**：API 设计与规划
2. **发布**：版本管理与发布流程
3. **调用**：API 调用与监控
4. **下线**：API 退役与迁移

### 12.2 API 版本管理

- 支持多版本并存
- 版本切换平滑
- 便于灰度发布和回滚

### 12.3 API 文档管理

- 自动生成 API 文档
- 支持 OpenAPI V2.0 和 V3.0 格式
- 支持上传 OpenAPI YAML 文件创建 API 文档
- 方便外部系统获取 API 文档数据
