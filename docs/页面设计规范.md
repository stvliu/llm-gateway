### 1.2 主题系统

Ant Design 6.x 采用 Design Token 系统，支持亮色/暗色主题自动切换。

#### 主题配置

```tsx
import { ConfigProvider, theme } from 'antd';

// 亮色主题
const lightTheme = {
  algorithm: theme.defaultAlgorithm,
};

// 暗色主题
const darkTheme = {
  algorithm: theme.darkAlgorithm,
};

// 应用主题
<ConfigProvider theme={isDark ? darkTheme : lightTheme}>
  <App />
</ConfigProvider>
```

### 1.3 核心设计 Token

使用 `theme.useToken()` 获取当前主题的 token 值：

```tsx
import { theme } from 'antd';

const { token } = theme.useToken();

// 使用 token
<div style={{
  color: token.colorText,
  background: token.colorBgContainer,
  borderColor: token.colorBorder,
}}>
  内容
</div>
```

## 四、实体列表点击交互规格

### 4.1 核心交互：点击列表行打开抽屉详情

#### 交互流程图

```
用户点击列表行
      │
      ▼
┌─────────────────────────────────────┐
│  检查当前是否有未保存的编辑更改     │
└─────────────────────────────────────┘
      │
      ├──── 有未保存更改 ────┐
      │                      ▼
      │           ┌─────────────────────────────┐
      │           │  弹出确认对话框             │
      │           │  "您有未保存的更改..."      │
      │           └─────────────────────────────┘
      │                      │
      │                      ├──── [继续编辑] ──── 保持当前抽屉，不切换
      │                      │
      │                      └──── [放弃更改] ──── 关闭当前抽屉，打开新抽屉
      │
      └──── 无未保存更改 ────┐
                            ▼
                 ┌─────────────────────────────┐
                 │  关闭当前抽屉（如有）       │
                 │  打开新实体详情抽屉         │
                 │  高亮选中行                 │
                 └─────────────────────────────┘
                            │
                            ▼
                 ┌─────────────────────────────┐
                 │  加载实体详情数据           │
                 │  显示详情内容               │
                 └─────────────────────────────┘
```

#### 点击区域定义

| 点击区域 | 触发行为 | 说明 |
|----------|----------|------|
| **行内任意单元格** | 打开详情抽屉 | 除操作列外的所有区域 |
| **操作列图标按钮** | 执行对应操作 | 编辑、删除等，不打开抽屉 |
| **复选框列** | 切换选中状态 | 用于批量操作，不打开抽屉 |
| **行内链接/按钮** | 执行链接/按钮操作 | 如名称列可点击链接 |

## 五、抽屉式详情与编辑页面

### 5.1 抽屉定位模式：遮盖式

#### 核心原则

抽屉采用**遮盖模式**，从屏幕右侧滑入时：
- **不挤压列表空间**
- **遮盖在列表上方**
- **保持列表布局不变**
- **通过半透明遮罩层隔离交互**

```
┌─────────────────────────────────────────────────────────────────────┐
│  App Bar                                                            │
├──────────────┬──────────────────────────────────────────────────────┤
│              │              │                                      │
│   Side Menu  │   遮罩层     │         抽屉面板                      │
│              │   (半透明)   │         (480px)                      │
│              │              │                                      │
│   (240px)    │  ┌───────────┴────────────────────────────────────┐ │
│              │  │ ← 设备详情                                  ✕  │ │
│              │  ├────────────────────────────────────────────────┤ │
│              │  │ [详情] [属性] [告警]                          │ │
│              │  ├────────────────────────────────────────────────┤ │
│              │  │                                                │ │
│              │  │  基本信息                                      │ │
│              │  │  ────────────────────────────────────────────  │ │
│              │  │  名称: Device-02                              │ │

│              │                                                      │
```

## 十三、删除确认框（Delete Confirmation Dialog）设计规范

### 13.1 组件概述

*   **组件名称**： 删除确认框
*   **组件类型**： 模态对话框 (Modal Dialog)
*   **功能描述**： 在执行删除操作时，强制中断用户当前操作流，请求用户二次确认。其核心目标是**防止因误操作导致的数据丢失**，通过明确告知用户操作对象及不可逆的后果，确保用户意图明确。
*   **设计目标**： 引起用户足够注意、清晰传达风险、提供明确且平衡的操作选择。

### 13.2 触发场景

*   **单条删除**： 在数据列表的行操作菜单中，或在详情页的"危险操作"区域，点击"删除"操作时触发。确认框需明确展示**单个目标对象**的标识（如名称、ID）。
*   **批量删除**： 在列表页面勾选一个或多个条目后，点击页面上方的"删除"批量操作按钮时触发。确认框需明确展示**待删除对象的数量**。

### 13.3 结构、布局与定位

*   **容器层级**： 作为模态层，应覆盖在整个应用界面之上，`z-index` 值应确保其位于所有常规页面元素（包括导航栏、顶部栏）之上。
*   **遮罩**： 整个视口覆盖一层半透明黑色遮罩，用于隔离背景内容并聚焦用户注意力于确认框。
*   **对话框定位**： 在视口中**水平和垂直居中**显示。
*   **内部结构（自上而下）**：
    1.  **标题区 (Header)**： 显示警告标题。
    2.  **内容主体区 (Body)**：
            *   **警告图标**： 感叹号三角形图标，颜色为 `token.colorWarning`。
            *   **确认问句**： 以加粗或较大字体显示的核心问句。
            *   **后果描述**： 明确、无歧义地说明删除操作的后果，特别是其**不可恢复性**。
    3.  **操作区 (Footer)**：
            *   包含两个按钮，水平并排。
            *   **布局**： 按钮**右对齐**于容器内。
            *   **按钮顺序**： **"否"（取消操作）在左，"是"（确认删除）在右**。

### 13.4 内容与文案规范

*   **确认问句**：
    *   **单条删除**：`确定要删除[对象类型]的"[对象名称]"吗？`
        *   示例：`确定要删除设备的"Thermostat T1"吗？`
    *   **批量删除**：`确定要删除[数量]个[对象类型]吗？`
        *   示例：`确定要删除2个设备吗？`
*   **后果描述**：
    *   **固定格式**：`请注意：确认后，[所有选定的[对象类型]]/[[对象名称]]及其所有相关数据将不可恢复。`
    *   **要求**： 必须包含"**不可恢复**"或"**永久删除**"等明确警示词。
*   **操作按钮文案**：
    *   **取消按钮**： 使用"**否**"或"**取消**"。
    *   **确认按钮**： 使用"**是**"或"**删除**"。

### 13.5 交互逻辑

*   **触发**： 用户点击任何"删除"按钮。
*   **关闭/取消**：
    1.  点击"**否**"按钮。
    2.  点击遮罩层（模态框外部区域）。
    3.  按下键盘 `Esc` 键。
*   **确认与后续**：
    1.  点击"**是**"按钮。
    2.  确认框立即关闭。
    3.  系统发起删除请求，界面应给出明确的**加载状态**。
    4.  操作完成后，刷新相关数据列表或页面，并给予全局提示。

### 13.6 组件实现

```tsx

import { ExclamationCircleFilled } from '@ant-design/icons';

interface DeleteConfirmProps {
  open: boolean;
  title: string;
  description: string;
  onConfirm: () => void;
  onCancel: () => void;
  loading?: boolean;
}

const DeleteConfirmModal: React.FC<DeleteConfirmProps> = ({
  open,
  title,
  description,
  onConfirm,
  onCancel,
  loading,
}) => {
  const { token } = theme.useToken();

  return (
    <Modal
      open={open}
      onCancel={onCancel}
      onOk={onConfirm}
      okText="删除"
      cancelText="取消"
      okButtonProps={{
        danger: true,
        loading,
      }}
      title={
        <span style={{ color: token.colorWarning }}>
          <ExclamationCircleFilled style={{ marginRight: 8 }} />
          确认删除
        </span>
      }
    >
      <p style={{ fontSize: token.fontSizeLG, fontWeight: 600, marginBottom: 8 }}>
        {title}
      </p>
      <p style={{ color: token.colorTextDescription }}>
        {description}
      </p>
    </Modal>
  );
};

// 使用示例
const showDeleteConfirm = (entityName: string, onConfirm: () => void) => {
  Modal.confirm({
    title: '确认删除',
    icon: <ExclamationCircleFilled />,
    content: (
      <div>
        <p>确定要删除"{entityName}"吗？</p>
        <p style={{ color: 'rgba(0,0,0,0.45)' }}>
          请注意：确认后，该数据将不可恢复。
        </p>
      </div>
    ),
    okText: '删除',
    cancelText: '取消',
    okButtonProps: { danger: true },
    onOk: onConfirm,
  });
};
```

### 13.7 可访问性 (A11y)

*   **焦点管理**：
    *   对话框打开时，**焦点必须自动置于"取消"按钮上**。
    *   使用 `Tab` 键应在两个按钮间循环，不允许焦点逃逸到背景内容。
*   **ARIA 属性**：
    *   对话框容器应设置 `role="dialog"` 和 `aria-modal="true"`。
    *   应使用 `aria-labelledby` 指向包含确认问句的元素。

### 13.8 使用原则

*   **强制性**： 任何删除数据实体的操作都必须经过此确认框。
*   **信息明确**： 必须清晰指明要删除的对象是什么，有多少。
*   **后果警示**： 必须明确提示操作不可逆。
*   **操作平衡**： 提供平等权重的"是/否"选择，取消操作必须和确认操作一样便捷。
*   **克制使用**： 仅用于高风险操作。低风险操作（如取消编辑）不应使用此模式。

## 十四、页面筛选器（下拉弹出式）设计规范

### 14.1 组件概述

*   **组件名称**： 筛选器面板 (Filter Panel)
*   **组件类型**： 下拉弹出面板 (Dropdown Popover Panel)
*   **功能描述**： 为用户提供一个临时、轻量的交互层，用于定义和修改当前列表视图的数据筛选条件。
*   **设计目标**： 易于触发、操作直观、状态明确、不中断主任务流。

### 14.2 触发机制与定位

*   **触发控件**： 一个位于列表页操作栏内的按钮，通常由"漏斗"图标和"筛选器"文字组成。可附加徽标以动态显示当前生效的筛选条件数量。
*   **触发动作**： 用户点击该按钮。
*   **显示与定位**：
    *   面板在触发按钮的**正下方**弹出。
    *   **水平对齐**： 面板的**左边缘与触发按钮的左边缘对齐**。
    *   **垂直贴合**： 面板的顶部与触发按钮的底部紧密贴合。
*   **关闭机制**：
    1.  点击面板内的"**更新**"或"**取消**"按钮。
    2.  点击面板之外的页面任何区域。
    3.  按下键盘 `Esc` 键。

### 14.3 面板视觉与布局规范

*   **容器 (Container)**：
    *   **宽度**： `320px` (固定宽度)
    *   **背景**： `token.colorBgContainer`
    *   **边框**： `1px solid token.colorBorderSecondary`
    *   **圆角**： `token.borderRadiusLG`
    *   **阴影**： `token.boxShadowSecondary`
    *   **层级 (Z-index)**： 确保面板浮于所有页面内容之上。

*   **内部结构 (自上而下)**：
    1.  **面板标题 (Header)**：
        *   **文字**： "设备筛选器" 或对应实体名称。
        *   **字体**： `token.fontSizeLG`， 字重 600， 颜色 `token.colorText`。
        *   **内边距**： `padding: 16px 20px 12px 20px;`。
        *   **下边框**： `1px solid token.colorBorderSecondary`。

    2.  **条件主体区 (Body)**：
        *   **内边距**： `padding: 20px;`。
        *   **布局**： 垂直堆叠表单字段组，间距统一为 `20px`。

        *   **筛选字段组 (Filter Field Group)**：
            *   **标签 (Label)**：
                *   **文字**： 字段描述，如"设备状态"。
                *   **样式**： `token.fontSizeSM`， 颜色 `token.colorTextDescription`。
            *   **控件 (Control)**：
                *   使用 Ant Design 的 Select、Input、DatePicker 等组件。
                *   默认选项应为"全部"或"所有"。

    3.  **操作区 (Footer)**：
        *   **布局**： 弹性布局，两端对齐。
        *   **内边距**： `padding: 16px 20px;`。
        *   **上边框**： `1px solid token.colorBorderSecondary`。
        *   **按钮**：
            *   **左侧按钮**： 一个"**重置**"按钮。
            *   **右侧按钮组**： 包含"**取消**"和"**更新**"两个按钮。

### 14.4 组件实现

```tsx
import { useState } from 'react';
import { Button, Dropdown, Form, Select, Space, Tag, theme } from 'antd';
import { FilterOutlined } from '@ant-design/icons';

interface FilterPanelProps {
  fields: Array<{
    name: string;
    label: string;
    options: Array<{ value: string; label: string }>;
  }>;
  values: Record<string, string>;
  onChange: (values: Record<string, string>) => void;
  onReset: () => void;
}

const FilterPanel: React.FC<FilterPanelProps> = ({
  fields,
  values,
  onChange,
  onReset,
}) => {
  const [open, setOpen] = useState(false);
  const [form] = Form.useForm();
  const { token } = theme.useToken();

  const activeFilterCount = Object.values(values).filter(Boolean).length;

  const handleApply = () => {
    const formValues = form.getFieldsValue();
    onChange(formValues);
    setOpen(false);
  };

  const handleReset = () => {
    form.resetFields();
    onReset();
  };

  const dropdownContent = (
    <div style={{
      width: 320,
      background: token.colorBgContainer,
      borderRadius: token.borderRadiusLG,
      boxShadow: token.boxShadowSecondary,
    }}>
      <div style={{
        padding: '16px 20px 12px',
        borderBottom: `1px solid ${token.colorBorderSecondary}`,
      }}>
        <span style={{
          fontSize: token.fontSizeLG,
          fontWeight: 600,
          color: token.colorText,
        }}>
          筛选条件
        </span>
      </div>

      <Form form={form} layout="vertical" style={{ padding: 20 }}>
        {fields.map((field) => (
          <Form.Item
            key={field.name}
            name={field.name}
            label={
              <span style={{
                fontSize: token.fontSizeSM,
                color: token.colorTextDescription,
              }}>
                {field.label}
              </span>
            }
          >
            <Select
              placeholder="全部"
              allowClear
              options={field.options}
            />
          </Form.Item>
        ))}
      </Form>

      <div style={{
        display: 'flex',
        justifyContent: 'space-between',
        padding: '16px 20px',
        borderTop: `1px solid ${token.colorBorderSecondary}`,
      }}>
        <Button type="link" onClick={handleReset}>
          重置
        </Button>
        <Space>
          <Button onClick={() => setOpen(false)}>取消</Button>
          <Button type="primary" onClick={handleApply}>更新</Button>
        </Space>
      </div>
    </div>
  );

  return (
    <Dropdown
      open={open}
      onOpenChange={setOpen}
      dropdownRender={() => dropdownContent}
      trigger={['click']}
    >
      <Button icon={<FilterOutlined />}>
        筛选器
        {activeFilterCount > 0 && (
          <Tag color="processing" style={{ marginLeft: 8 }}>
            {activeFilterCount}
          </Tag>
        )}
      </Button>
    </Dropdown>
  );
};
```

### 14.5 激活的筛选条件标签行

```tsx
import { Space, Tag, theme } from 'antd';
import { CloseOutlined } from '@ant-design/icons';

interface FilterTagsProps {
  filters: Array<{ key: string; label: string; value: string }>;
  onRemove: (key: string) => void;
  onClearAll: () => void;
}

const FilterTags: React.FC<FilterTagsProps> = ({
  filters,
  onRemove,
  onClearAll,
}) => {
  const { token } = theme.useToken();

  if (filters.length === 0) return null;

  return (
    <div style={{
      display: 'flex',
      flexWrap: 'wrap',
      gap: 8,
      padding: '12px 24px',
      background: token.colorFillAlter,
      borderBottom: `1px solid ${token.colorBorderSecondary}`,
    }}>
      {filters.map((filter) => (
        <Tag
          key={filter.key}
          closable
          onClose={() => onRemove(filter.key)}
          style={{
            background: token.colorPrimaryBg,
            color: token.colorPrimary,
            border: 'none',
          }}
        >
          {filter.label}: {filter.value}
        </Tag>
      ))}
      <Button type="link" size="small" onClick={onClearAll}>
        清除全部
      </Button>
    </div>
  );
};
```

### 14.6 交互与状态逻辑

*   **初始状态**： 面板隐藏。触发按钮无特殊样式，或显示当前生效的筛选条件数量。
*   **展开状态**： 点击触发按钮，面板弹出。焦点应自动置于面板内的第一个可交互控件上。
*   **应用筛选 ("更新")**：
    1.  面板关闭。
    2.  页面主列表根据设定的条件重新加载数据。
    3.  在列表顶部显示"激活的筛选条件标签行"。
*   **取消操作**： 点击"取消"或面板外区域，面板关闭，所有未"更新"的修改被丢弃。
*   **重置操作**： 点击"重置"，立即将面板内所有条件控件的值恢复至默认状态。

### 14.7 扩展性与可访问性

*   **多条件支持**： 面板的 Body 区域应设计为可滚动。
*   **复杂控件**： 支持文本输入框、日期/时间选择器、开关等。
*   **键盘导航**：
    *   `Tab` / `Shift+Tab` 应在面板内的可聚焦元素间循环。
    *   `Esc` 必须可关闭面板。
*   **屏幕阅读器 (ARIA)**：
    *   面板容器应设置 `role="dialog"` 或 `role="menu"`。
    *   触发按钮应通过 `aria-expanded` 属性告知屏幕阅读器面板的展开/收起状态。

## 十五、总结

本设计规范基于 Ant Design 6.x 设计系统，核心特点：

| 特点 | 描述 |
|------|------|
| **Design Token 系统** | 使用 token 实现主题一致性 |
| **双主题支持** | 亮色/暗色主题自动切换 |
| **组件化设计** | 基于 Ant Design 组件库 |
| **遮盖式抽屉** | 不挤压列表，保持上下文 |
| **渐进式披露** | 高级功能隐藏在 Tab 中 |
| **响应式设计** | 多断点支持 |
| **可访问性** | 符合 WCAG 标准 |

此设计规范适用于构建企业级 IoT 平台或 B 端管理系统，具有专业、清晰、高效的特点。
