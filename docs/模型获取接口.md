# KIMI调研 #

基于 2026 年 5 月 15 日的最新公开资料，以下是对国内外常见大模型供应商是否支持通过 API 接口获取模型列表及模型信息的系统调研结果。

---

## 一、国际主流厂商

### 1. OpenAI
**支持情况：✅ 原生支持**

OpenAI 在其官方 API 中提供了标准的模型发现端点，这是行业的事实标准：
- **端点**：`GET https://api.openai.com/v1/models`
- **功能**：列出所有可用的模型，包括模型 ID、所有者、创建时间等元数据
- **格式**：返回 OpenAI 标准的模型列表格式（`{"object": "list", "data": [...]}`）
- **认证**：`Authorization: Bearer sk-...`

该端点被绝大多数第三方工具和 SDK 依赖，用于自动发现可用模型。

### 2. Anthropic (Claude)
**支持情况：✅ 原生支持（2026 年更新）**

根据 2026 年 4 月的 API 文档，Anthropic 原生 API 已明确提供 Models API：
- **端点**：`GET https://api.anthropic.com/v1/models`
- **功能**：列出可用模型并检查模型能力
- **认证**：`x-api-key: YOUR_API_KEY`
- **必需头部**：`anthropic-version: 2023-06-01`

此外，Anthropic 在 2026 年 3 月还推出了 **OpenAI 兼容 API 端点**，允许通过 OpenAI SDK 调用 Claude 模型，进一步降低了迁移成本。但 Anthropic 明确说明该兼容层"**主要用于测试评估**，生产环境仍推荐使用原生 SDK"。

**2026 年 5 月最新动态**：Claude Opus 4.7 已发布，Claude Sonnet 4 和 Opus 4 将于 2026 年 6 月 15 日退役。

### 3. Google (Gemini)
**支持情况：❌ 不支持（原生格式）**

Google Gemini API 使用独立的 REST 格式，与 OpenAI 不兼容：
- **对话端点**：`POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`
- **模型信息**：需通过 Google Cloud Console 或文档手动查询，**无自动化的模型列表 API 端点**
- **鉴权**：`x-goog-api-key: YOUR_API_KEY` 或 URL 参数 `?key=...`

Gemini 的模型发现依赖于官方文档或 SDK 中的硬编码模型名称，不支持通过 API 动态拉取可用模型列表。

## 二、国内主流厂商

### 4. DeepSeek (深度求索)
**支持情况：✅ 支持（OpenAI 兼容模式）**

DeepSeek 官方 API 完全兼容 OpenAI 格式：
- **Base URL**：`https://api.deepseek.com/v1`
- **端点**：`GET /v1/models`（兼容 OpenAI 标准）
- **认证**：`Authorization: Bearer sk-...`
- **代表模型**：`deepseek-v4-pro`、`deepseek-v4-flash` 等

2026 年 5 月 12 日的验证显示，DeepSeek 的 `/v1/models` 端点确实返回模型列表，但**不返回定价信息**，需要开发者额外维护定价表。

### 5. 阿里云百炼 (通义千问 Qwen)
**支持情况：✅ 支持（OpenAI 兼容模式）**

阿里云百炼提供完整的 OpenAI 兼容接口：
- **Base URL**：
    - 北京：`https://dashscope.aliyuncs.com/compatible-mode/v1`
    - 弗吉尼亚：`https://dashscope-us.aliyuncs.com/compatible-mode/v1`
    - 新加坡：`https://dashscope-intl.aliyuncs.com/compatible-mode/v1`
- **端点**：`GET /v1/models`（支持）
- **认证**：`Authorization: Bearer $DASHSCOPE_API_KEY`

官方文档明确展示了兼容 OpenAI 的接口体系，兼容层完整支持模型发现。

### 6. 百度千帆 (文心一言)
**支持情况：⚠️ 部分支持（非 OpenAI 格式）**

百度千帆 API 采用独立的鉴权和接口体系：
- **模型详情接口**：`POST https://qianfan.baidubce.com/v2/model?Action=DescribeModelSet`
- **鉴权方式**：基于 AK/SK 的签名计算鉴权（非 Bearer Token）
- **限制**：需要预先知道 `modelSetName` 或 `modelSetId` 才能查询，**不支持像 OpenAI 那样无参数获取全部模型列表**

**结论**：百度提供模型信息查询能力，但接口设计为"按名称/ID 查询详情"，而非"列出所有可用模型"，且格式与 OpenAI 不兼容。

### 7. 字节跳动 (豆包 / 火山方舟)
**支持情况：❓ 未明确支持（公开资料有限）**

火山方舟官方文档主要展示视频生成模型（如 `doubao-seedance` 系列）的模型列表页面，但**未找到关于 `/v1/models` API 端点的明确公开文档**。其 Base URL 为 `https://ark.cn-beijing.volces.com/api/v3`，但关于模型列表接口的 REST API 公开资料有限。

**推测**：火山方舟可能通过控制台提供模型列表，但缺乏官方公开的 REST API 文档确认。

### 8. 智谱 AI (GLM)
**支持情况：⚠️ 混合支持**

智谱 AI 的 API 支持情况较为复杂，存在两个不同的接口体系：

**原生 API**：
- **Base URL**：`https://open.bigmodel.cn/api/paas/v4/`
- **路径规范**：`/api/paas/v4/chat/completions`（**非 OpenAI 标准路径**）
- **问题**：原生路径与 OpenAI 兼容路径存在冲突，有开发者报告在 OpenAI 兼容模式下强制拼接 `/v1` 导致 404 错误

**OpenAI 兼容模式**（通过第三方或特定渠道）：
- **Base URL**：`https://api.cxsee.com/v1` 或 `https://claude.claudeyy.com/v1`
- **端点**：`POST /chat/completions`
- **支持模型**：`glm-5-turbo`、`glm-4.7` 等

**结论**：智谱官方原生 API **不完全兼容** OpenAI 的 `/v1/models` 端点，但部分第三方兼容渠道支持。

### 9. 月之暗面 (Kimi)
**支持情况：✅ 支持（OpenAI 兼容模式）**

Kimi API 完全兼容 OpenAI 格式，官方文档明确声明支持 List Models API：
- **Base URL**：`https://api.moonshot.cn/v1`
- **端点**：`GET /v1/models`（兼容 OpenAI 标准）
- **认证**：`Authorization: Bearer MOONSHOT_API_KEY`
- **代表模型**：`kimi-k2.6`、`kimi-k2.5`、`moonshot-v1-8k/32k/128k` 等

官方文档明确说明："You can use our List Models API to get a list of currently available models."

**2026 年 5 月最新动态**：`kimi-k2` 系列将于 **2026 年 5 月 25 日**正式下线，推荐使用 `kimi-k2.6`。

### 10. 讯飞星火
**支持情况：❓ 未明确支持（公开资料有限）**

在多次搜索中，**未找到讯飞星火 API 提供模型列表接口的公开文档**。其 API 主要面向对话和语音识别，模型发现可能需要通过官方文档或控制台手动获取。

## 四、关键发现与建议

1. **OpenAI 兼容模式成为事实标准**：国内主流厂商（DeepSeek、阿里云、Kimi）均通过兼容 OpenAI API 格式来降低开发者迁移成本，这也使得它们天然支持 `GET /v1/models` 模型发现端点。

2. **原生协议 vs 兼容协议**：国际厂商中，OpenAI 和 Anthropic 均原生支持模型列表；Google 坚持独立协议，不支持。国内厂商中，百度千帆采用独立鉴权体系，模型发现能力受限；智谱 AI 存在原生路径与兼容路径的冲突。

3. **第三方聚合平台的补充作用**：如 OpenRouter、硅基流动等聚合平台通过统一封装，为下游应用提供了标准化的模型发现能力，弥补了部分厂商原生 API 的不足。

4. **实际开发建议**：如果构建需要动态发现模型的应用，优先选择明确支持 OpenAI 兼容 `/v1/models` 端点的厂商（OpenAI、Anthropic、DeepSeek、阿里云、Kimi），或采用聚合 API 网关作为统一接入层。对于 Google Gemini、百度千帆、讯飞星火等厂商，建议通过官方文档或控制台手动维护模型列表。

## 二、详细说明与建议

### 1. **完全支持专用API查询的供应商**
- **OpenAI**、**Anthropic**、**Kimi** 提供了标准的`GET /v1/models`（或类似）接口，开发者可直接编程获取模型列表及元数据。
- **百度千帆** 通过`DescribeModel`等接口提供模型信息查询。
- **DeepSeek** 在官方文档中明确列出了当前可用的模型ID及特性，信息集中且易于获取。

### 2. **通过控制台/文档提供列表，但无专用API的供应商**
- **智谱AI**、**阿里云百炼**、**腾讯混元**、**讯飞星火**、**字节跳动豆包** 等平台，均在控制台或文档页面提供了完整的模型列表、规格及调用参数，但**未明确提供专用的REST API端点供程序化查询**。开发者需要手动查阅文档或登录控制台查看。

### 3. **通过聚合平台接入的供应商**
- 如**MiniMax**、**硅基流动**等，通常作为第三方模型集成在腾讯云TokenHub、阿里云百炼等平台中。模型列表由聚合平台统一管理，供应商自身可能不直接提供模型列表查询API。

### 4. **通用获取方法**
即使平台未提供专用的List Models API，开发者仍可通过以下方式获取模型信息：
- **查阅官方文档**：各平台文档均会列出支持的模型ID及规格（如腾讯云TokenHub文档、阿里云百炼文档）。
- **登录控制台**：在“模型广场”、“模型列表”等页面查看所有可用模型。
- **使用OpenAI兼容接口**：对于支持OpenAI兼容格式的平台（如腾讯云TokenHub、Kimi），可尝试调用`/v1/models`，部分平台可能支持此端点。
- **关注官方公告与更新日志**：模型迭代信息通常通过公告或更新日志发布（如DeepSeek更新日志）。

## 三、2026年市场趋势与选型建议
1.  **接口标准化**：越来越多平台兼容OpenAI API格式（如腾讯云TokenHub、Kimi），降低了集成成本。
2.  **模型迭代加速**：主流模型已进入V4/V5时代（如DeepSeek-V4、GLM-5.1、Qwen3.6系列），上下文窗口普遍扩展至256K-1M，并强化了Agent、多模态、深度思考等能力。
3.  **成本与性能平衡**：各平台均提供从旗舰版到轻量版的模型矩阵（如豆包Seed 2.0的Pro/Lite/Mini，千问的Max/Plus/Flash），方便根据场景选择。
4.  **选型建议**：
    - **需要程序化获取模型列表**：优先选择OpenAI、Anthropic、Kimi、百度千帆等提供专用API的供应商。
    - **追求性价比与中文优化**：可关注智谱GLM-5.1、DeepSeek-V4-Flash、通义千问Flash等。
    - **企业级集成**：阿里云百炼、腾讯云TokenHub等提供完整的模型管理、监控、安全能力。
    - **复杂Agent与推理任务**：考虑Claude Opus 4.7、豆包Seed 2.0 Pro、混元Hy3 preview等。

## 四、快速查询指引
| 需求场景 | 推荐查询方式 |
|----------|------------|
| 获取最新模型列表 | 登录对应平台控制台，查看“模型广场”或“模型列表”页面 |
| 编程式集成 | 优先使用OpenAI、Anthropic、Kimi等提供`/models`端点的平台；其他平台需将模型ID硬编码或通过配置中心管理 |
| 了解模型详细规格 | 查阅官方API文档中的“模型介绍”或“能力说明”章节（如腾讯云文档） |
| 获取价格与限流信息 | 控制台“计费说明”或“价格计算器”页面 |

总体而言，2026年大模型API生态已高度成熟，所有主流供应商均提供API调用能力，但在**模型列表的编程式获取**上，仅部分供应商提供了专用接口。在实际开发中，建议结合官方文档、控制台和社区资源，确保使用最新的模型ID和规格信息。
