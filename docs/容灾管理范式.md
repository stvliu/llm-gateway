# 容灾管理范式与控制台落地

> 关联：`doc/容灾方案设计.md` 的管理面配套。把四层容灾栈机制藏起来，给管理员暴露「容灾模式」档位 + 「降级兜底」开关，专家字段折叠。

## 一、管理核心原则：选而非填

容灾画像有十几个字段，但 99% 场景管理员不该看到它们。三个杠杆：

1. **好默认**——开箱即用的 `default` profile，不配置也安全。
2. **模板化**——预设画像模板，管理员克隆微调而非从零填。
3. **可视化**——容灾总览看状态，绑定关系在现有列表加一列下拉。

管理员面对的是「给这个 Key 选哪个模板」，不是「逐字段配容灾」。错误分流表、`qualityFloor`、`cluster_affinity` 等专家字段默认折叠，只在「高级配置」展开。

## 二、三屏管理范式

### 屏1：容灾总览（Dashboard 增强，只读）

回答「现在稳不稳」，只读不配置：

- **故障域拓扑**：Cluster 卡片视图，每卡显示成员渠道 + 健康灯（绿/黄/红）。一眼看到哪些渠道共因、哪个域挂了。
- **实时转移事件流**：最近 N 条 L1/L2 转移记录——「gpt-4o 请求 14:32 触发 L1，openai-us→openai-sg，成功」。
- **耗尽告警**：某模型所有渠道/L1 候选耗尽时高亮，提示该补供给侧。

### 屏2：画像模板（Templates，低频配）

策略库页，管理预设模板：

- 开箱模板：`default` / `strict`（严格型）/ `aggressive`（激进型）/ `batch`（批量型）。
- 模板列表 + 一键应用到示例 Key 的预览。
- 专家字段（错误分流表、`pinned_model_codes`）折叠在「高级」里。

### 屏3：绑定关系（复用现有 Keys/Teams 页，高频）

管理员 99% 日常操作，不新建页面，在现有列表加一列下拉：

- **API Keys 列表**：每行加「容灾模式」下拉，选档位即完成绑定。
- **Teams 列表**：每行加「默认模式」下拉，设团队默认。
- 绑定即生效，无需多步表单。

## 三、应急操作（复用 Channels 页）

| 操作 | 作用 | 场景 |
|------|------|------|
| 一键手动熔断（摘流量） | 立即把某渠道踢出候选 | 怀疑渠道质量差，主动摘除 |
| 一键恢复 | 解除手动熔断 | 渠道修复，重新接入 |
| 紧切指定域 | 临时把流量钉到某 Cluster | 主域故障，强制切备用域 |

手动熔断写入熔断器（复用现有 `CircuitBreaker`），与自动熔断同语义，`HealthRouter` 自动过滤，不引入新的「摘除」状态机。

## 四、容灾模式档位 → 底层字段推导映射

管理员只面对 2 个面向字段：`容灾模式`（三档位）+ `降级兜底`（开关+深度）。其余字段由档位自动推导，专家才覆盖。

### 面向管理员的两个字段

| 字段 | 取值 | 说明 |
|------|------|------|
| 容灾模式 | `STANDARD` / `STRICT` / `AGGRESSIVE` | 覆盖五场景的三档位 |
| 降级兜底 | `{enabled: bool, maxDepth: int}` | 由模式预填，可微调 |

### 三档位语义

- **STANDARD（标准）**：L1 全开 + L2 浅降级（深度 2）。通用默认，平衡可用性与质量。对应五场景里的「运营流程自动化」「多 agent 大脑」（agent 走会话亲和另配）。
- **STRICT（严格）**：L1 全开 + **L2 关闭**。不可降级场景，宁可报错不可换模型。对应「Claude Code/CodeX」「agent 大脑（要求一致性时）」。
- **AGGRESSIVE（激进）**：L1 全开 + L2 深降级（深度 3）+ 短超时 + 就近。可用性优先，质量次之。对应「客服/HelpDesk」。

`BATCH`（批量）作为 STANDARD 的变体：QUEUED 转移 + COST_OPTIMIZED + 长超时，对应「IPD 文档生成」，由「容灾模式=STANDARD + 高级里切 transferMode=QUEUED」实现，不单列档位以保持三档简洁。

### 档位 → ResilienceProfile 字段推导表

| Profile 字段 | STANDARD | STRICT | AGGRESSIVE | 备注 |
|------|------|------|------|------|
| `enableL1ChannelFailover` | true | true | true | 三档都开 L1（核心） |
| `enableL2ModelDegradation` | true | **false** | true | STRICT 关 L2 |
| `degradationMaxDepth` | 2 | 0 | 3 | 「降级兜底」可微调 |
| `transferMode` | FAST | FAST | FAST | BATCH 变体切 QUEUED |
| `sessionAffinity` | false | false | false | agent 场景高级开启 |
| `pinnedModelCodes` | null | **需填**（锁定模型） | null | STRICT 专家字段，锁定 Claude 等 |
| `qualityFloor` | null | null | STANDARD | 激进降级兜质量下限 |
| `timeoutSeconds` | null（用渠道默认） | 60 | **15** | AGGRESSIVE 短超时 |
| `costStrategy` | null | null | LATENCY_OPTIMIZED | BATCH 变体切 COST_OPTIMIZED |
| `clusterAffinity` | null | PINNED | NEAREST | |
| `errorRoutingOverride` | 默认表 | 全 L1（除 INVALID_REQUEST） | 默认表 | STRICT 覆盖：所有可转移错误都走 L1 不降级 |

### 「降级兜底」开关与档位的联动

`降级兜底.enabled=false` 等价于 `enableL2ModelDegradation=false` + `degradationMaxDepth=0`，即任何档位都能用这个开关临时关闭 L2。`maxDepth` 在 `enabled=true` 时生效，由档位预填默认值，管理员可在 1–5 内微调。

## 五、操作映射总表

```
管理员问                  去哪                    做什么
─────────────────────────────────────────────────────────
现在稳不稳?          → 容灾总览               只看
给新应用配容灾       → Keys 页选下拉           选容灾模式档位
客服要更激进降级     → Keys 页选 AGGRESSIVE     选档位（不用进模板）
CodeX 要锁模型       → Keys 页选 STRICT + 高级  填 pinnedModelCodes
某渠道有问题先摘掉   → Channels 页一键熔断      应急
主域挂了快切备用     → Channels 页紧急切域      应急
团队级默认策略       → Teams 页选模式           设团队默认
```

## 六、控制台页面改动清单（P2 落地依据）

| 页面 | 改动 | 复杂度 |
|------|------|--------|
| Dashboard | 新增「容灾总览」区块（故障域拓扑 + 转移事件流） | 中 |
| API Keys 列表 | 加「容灾模式」下拉列 + 高级抽屉（pinned/兜底深度） | 小 |
| Teams 列表 | 加「默认模式」下拉列 | 小 |
| Channels 详情 | 加「手动熔断/恢复/紧切域」按钮 | 小 |
| 新建模板页（可选） | 画像模板 CRUD，专家字段折叠 | 中 |

新增后端 API：
- `GET /api/resilience/profiles` —— 模板列表
- `PUT /api/keys/{id}/resilience` —— 绑定模式（body: `{mode, fallback:{enabled,maxDepth}, pinnedModelCodes?}`）
- `PUT /api/teams/{id}/resilience-default`
- `POST /api/channels/{id}/circuit-breaker` —— 手动熔断/恢复
- `POST /api/resilience/events` —— 转移事件流（SSE 或轮询）

## 七、关键取舍

1. **不暴露四层栈概念**：L0/L1/L2 是内部机制，管理员只看「容灾模式」+「降级兜底」。
2. **三档位覆盖五场景**：STANDARD/STRICT/AGGRESSIVE + BATCH 变体，避免模式爆炸。
3. **日常操作零新页面**：绑定靠现有 Keys/Teams 列表加下拉，不强迫管理员学新交互。
4. **应急复用熔断器**：手动摘流量与自动熔断同语义，无新状态机。
