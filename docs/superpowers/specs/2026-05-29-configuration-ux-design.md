# 供应商/接入点/API Key/模型 配置体验设计

> 日期：2026-05-29
> 状态：已定稿（版本 v2，根据深度 Review 修正）

---

## 1. 设计原则

### 1.1 用户思维模型优先

界面按用户的思维模型组织，而非后端领域模型：

| 用户思维 | 后端实体 |
|---------|---------|
| "我要接入哪个 AI 公司" | Provider |
| "我拿到什么 Key" | ChannelCredential |
| "我能用哪些模型" | ChannelModel → Model |
| "谁可以访问" | User, Team |

用户不需要理解 `Provider → Channel → ChannelEndpoint → ChannelCredential → ChannelModel → Model` 的层级关系。

### 1.2 双模式设计

| 维度 | 快速模式 | 专家模式 |
|------|---------|---------|
| 目标用户 | 初次配置 / 快速新增 | 高阶管理员 / 批量变更 |
| 操作路径 | 3步向导 + 智能默认值 | Tab 面板 + YAML 编辑 |
| 默认值 | 自动推断（内置模板） | 全部字段可编辑 |
| 批量能力 | 无 | 导入导出 / 批量轮换 |

### 1.3 渐进式披露

用户先看到快速模式，熟练后自然发现专家模式入口。模式切换不丢失已填数据。

## 3. 快速接入流程

### 3.1 三步向导

```
步骤 1：选择供应商      步骤 2：配置接入         步骤 3：选择模型
┌─────────────────┐   ┌─────────────────┐   ┌─────────────────┐
│ ○ OpenAI        │   │ API Key: [____] │   │ ☐ gpt-4o       │
│ ○ Anthropic     │   │ 测试连通性 🔄   │   │ ☐ gpt-4o-mini  │
│ ○ Azure OpenAI  │   │                 │   │ ☐ o3           │
│ ○ Google Gemini │   │ + 添加备用 Key  │   │ ☐ o4-mini      │
│ ○ 自定义...     │   │ (负载均衡)      │   │                 │
└─────────────────┘   └─────────────────┘   └─────────────────┘
                                             全不选默认不启用
```

关键改进：
- 步骤 3 模型**默认不勾选**，用户按需选择，避免意外消耗
- 步骤间自动保存草稿，离开后回来恢复进度
- 步骤 1 选"自定义"时展开更多字段（协议、Base URL、协议版本）

### 3.2 智能默认值

选择主流供应商后，系统自动填充：

| 供应商 | 协议 | 默认 Endpoint | 推荐模型 |
|--------|------|--------------|---------|
| OpenAI | OPENAI | https://api.openai.com/v1 | gpt-4o, gpt-4o-mini, o3, o4-mini |
| Anthropic | ANTHROPIC | https://api.anthropic.com/v1 | claude-sonnet-4-6, claude-haiku-4-5 |
| Azure OpenAI | OPENAI | {resource}.openai.azure.com | 需用户指定 |
| Google Gemini | GEMINI | https://generativelanguage.googleapis.com | gemini-2.0-flash |

**模板扩展点机制**：Azure 等需要额外参数的供应商，在步骤 2 中自动插入供应商特定字段（如 "Resource Name"、"API Version"），不破坏三步结构。

### 3.3 Key 输入交互

- 支持同时粘贴多个 Key（换行/逗号分隔）
- 自动去重
- 内置连通性测试按钮，测试期间显示 spinner，超时 10 秒提示
- 支持单通道配置多 Key（负载均衡），可视化展示优先组和权重
- Key 输入框支持 paste 事件监听，粘贴后自动触发格式检测

### 3.4 向导中的错误处理

| 场景 | 行为 |
|------|------|
| 连通性测试失败 | 显示具体错误原因（Key 无效/网络超时/供应商限流），提供"重试"和"换一个 Key"两个操作 |
| Key 已过期 | 标注"此 Key 已过期"，阻止继续 |
| 模型列表加载失败 | 显示空模型列表 + "跳过此步骤，稍后在专家模式中配置"链接 |
| 步骤间离开 | 自动保存草稿到 localStorage，标记"未完成"状态，仪表盘显示待办提示 |
| 并发提交 | 后端返回冲突时，提示"此供应商正在被其他管理员配置"，展示当前状态 |

## 4. 专家模式

### 4.1 Tab 布局

切换到专家模式时，快速模式下填入的信息自动展开到完整视图。

Tab 缩减至 5 个（超过 5 个的按钮折叠入 More 菜单）：

| Tab | 包含字段 |
|-----|---------|
| 基础信息 | 供应商、显示名称、计费模式、优先级、权重 |
| 接入点 | 协议（OPENAI/ANTHROPIC/GEMINI/NATIVE）、Base URL、多接入点配置 |
| API Key | Key 管理（CRUD）、优先级、权重、状态、过期监控、轮换操作 |
| 模型映射 | 关联模型、upstream_model_name（别名映射）、定价覆盖、能力标签 |
| 更多 | 限流与配额（RPM/TPM）、高级设置（超时、重试策略、断路器参数、自定义 Header） |

### 4.2 YAML 双向编辑

**冲突解决策略（单向优先）：**
- 表单操作为主：用户在表单修改时，YAML 预览区实时同步更新
- YAML 编辑为独立操作：点击"编辑 YAML"进入独立编辑器，此时表单锁定
- 从 YAML 编辑器保存退出后，表单重新渲染以反映 YAML 中的值
- 若 YAML 语法错误，编辑器底部显示错误提示 + 行号定位，阻止保存

**版本管理：**
- 每次保存自动生成版本快照
- 版本对比支持 side-by-side diff
- 回滚操作需二次确认："回滚后将丢失 X 次修改"

## 5. 开发者门户

开发者门户是独立视图，与 Admin 侧边栏完全隔离。通过右上角 `👤 切换到开发者视图` 进入。

### 5.1 模型目录

- 展示当前用户所在团队已开通的所有模型
- 每个模型卡片包含：名称、供应商、能力标签（文本/图像）、价格透明
- 支持按供应商/能力搜索筛选
- 未开通任何模型时，显示空状态："暂无可用模型，请联系团队管理员开通"

### 5.2 自助 Key 生成

- 一键创建 API Key，权限范围由管理员在团队级别预配置（开发者无需选择）
- 自动关联到当前用户和团队
- 创建成功后弹窗展示完整 Key + 代码示例，弹窗关闭后 Key 不再可读
- 每个开发者可管理自己的 Key（查看前缀、吊销、重生成），不可查看其他开发者的 Key

### 5.3 内嵌代码示例

- 自动填入新生成的 API Key
- 代码中包含 Gateway 的完整 Base URL：`https://api.your-gateway.com/v1`
- 支持多语言切换：cURL / Python / Node.js / Java
- 一键复制

```bash
# cURL 示例（Key 自动填充）
curl https://api.your-gateway.com/v1/chat/completions \
  -H "Authorization: Bearer sk-your-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```

## 6. 模板与批量操作

### 6.1 预置模板

- OpenAI 标准、Anthropic 标准、Azure OpenAI、Google Gemini
- 每个模板预配置了默认 Endpoint、协议、推荐模型
- 支持"使用此模板" + 自定义覆盖
- 模板更新（如 OpenAI 新增模型）不自动影响已创建的配置——模板是模板，配置是配置

### 6.2 自定义模板

- 管理员可将已有配置保存为自定义模板
- 支持团队内共享

### 6.3 批量操作

**导入流程（三步）：**
1. 上传或粘贴配置文本（YAML / JSON / CSV）
2. 解析预览：显示导入内容概览 + 差异对比（新增/修改/不变）
3. 确认执行：存在冲突时逐条标记，用户决定"跳过冲突项"或"覆盖"

**导出策略：**
- 导出不包含 API Key（仅导结构 + 元数据 + Key 前缀用于识别）
- 重新导入后提示"请补充 API Key"
- 导出范围可选定：全部 / 指定供应商 / 指定通道

## 7. 统一 API Key 管理

### 7.1 双 Tab 视角

| 视角 | 内容 | 展示信息 |
|------|------|---------|
| 上游 Key | 供应商凭证（ChannelCredential） | 前缀、供应商、关联通道、状态、优先级/权重、最后使用时间、近 24h 错误率 |
| 下游 Key | 用户密钥（UserApiKey） | 前缀、所属用户、关联通道、状态、最后使用时间、创建时间 |

### 7.2 关键交互

- 搜索/筛选：按 Key 前缀、供应商、状态筛选
- **状态标签（色盲友好）**：`✅ 活跃`（绿底）、`⚠️ 已降级`（黄底加图标）、`❌ 过期`（红底加图标）
- 批量轮换：选择多个 Key → "轮换" → 系统生成新 Key → 旧 Key 进入 24h 宽限期（新旧同时有效）→ 宽限期内可回滚
- 过期告警：Key 到期前 N 天（可配置）发送通知，支持应用内通知 + 邮件

### 7.3 安全约束

- "👁️ 查看明文"需要二次认证（输入登录密码或 MFA 验证码）
- Key 明文查看操作记录到审计日志
- Key 列表页默认仅显示前缀（前 8 字符 + 掩码）
- 批量导出不包含 Key 明文

| 页面 | 空状态设计 |

| 模型目录 | "暂无模型，请先接入供应商" + 跳转快速接入链接 |
| API Key 管理（上游）| "尚未添加任何供应商 Key" + 跳转供应商列表 |

### 9.2 加载状态

| 场景 | 加载态 |
|------|--------|
| 首页仪表盘加载 | 供应商卡片骨架屏（3 个灰色卡片） |

### 9.3 错误状态

| 场景 | 错误处理 |
|------|---------|
| 仪表盘数据加载失败 | 重试按钮 + "数据加载失败" |

| 网络断连 | 顶部通栏提示 + 断连状态下禁止提交 |
| YAML 语法错误 | 编辑器内行号定位 + 底部错误摘要 |

## 10. 无障碍（Accessibility）

| 规则 | 实现方式 |
|------|---------|
| 非颜色标识 | Key 状态使用图标 + 文字标签 + 颜色的三重编码：`✅ 活跃`、`⚠️ 已降级`、`❌ 过期` |
| 键盘导航 | 三步骤向导支持 Tab/Enter 导航，方向键切换选项 |
| 屏幕阅读器 | 所有操作按钮带 aria-label，步骤指示器带 aria-current="step" |
| 对比度 | 所有文本满足 WCAG AA 4.5:1 |
| 焦点管理 | 错误时自动聚焦第一个错误字段；弹窗关闭后回到触发按钮 |
| 减少动效 | 尊重 prefers-reduced-motion，YAML 预览同步不做动画 |
| 错误公告 | 表单错误使用 aria-live="polite" 通知屏幕阅读器 |

## 11. 通知体系

| 通知类型 | 触发条件 | 展示方式 | 目标用户 |
|---------|---------|---------|---------|
| Key 即将过期 | 到期前 N 天 | 仪表盘 banner + 右上角通知铃铛 + 邮件 | Admin |
| Key 已过期 | 到期当天 | 仪表盘红色警告 + 邮件 | Admin |
| 配置冲突 | 保存时发现版本落后 | 弹窗 + diff 对比 | Admin |
| 模型已弃用 | 上游模型 deprecation | 仪表盘提示 + 模型列表标注 | Admin |
| Key 创建成功 | 开发者创建 Key | 弹窗（展示一次）| Developer |
| 导入完成 | 批量导入结束 | Toast（成功数/失败数）| Admin |

## 12. 技术实现建议

### 12.1 模板系统

- 内置模板以 JSON/YAML 格式存储在 `gateway-boot/src/main/resources/templates/`
- 模板数据结构对齐 `Channel` + `ChannelEndpoint` + `ChannelModel` 聚合根
- 自定义模板存储在数据库 `provider_templates` 表中
- 模板更新不影响已实例化的配置（复制而非引用）

### 12.2 配置导入导出格式

```yaml
version: "1.0"
providers:
  - name: OpenAI
    channels:
      - name: 主通道
        billing_mode: pay_as_you_go
        endpoints:
          - protocol: OPENAI
            base_url: https://api.openai.com/v1
        credentials:
          - api_key_prefix: sk-proj-xxx
            priority: 1
            weight: 100
        models:
          - model_name: gpt-4o
            upstream_model_name: gpt-4o
          - model_name: gpt-4o-mini
            upstream_model_name: gpt-4o-mini
```

### 12.3 前端路由

```
/                        → 仪表盘
/providers               → 供应商列表
/providers/:id           → 供应商详情（快速/专家模式）
/models                  → 模型目录
/keys                    → API Key 管理（上游/下游 Tab）
/teams                   → 团队与权限
/settings                → 系统设置
/developer               → 开发者门户（独立布局）
/developer/keys          → 我的 API Key
/developer/usage         → 个人用量
```
