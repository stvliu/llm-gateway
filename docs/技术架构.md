## 1. 模块总览

> **现状**：2026-08-25 最终包结构定型后，项目为 **17 模块 Maven 多模块架构**（父 POM artifactId = `gateway-project`）。业务逻辑已下沉到各功能域模块，HTTP 承载归 `gateway-web`（api/interceptor/advice），`gateway-boot` 仅保留启动装配（config/init/event + GatewayApplication）。

## 2. gateway-boot 后端主模块

> **现状**：`gateway-web` 为 HTTP 承载层（根包 `com.codingas.gateway.web`），包含 `api` 全部 Controller、`interceptor` 与 `advice`；`gateway-boot` 为启动装配（根包 `com.codingas.gateway.boot`，`config`/`init`/`event` + GatewayApplication），负责装配各功能域模块（protocol/provider/iam/usage/security/audit/alert/resilience/proxy/stats/common）。业务逻辑与持久化实现已按域下沉到各功能域模块，采用模块化包名（模块 = 根包，去除 DDD 前缀），详见 `docs/constitution.md` §3.1。

### 2.2 技术选型决策

#### 2.2.1 Sa-Token vs Spring Security

| 维度 | Sa-Token | Spring Security | 决策 |
|------|----------|-----------------|------|
| **学习曲线** | 低 | 高 | ✅ Sa-Token |
| **配置复杂度** | 简单 | 复杂 | ✅ Sa-Token |
| **API Key 认证** | 内置支持 | 需自定义 | ✅ Sa-Token |
| **性能** | 轻量 | 较重 | ✅ Sa-Token |
| **社区生态** | 中文社区 | 全球主流 | 🟡 Spring Security |
| **企业级特性** | 足够 | 完善 | 🟡 Spring Security |

**决策结论**：选择 Sa-Token
- 项目主要面向国内政企客户，中文社区支持更好
- API Key 认证场景简单，Sa-Token 内置支持
- 轻量级框架更符合网关性能要求

#### 2.2.2 LangChain4j vs 直接 HTTP 调用

> **现状**：当前实现为 **直接 HTTP 调用（OkHttp 4.12.0 + okhttp-sse）**，未引入 LangChain4j（pom 无依赖）。LangChain4j 集成作为「规划中 / 设计愿景」保留。

| 维度 | LangChain4j | 直接 HTTP | 决策 |
|------|-------------|----------|------|
| **多厂商统一** | ✅ 统一 API | ❌ 各厂商差异大 | 🟡 直接 HTTP + 协议适配层 |
| **Token 计量** | ✅ 内置估算器 | ❌ 需自行实现 | ✅ 自研 Token 计量 |
| **流式处理** | ✅ 统一封装 | 🟡 需逐厂商适配 | ✅ 协议插件化适配 |
| **灵活性** | 🟡 受框架约束 | ✅ 完全可控 | ✅ 直接 HTTP |
| **升级风险** | 🟡 依赖框架更新 | ✅ 自主控制 | ✅ 直接 HTTP |

**现状结论**：当前选择 **直接 HTTP + 协议适配层（双协议插件化）**
- 通过 `gateway-protocol` 抽象层（Canonical IR + ProtocolAdapter SPI）统一 OpenAI/Anthropic/Gemini 协议差异，替代 LangChain4j 的框架封装
- Token 计量自研实现（输入/输出分别统计），符合「Token 成本透明」核心原则
- 若后续引入 LangChain4j（规划中），可通过域核心模块的纯净接口隔离，不影响现有协议适配架构

#### 2.2.3 数据库选型：PostgreSQL + H2（MySQL 规划中）

> **现状**：当前仅支持 **PostgreSQL 14+（生产）** 与 **H2（开发测试，`MODE=PostgreSQL`）**，无 MySQL 驱动。MySQL 支持（含「标准版」分层）为「规划中 / 设计愿景」，不作为已实现能力描述。

| 维度 | PostgreSQL 14+ | H2（开发） | 说明 |
|------|---------------|------------|------|
| **定位** | 生产环境唯一数据库 | 本地开发/测试 | H2 以 MODE=PostgreSQL 兼容模式运行 |
| **向量存储** | 🟡 pgvector 可选（规划中） | ❌ | 语义缓存为规划功能 |
| **JSONB 性能** | ✅ 二进制存储+索引 | 🟡 兼容模式 | 模型能力存储 |
| **全文检索** | ✅ 内置 | 🟡 部分兼容 | 日志搜索 |
| **迁移** | ✅ Flyway 11.0.0 | ✅ 同一迁移脚本 | V1~V68 |

**环境数据库矩阵**：

| 环境 | 数据库 | 说明 |
|------|--------|------|
| **生产** | PostgreSQL 14+ | 唯一生产数据库 |
| **开发/测试** | H2（MODE=PostgreSQL 文件库） | 零外部依赖，快速启动 |
| **分布式高可用** | PostgreSQL 集群 | 主从复制（+ pgvector 可选，规划中） |
| **MySQL** | ❌ 不支持（规划中） | 当前无 MySQL 驱动，未列入选型 |

**决策结论**：
- **生产选型 PostgreSQL 14+**：JSONB、全文检索、信创兼容能力完整，配合 Flyway 迁移体系
- **开发选型 H2（MODE=PostgreSQL）**：与生产同方言，避免开发/生产行为差异
- **MySQL 支持规划中**：若后续需要，可通过数据访问层抽象（Gateway 接口）扩展，当前不作为选型目标

### 2.4 安全机制

> **版本说明**：当前敏感数据加密使用 **AES-256-GCM**（`gateway-iam` 的 `EncryptionService` 实现，密钥由 `GATEWAY_ENCRYPTION_KEY` 配置）；**国密算法（SM2/SM3/SM4）为「规划中 / 设计愿景」**，当前代码无 Bouncy Castle 依赖、未实现。

| 机制 | 实现 | 说明 |
|------|------|------|
| 认证 | Sa-Token + ApiKeySaTokenDao | API Key → User 映射（gateway-iam） |
| 限流 | JVM 本地 + Redis 分布式 | 双层限流（gateway-usage） |
| 脱敏 | 数据脱敏（SensitiveDataRule） | 全局响应拦截（gateway-security） |
| 威胁检测 | IpBlock IP 威胁检测 | 安全与威胁域（gateway-security） |
| 加密 | AES-256-GCM | 敏感数据（API Key 等）加密存储，密钥外部化 |
| 签名 | —（规划中） | 许可证签名验证（原 SM2/RSA 设计，当前无实现） |

### 2.5 国密算法实现

> **状态**：**规划中 / 设计愿景**。当前代码未实现国密算法（SM2/SM3/SM4），无 Bouncy Castle 依赖；敏感数据加密实际使用 AES-256-GCM。以下为未来引入国密算法时的设计蓝图，仅作设计参考，不代表已实现能力。
>
> **版本说明**：若未来落地，国密算法将作为**企业版专属功能**，标准版不支持。

#### 2.5.1 算法应用场景

| 场景 | 算法 | 说明 |
|------|------|------|
| API Key 加密 | SM4-GCM | 对称加密，替代 AES |
| 密码哈希 | SM3 | 哈希算法，替代 SHA-256 |
| 许可证签名 | SM2 | 非对称加密，替代 RSA |
| 数据完整性 | SM3-HMAC | 消息认证码 |

#### 2.5.3 核心接口定义

```java
// 域核心模块 - 加密网关接口
public interface CryptoGateway {
    
    /**
     * SM4-GCM 对称加密
     */
    String encrypt(String plaintext, String key);
    
    /**
     * SM4-GCM 对称解密
     */
    String decrypt(String ciphertext, String key);
    
    /**
     * SM3 哈希
     */
    String hash(String data);
    
    /**
     * SM2 签名
     */
    String sign(String data, String privateKey);
    
    /**
     * SM2 验签
     */
    boolean verify(String data, String signature, String publicKey);
}
```

#### 2.5.4 API Key 加密存储

```
加密流程：
明文 API Key → 生成随机 IV（12字节）→ SM4-GCM 加密 → Base64 编码 → 存储

存储格式：
IV:密文:Tag（Base64 编码）

解密流程：
存储格式 → Base64 解码 → 解析 IV/密文/Tag → SM4-GCM 解密 → 明文 API Key
```

```
┌─────────┐      ┌─────────┐       ┌─────────┐
```

### 4.3 完整性校验

```java
// 审计链校验服务
@Service
public class AuditChainVerificationService {
    
    /**
     * 验证审计链完整性
     * @return 校验结果
     */
    public VerificationResult verifyChain() {
        List<AuditLog> logs = auditGateway.findAllOrderByCreatedAt();
        
        for (int i = 1; i < logs.size(); i++) {
            AuditLog prev = logs.get(i - 1);
            AuditLog current = logs.get(i);
            
            // 验证 previous_hash 是否匹配
            if (!current.getPreviousHash().equals(prev.getCurrentHash())) {
                return VerificationResult.tampered(i, "Hash chain broken");
            }
            
            // 验证 current_hash 计算是否正确
            String expectedHash = calculateHash(prev.getCurrentHash(), current);
            if (!current.getCurrentHash().equals(expectedHash)) {
                return VerificationResult.tampered(i, "Hash mismatch");
            }
        }
        
        return VerificationResult.valid();
    }
}
```

#### 6.5.1 域核心模块接口

```java
/**
 * 限流器接口
 * 
 * 域核心模块只定义限流能力，不暴露技术实现细节。
 * 具体实现（本地/分布式）由实现类根据配置决定。

public interface RateLimiter {

     * 尝试获取许可
     * @param key 限流 Key（用户/API Key/Channel 等）

     * @param window 时间窗口
     * @return 限流结果（是否允许、剩余次数、重试等待时间）

    private String id;        // 具体标识
    private String scope;     // 作用域（可选）
}

 * 限流结果
 */

    private int remaining;
```

#### 6.5.2 技术实现

**本地限流实现（标准版单机）**：

```java
@Component
@ConditionalOnProperty(name = "rate-limit.mode", havingValue = "local", matchIfMissing = true)
public class LocalRateLimiter implements RateLimiter {
    
    private final Map<String, com.google.common.util.concurrent.RateLimiter> limiters 
        = new ConcurrentHashMap<>();
    
    @Override
    public RateLimitResult tryAcquire(RateLimitKey key, int limit, Duration window) {
        String limiterKey = buildKey(key);
        com.google.common.util.concurrent.RateLimiter limiter = 
            limiters.computeIfAbsent(limiterKey, k -> 
                com.google.common.util.concurrent.RateLimiter.create(limit / window.toSeconds()));
        
        boolean allowed = limiter.tryAcquire();
        return new RateLimitResult(allowed, (int) limiter.availablePermits(), 0);
    }
    
    @Override
    public int getCurrentCount(RateLimitKey key) {
        return 0;  // 本地限流不统计精确计数
    }
}
```

**分布式限流实现（企业版）**：

```java
@Component
@ConditionalOnProperty(name = "rate-limit.mode", havingValue = "distributed")
public class RedisRateLimiter implements RateLimiter {
    
    private final RedisTemplate<String, String> redisTemplate;
    private final DefaultRedisScript<List<Long>> slidingWindowScript;
    
    @Override
    public RateLimitResult tryAcquire(RateLimitKey key, int limit, Duration window) {
        String redisKey = buildKey(key);
        List<Long> result = redisTemplate.execute(
            slidingWindowScript,
            Collections.singletonList(redisKey),
            String.valueOf(window.toMillis()),
            String.valueOf(limit),
            String.valueOf(System.currentTimeMillis())
        );
        
        boolean allowed = result.get(0) == 1L;
        long remaining = result.get(1);
        return new RateLimitResult(allowed, remaining, allowed ? 0 : window.toMillis());
    }
    
    @Override
    public int getCurrentCount(RateLimitKey key) {
        String redisKey = buildKey(key);
        Long count = redisTemplate.opsForZSet().zCard(redisKey);
        return count != null ? count.intValue() : 0;
    }
}
```

#### 6.5.3 Redis Lua 脚本（分布式限流）

```lua
-- sliding_window_limit.lua
-- KEYS[1] = 限流 Key
-- ARGV[1] = 窗口大小（毫秒）
-- ARGV[2] = 限制次数
-- ARGV[3] = 当前时间戳

local key = KEYS[1]
local window = tonumber(ARGV[1])
local limit = tonumber(ARGV[2])
local now = tonumber(ARGV[3])

-- 清理过期数据
redis.call('ZREMRANGEBYSCORE', key, 0, now - window)

-- 获取当前窗口请求数
local current = redis.call('ZCARD', key)

if current < limit then
    redis.call('ZADD', key, now, now .. ':' .. math.random())
    redis.call('PEXPIRE', key, window)
    return {1, limit - current - 1}  -- 允许，剩余次数
else
    return {0, 0}  -- 拒绝
end
```

```java
// 域核心模块 - 静默期服务
@Service
public class AlertSilenceService {
    
    private final RedisTemplate<String, String> redisTemplate;
    
    /**
     * 检查是否在静默期
     */
    public boolean isInSilencePeriod(String ruleCode, String targetKey) {
        String silenceKey = buildSilenceKey(ruleCode, targetKey);
        return Boolean.TRUE.equals(redisTemplate.hasKey(silenceKey));
    }
    
    /**
     * 设置静默期
     */
    public void setSilencePeriod(String ruleCode, String targetKey, int minutes) {
        String silenceKey = buildSilenceKey(ruleCode, targetKey);
        redisTemplate.opsForValue().set(silenceKey, "1", minutes, TimeUnit.MINUTES);
    }
    
    private String buildSilenceKey(String ruleCode, String targetKey) {
        return String.format("alert:silence:%s:%s", ruleCode, targetKey);
    }
}
```

### 8.5 认证流程

```
1. 发起登录
   └── GET /oauth/{provider}/login
       ├── 生成 state（存入 Redis，5 分钟过期）
       ├── 构建授权 URL
       └── 重定向到 OAuth Provider

2. 用户授权
   └── OAuth Provider 显示授权页面
       └── 用户同意授权

3. 回调处理
   └── GET /oauth/{provider}/callback?code=xxx&state=xxx
       ├── 验证 state（防止 CSRF）
       ├── 用 code 换取 access_token
       ├── 获取用户信息
       └── 查找或创建用户

4. 用户查找/创建
   ├── UserOAuth 存在？→ 登录已有用户
   └── UserOAuth 不存在？
       ├── 已登录用户？→ 绑定 OAuth 身份
       └── 未登录用户？→ 创建新用户 + 创建 UserOAuth

5. 建立会话
   └── Sa-Token 创建会话
       ├── 生成 token
       ├── 存储用户信息
       └── 重定向到前端
```

### 10.6 请求/响应拦截

```java
// 技术实现 - 响应脱敏拦截器
@ControllerAdvice
public class SensitiveDataResponseAdvice implements ResponseBodyAdvice<Object> {
    
    private final SensitiveDataDetector detector;
    private final SensitiveDataMasker masker;
    
    @Override
    public Object beforeBodyWrite(Object body, MethodParameter returnType, 
                                   MediaType selectedContentType,
                                   Class<? extends HttpMessageConverter<?>> selectedConverterType,
                                   ServerHttpRequest request, ServerHttpResponse response) {
        if (body instanceof String content) {
            List<SensitiveDataMatch> matches = detector.detect(content);
            if (!matches.isEmpty()) {
                return masker.mask(content, matches);
            }
        }
        return body;
    }
}
```

### 13.3 缓存架构

#### 13.3.1 Spring Cache 集成

项目采用 Spring Cache 作为统一缓存抽象，支持本地缓存和 Redis 缓存无缝切换。

**优势**：
- **注解简化**：`@Cacheable` / `@CacheEvict` 减少样板代码
- **无缝切换**：本地缓存 ↔ Redis 缓存只需改配置
- **统一管理**：`CacheManager` 统一管理所有缓存

**配置示例**：

```yaml
# 标准版单机 - 本地缓存
spring:
  cache:
    type: caffeine
    caffeine:
      spec: maximumSize=10000,expireAfterWrite=5m

# 企业版分布式 - Redis 缓存
spring:
  cache:
    type: redis
    redis:
      time-to-live: 5m
      cache-null-values: false
```

#### 13.3.5 配置同步兜底机制

> **适用场景**：企业版多实例部署，需要保证配置变更实时同步到所有实例。

**设计原则**：

| 原则 | 说明 |
|------|------|
| **事件优先** | 配置变更通过事件机制（Redis Pub/Sub）实时广播 |
| **轮询兜底** | 定时轮询版本号作为兜底，防止事件丢失 |
| **版本检测** | 所有实体表新增 `version` 字段，支持变更检测 |

**同步机制对比**：

| 机制 | 触发方式 | 延迟 | 可靠性 | 适用场景 |
|------|---------|------|--------|---------|
| **事件驱动** | 配置变更时主动发布 | 毫秒级 | 🟡 依赖 Redis | 实时同步（主） |
| **定时轮询** | 后台定时检查版本号 | 秒级（可配置） | ✅ 独立于 Redis | 兜底保障（备） |

**架构设计**：

```
┌─────────────────────────────────────────────────────────────┐
│                  配置同步兜底机制                             │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  [配置变更流程]                                              │
│  管理后台更新配置                                            │
│       │                                                      │
│       ▼                                                      │
│  数据库更新（version++）                                     │
│       │                                                      │
│       ├──────────────────┐                                  │
│       ▼                  ▼                                  │
│  Redis Pub/Sub        定时轮询（30秒）                       │
│  （实时广播）           （版本检测）                          │
│       │                  │                                  │
│       └────────┬─────────┘                                  │
│                ▼                                            │
│         各实例收到通知                                       │
│                │                                            │
│                ▼                                            │
│         清空缓存 → 重新加载                                  │
│                                                              │
│  [兜底机制说明]                                              │
│  - 轮询间隔：30 秒（可配置）                                  │
│  - 检测方式：比较 MAX(version) 是否变化                       │
│  - 触发条件：version 变化时触发缓存刷新                       │
│  - 适用表：providers, models, provider_api_keys 等           │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

**配置示例**：

```yaml
# application-cluster.yaml（企业版）
gateway:
  config:
    cache:
      # 版本检查间隔（秒）
      version-check-interval: 30
    event:
      # Redis Pub/Sub 通道
      redis-channel: "gateway:config:changed"
      # 事件模式：local（本地）/ redis（远程）
      mode: redis
```

**兜底机制实现要点**：

1. **版本号字段**：所有配置表新增 `version BIGINT DEFAULT 0` 字段
2. **乐观锁支持**：更新时校验版本号，防止并发冲突
3. **版本索引**：为 `version` 字段创建索引，加速 `MAX(version)` 查询
4. **独立于 Redis**：即使 Redis 故障，轮询仍可保证最终一致性

**详细设计参考**：`docs/superpowers/specs/2026-05-04-provider-model-apikey-loading-design.md`

```java
// 技术实现 - 本地限流实现
@Component
@ConditionalOnProperty(name = "rate-limit.mode", havingValue = "local", matchIfMissing = true)
public class LocalRateLimiter implements RateLimiter {
    
    private final Map<String, com.google.common.util.concurrent.RateLimiter> limiters 
        = new ConcurrentHashMap<>();
    
    @Override
    public RateLimitResult tryAcquire(RateLimitKey key, int limit, Duration window) {
        String limiterKey = buildKey(key);
        com.google.common.util.concurrent.RateLimiter limiter = 
            limiters.computeIfAbsent(limiterKey, k -> 
                com.google.common.util.concurrent.RateLimiter.create(limit / window.toSeconds()));
        
        boolean allowed = limiter.tryAcquire();
        return new RateLimitResult(allowed, (int) limiter.availablePermits(), 0);
    }
    
    @Override
    public int getCurrentCount(RateLimitKey key) {
        return 0;  // 本地限流不统计精确计数
    }
}
```

#### 14.4.9 适用场景

| 场景 | 推荐配置 | 说明 |

#### 14.4.10 限制说明

标准版单机部署的限制：

| 限制项 | 说明 |
|--------|------|
| **无高可用** | 单点故障风险 |
| **无语义缓存** | 不支持向量相似度缓存 |
| **无分布式限流** | 仅支持 JVM 本地限流 |
| **无 MCP 协议** | 企业版专属功能 |
| **无国密算法** | 企业版专属功能 |
| **无审计链 WORM** | 企业版专属功能 |
| **性能上限** | 单实例 QPS ≤ 5,000 |

#### 14.4.11 升级路径

从标准版单机部署升级到企业版分布式部署：

```
标准版单机                          企业版分布式
────────────                        ────────────
单 JVM 进行      ─────升级────►     K8s 多副本
PostgreSQL/H2    ─────迁移────►     PostgreSQL 集群（+ pgvector 规划中）
本地限流         ─────替换────►     Redis 分布式限流
本地缓存         ─────迁移────►     Redis 集群
无语义缓存       ─────启用────►     pgvector 语义缓存（规划中）
配置文件         ─────迁移────►     Nacos 配置中心
```
