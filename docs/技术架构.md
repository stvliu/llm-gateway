### 2.4 LLM 网关组件（LangChain4j 实现）

#### 2.4.1 技术选型

| 组件 | 技术 | 版本 | 说明 |
|------|------|------|------|
| **LLM 调用框架** | LangChain4j | 1.x | 统一封装 OpenAI/Anthropic 等多厂商 API |
| **底层 HTTP** | OkHttp | 5.x | LangChain4j 内部复用 OkHttp 连接池 |
| **Token 计量** | 内置 Estimator | - | `OpenAITokenCountEstimator` / `AnthropicTokenCountEstimator` |

#### 2.4.2 架构设计

```
domain/proxy/gateway/
├── ProxyGateway.java              # 代理转发接口（纯净，无外部依赖）
└── TokenCountGateway.java         # Token 计量接口（纯净，无外部依赖）

infrastructure/gateway/llm/
├── LangChain4jProxyGateway.java   # 实现 ProxyGateway，调用 OpenAI/Anthropic
└── LangChain4jTokenCountGateway.java  # 实现 TokenCountGateway，估算 Token 量
```

#### 2.4.7 职责边界

| 层 | 职责 |
|---|------|
| **domain** | 定义 `ProxyGateway` / `TokenCountGateway` 接口，纯 Java，无依赖 |
| **infrastructure** | 实现 `LangChain4jProxyGateway` / `LangChain4jTokenCountGateway`，依赖 LangChain4j |
| **adapter** | 调用 application 层服务，不直接感知 LangChain4j |

#### 2.4.8 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 厂商 API 变更 | LangChain4j 更新可能滞后 | 接口隔离，保留直接调用 OkHttp 的降级能力 |
| 版本升级破坏性变更 | 升级可能破坏兼容性 | 锁定主版本号，SPI 机制便于替换实现 |
| 部分厂商不支持 | Azure/Vertex 等 | 按需扩展 `TokenCountEstimator` 接口 |

#### 2.4.9 LangChain4j厂商动态配置管理（数据库加载）

LangChain4j 官方不支持从数据库加载配置，需自行实现动态刷新机制。

##### 设计方案

```
ProviderRepository (JPA)
        │
        ▼
ProviderConfigService  ──►  ChatModelCache  ──►  LangChain4jProxyGateway
        │                                                │
        │◄───── 配置变更事件 ───────┘                     │
        │                                                ▼
   配置变更监听器                                  动态构建 ChatModel
```

##### 核心组件

| 组件 | 职责 |
|------|------|
| `ProviderRepository` | 从数据库加载 Provider 配置（API Key、BaseURL、模型列表） |
| `ChatModelCache` | 缓存 ChatModel 实例，支持热更新 |
| `ProviderConfigService` | 配置变更时发布事件，触发缓存刷新 |
| `LangChain4jProxyGateway` | 从缓存获取 ChatModel，不直接创建 |

##### 接口定义

```java
// Domain 层 - 纯净接口
public interface ChatModelRegistry {
    ChatModel get(String providerCode);
    void refresh(String providerCode);
    void refreshAll();
}
```

##### 实现示例

```java
// Infrastructure 层 - 动态配置实现
@Component
public class DynamicChatModelRegistry implements ChatModelRegistry {

    private final Map<String, ChatModel> modelCache = new ConcurrentHashMap<>();
    private final ProviderRepository providerRepository;

    @Override
    public ChatModel get(String providerCode) {
        return modelCache.computeIfAbsent(providerCode, this::buildModel);
    }

    @Override
    public void refresh(String providerCode) {
        modelCache.remove(providerCode);
        log.info("ChatModel refreshed for provider: {}", providerCode);
    }

    @Override
    public void refreshAll() {
        modelCache.clear();
        log.info("All ChatModels refreshed");
    }

    private ChatModel buildModel(String providerCode) {
        Provider provider = providerRepository.findByCode(providerCode)
            .orElseThrow(() -> new ProviderNotFoundException(providerCode));

        return switch (provider.getApiType()) {
            case OPENAI -> OpenAiChatModel.builder()
                .apiKey(provider.getApiKey())
                .modelName(provider.getDefaultModel())
                .baseUrl(provider.getBaseUrl())  // 支持自定义 endpoint
                .timeout(Duration.ofSeconds(provider.getTimeout()))
                .build();
            case ANTHROPIC -> AnthropicChatModel.builder()
                .apiKey(provider.getApiKey())
                .modelName(provider.getDefaultModel())
                .timeout(Duration.ofSeconds(provider.getTimeout()))
                .build();
        };
    }
}
```

##### 配置变更监听

```java
@Component
public class ProviderConfigEventListener {

    private final ChatModelRegistry chatModelRegistry;

    @EventListener
    public void onProviderUpdated(ProviderUpdatedEvent event) {
        chatModelRegistry.refresh(event.getProviderCode());
    }

    @EventListener
    public void onApiKeyRotated(ApiKeyRotatedEvent event) {
        // 密钥轮换时热更新
        chatModelRegistry.refresh(event.getProviderCode());
    }
}
```

##### 调用方式

```java
@Service
public class LangChain4jProxyGateway implements ProxyGateway {

    private final ChatModelRegistry chatModelRegistry;

    @Override
    public ChatResponse forward(ProxyRequest request) {
        String providerCode = request.getProviderCode();
        ChatModel model = chatModelRegistry.get(providerCode);
        // 调用模型...
    }
}
```

##### 热更新触发场景

| 场景 | 触发方式 |
|------|---------|
| Provider 配置编辑 | `ProviderUpdatedEvent` |
| API Key 轮换 | `ApiKeyRotatedEvent` |
| 模型列表变更 | `ModelListChangedEvent` |
| 渠道健康检查恢复 | `ChannelRecoveredEvent` |

##### 职责边界

| 层 | 职责 |
|---|------|
| **domain** | 定义 `ChatModelRegistry` 接口 |
| **infrastructure** | 实现 `DynamicChatModelRegistry`，从数据库加载配置并缓存 |
| **application** | 发布配置变更事件 |
| **adapter** | 触发配置变更（通过 Controller 或外部系统） |

## 7. 部署架构

### 7.1 容器化

```dockerfile
# 多阶段构建
FROM maven:3.9-eclipse-temurin-21 AS builder
WORKDIR /app
COPY pom.xml .
COPY src ./src
RUN mvn package -DskipTests

FROM eclipse-temurin:21-jre-alpine
WORKDIR /app
COPY --from=builder /app/target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: llm-gateway
spec:
  replicas: 3
```
