## 业务域总览 / Business Domains Overview

| # | 业务域 | 英文名 | 核心职责 | 定位 |
|---|--------|--------|---------|------|
| 1 | 智能路由 | router | 路由决策、大模型交互执行、协议转换 | **核心域** |
| 2 | 模型供给 | supply | Provider 管理、Model 管理、ProviderApiKey | 支撑域 |
| 3 | 安全控制 | security | 身份认证、访问授权、敏感数据保护 | 支撑域 |
| 4 | 限额配额 | quota | Token 限额、用量预扣、限流控制 | 支撑域 |
| 5 | 会话记录 | session | 调用记录、用量归因、对话内容管理 | 支撑域 |
| 6 | 审计合规 | audit | 操作审计、不可篡改记录 | 支撑域 |
| 7 | 告警管理 | alert | 告警规则、通知发送、历史记录 | 支撑域 |

**域定位说明**：
- **核心域**：网关差异化竞争力所在，缺失则失去存在价值
- **支撑域**：企业级客户刚需，为核心域提供保障机制

## 1. router/ — 智能路由（核心域）

### 责任 / Responsibilities

- 路由决策：根据策略选择目标 Provider/Model
- 请求执行：发送请求到大模型，接收响应
- 协议转换：OpenAI ↔ Anthropic 格式转换
- 负载均衡：多 Provider/Key 的流量分配
- 故障转移：失败时自动切换
- 流式处理：SSE 流式响应分块

### 实体 / Entities

| 实体 | 英文名 | 说明 |
|------|--------|------|
| RouteGroup | 路由分组 | 路由策略配置，支持负载均衡和故障转移 |
| RouteGroupProvider | 路由关联 | 路由分组与 Provider 的关联，含权重/优先级/健康状态 |

### 实体关系 / Relationships

```
RouteGroup
├── 聚合 RouteGroupProvider（一个分组包含多个路由关联）
├── 被 RouterDomainService 用于路由决策
├── 配置负载均衡策略（权重分配）
└── 配置故障转移策略（备用 Provider）

RouteGroupProvider
├── 关联 Provider（一个路由关联必须指向一个 Provider）
├── 持有权重配置（用于负载均衡流量分配）
├── 持有优先级配置（高优先级优先使用）
├── 持有健康状态（由健康检查更新）
├── 由管理员配置（security 域管理员操作）
└── 当 Provider 不可用时被 RouterDomainService 自动跳过
```

## 2. supply/ — 模型供给

### 责任 / Responsibilities

- Provider 管理：模型提供商（OpenAI、Anthropic 等）
- Model 管理：模型列表和元数据
- ProviderApiKey 管理：Provider 调用凭证，多 Key 轮换
- 渠道健康检查：定期检测 Provider 可用性

### 实体 / Entities

| 实体 | 英文名 | 说明 |
|------|--------|------|
| Provider | 模型提供商 | 模型服务提供方，如 OpenAI、Anthropic |
| Model | AI 模型 | 具体的 AI 模型，如 gpt-4o、claude-sonnet-4 |
| ProviderApiKey | Provider 访问凭证 | 网关调用 Provider 的凭据，管理员配置，支持多 Key 轮换 |

### 实体关系 / Relationships

```
Provider
├── 提供多个 Model（一个 Provider 下有多个可用模型）
├── 配置多个 ProviderApiKey（一个 Provider 支持多组凭证）
├── 由管理员创建/启用/禁用（security 域）
├── 被 RouterDomainService 查询用于路由执行
└── 标识 BaseURL、状态（启用/禁用）

Model
├── 必须归属一个 Provider（不能独立存在）
├── 标识模型能力（上下文长度、多模态、Tool Use 支持）
├── 被 RouterDomainService 用于请求参数构造
└── 可被 RouteGroupProvider 引用（指定可用模型）

ProviderApiKey
├── 用于访问一个 Provider（凭证绑定到特定 Provider）
├── 被 LLMDispatcher 用于调用 Provider API
├── 支持多 Key 轮换（自动选择可用 Key）
├── 加密存储，由 ApiKeyEncryptionDomainService 管理
├── 持有 RPM/TPM 限制（上游 Provider 限制）
└── 失效时由 Key 健康检查自动禁用
```

## 3. security/ — 安全控制

### 责任 / Responsibilities

- 身份认证：验证请求者身份
- 访问授权：RBAC/ABAC 权限判断
- 敏感数据保护：PII 检测与脱敏
- IP/UA 过滤：黑名单/白名单控制

### 实体 / Entities

| 实体 | 英文名 | 说明 |
|------|--------|------|
| User | 系统用户 | 系统使用者 |
| Role | 角色 | 权限集合，用于 RBAC |
| Permission | 权限 | 细粒度权限，用权限码标识 |
| GatewayApiKey | 网关访问凭证 | 用户调用网关的凭证，用户自管理 |
| IpBlocklist | IP 黑名单 | 系统屏蔽的 IP 地址 |
| SensitiveDataRule | 敏感数据规则 | PII 检测与脱敏规则 |

### 实体关系 / Relationships

```
User
├── 创建多个 GatewayApiKey（用户持有自己的凭证）
├── 被分配多个 Role（支持多角色绑定）
├── 受 TokenLimit 约束（用户级限额）
├── 操作产生 AuditLog（谁做了什么）
├── 登录触发 AuthenticationDomainService 验证
├── 密码 BCrypt 加密存储
└── 可设置个人语言偏好

Role
├── 被分配给多个 User（角色可以被多用户持有）
├── 包含多个 Permission（角色拥有权限集合）
├── 用于 RbacDomainService 权限判断
└── 预设角色：管理员、开发者、观察者、财务管理员

Permission
├── 被多个 Role 包含（权限可复用）
├── 用权限码标识（如 provider:create, model:read）
└── 细粒度控制 API 操作权限

GatewayApiKey
├── 被 User 创建（用户生成自己的 Key）
├── 受 TokenLimit 约束（Key 级限额）
├── 用于请求认证（携带在 Authorization 头）
├── 可设置 IP 白名单（限制访问来源）
├── 可设置模型白名单（限制可用模型）
├── 过期时间由 GatewayApiKeyExpirationNotifier 监控
└── 哈希存储（不可还原）

IpBlocklist
├── 被系统全局应用（所有请求都检查）
├── 由管理员配置
├── 支持 IP/CIDR 格式
└── 命中时由 IpBlocklistDomainService 返回 403

SensitiveDataRule
├── 被 SensitiveDataMasker 应用到请求/响应
├── 包含检测规则（正则、关键词）
├── 定义脱敏方式（掩码、哈希、删除）
└── 覆盖 PII 类型：手机号、身份证、邮箱、银行卡等
```

## 4. quota/ — 限额配额

### 责任 / Responsibilities

- Token 限额：用户/Key/用户×渠道多级限制
- 预扣与结算：请求前预扣，实际消耗后调整
- 限流控制：RPM/TPM 令牌桶
- 超限策略：拒绝/降级/切换

### 实体 / Entities

| 实体 | 英文名 | 说明 |
|------|--------|------|
| TokenLimit | Token 限额配置 | 用户/Key/渠道的 Token 用量上限 |
| RateLimitConfig | 限流配置 | RPM/TPM 请求次数限制 |

### 实体关系 / Relationships

```
TokenLimit
├── 约束 User（用户级限额）
├── 约束 GatewayApiKey（Key 级限额）
├── 可选约束 Provider（用户×渠道限额）
├── 由 QuotaDomainService 检查
├── 超限时触发预设策略（REJECT → 402 / DOWNGRADE / SWITCH）
├── 与 UsageRecord 关联（用于计算已用量）
├── 支持周期重置（天/周/月/总量）
└── 预扣机制：请求前预估用量并冻结

RateLimitConfig
├── 约束 GatewayApiKey（Key 级 RPM/TPM）
├── 由 RateLimitDomainService 基于 Redis 令牌桶实现
├── 超限时返回 429 + Retry-After 头
├── 独立于 TokenLimit（两种不同的限制机制）
└── 支持 RPM（每分钟请求数）和 TPM（每分钟 Token 数）
```

## 5. session/ — 会话记录

### 责任 / Responsibilities

- 调用日志：每次 API 调用的元数据
- 用量记录：输入/输出 Token 统计
- 会话聚合：多轮对话的会话关联
- 对话内容：Prompt、Message、ResponseChunk

### 实体 / Entities

| 实体 | 英文名 | 说明 |
|------|--------|------|
| Conversation | 对话聚合根 | 多轮对话的会话 |
| CallLog | 调用日志 | 每次 API 调用的元数据 |
| UsageRecord | 用量记录 | 输入/输出 Token 统计 |
| Message | 消息 | 对话中的单条消息 |
| ResponseChunk | 响应片段 | 流式响应的单个片段 |

### 实体关系 / Relationships

```
Conversation
├── 由 User 发起（用户开始一个对话）
├── 包含多条 Message（多轮对话）
├── 产生多个 CallLog（每次 API 调用）
├── 用于跨次调用的上下文关联
└── 可设置 TTL（无活动超时自动清理）

CallLog
├── 归属 Conversation（属于哪个对话）
├── 记录调用元数据：
│   ├── 用户（User）
│   ├── 模型（Model）
│   ├── 请求时间、响应时间
│   ├── 状态码、错误信息
│   └── Trace ID（OpenTelemetry 追踪）
├── 产生 UsageRecord（记录 Token 消耗）
├── 触发 AlertRule（异常调用时）
└── 由 SessionDomainService 创建

UsageRecord
├── 归属 CallLog（从调用产生）
├── 记录输入 Token 数量
├── 记录输出 Token 数量
├── 用于 QuotaDomainService 限额计算
├── 由 TokenLimitDomainService 结算（预扣差额调整）
└── 支持按时间聚合（天/周/月统计）

Message
├── 归属 Conversation（属于哪个对话）
├── 区分角色（user/assistant/system）
├── 包含内容（Prompt/响应文本）
├── 支持多模态（图片、文件）
└── 由 RouterDomainService 构造后发送

ResponseChunk
├── 归属 Message（属于哪个消息）
├── 流式响应时逐步产生
├── 记录片段内容和时间戳
└── 最终组成完整的 assistant 回复
```

## 6. audit/ — 审计合规

### 责任 / Responsibilities

- 操作审计：记录所有管理操作
- 不可篡改性：链式哈希，WORM 存储
- 合规报告：满足 SOX/GDPR/等保要求

### 实体 / Entities

| 实体 | 英文名 | 说明 |
|------|--------|------|
| AuditLog | 审计日志 | 管理操作记录 |

### 实体关系 / Relationships

```
AuditLog
├── 记录操作者（User）
├── 记录操作类型（操作码）
├── 记录操作内容（变更前后数据）
├── 记录操作时间（时间戳）
├── 记录操作结果（成功/失败）
├── 记录客户端 IP（来源追溯）
├── 使用链式哈希（每条包含前一条哈希值）
├── WORM 存储（不可修改/删除）
├── 由 AuditDomainService 写入
└── 满足 SOX/GDPR/等保合规要求
```

## 7. alert/ — 告警管理

### 责任 / Responsibilities

- 规则定义：告警触发条件
- 模板管理：通知格式模板
- 通知发送：邮件、Webhook 等
- 历史记录：告警发送历史

### 实体 / Entities

| 实体 | 英文名 | 说明 |
|------|--------|------|
| AlertRule | 告警规则 | 告警触发条件定义 |
| AlertTemplate | 告警模板 | 通知格式模板 |
| AlertNotification | 告警通知 | 告警发送记录 |

### 实体关系 / Relationships

```
AlertRule
├── 定义触发条件（阈值、表达式）
├── 关联 AlertTemplate（使用模板格式化通知）
├── 由各域 DomainService 通过领域事件触发
├── 触发后产生 AlertNotification
├── 可属于不同业务域：
│   ├── 安全告警（登录异常、额度超限）
│   ├── 路由告警（Provider 不可用、失败率上升）
│   ├── 供给告警（Key 余额不足、模型下线）
│   └── 系统告警（服务异常、配置变更）
└── 支持静默期配置（避免重复告警）

AlertTemplate
├── 定义通知格式（标题、内容结构）
├── 被多个 AlertRule 引用（模板复用）
├── 支持多种渠道（邮件、Webhook、短信）
├── 包含变量占位符（{{alert_type}}, {{threshold}}）
└── 支持多语言（中文/英文）

AlertNotification
├── 由 AlertRule 触发产生
├── 使用 AlertTemplate 格式化
├── 记录：
│   ├── 触发时间
│   ├── 告警内容
│   ├── 通知渠道
│   ├── 发送状态（成功/失败）
│   └── 确认状态（已确认/未确认）
├── 由 AlertDomainService 管理发送
└── 可被用户确认（Ack）
```

## 跨域实体关系总览 / Cross-Domain Relationships

### 核心业务链路

```
┌─────────────────────────────────────────────────────────────────────┐
│                         请求入口                                     │
└─────────────────────────────┬───────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────────┐
│  security/  安全控制                                                 │
│  User ──持有──► GatewayApiKey                                        │
│       ──受限于──► TokenLimit (quota/)                               │
└─────────────────────────────┬───────────────────────────────────────┘
                              │ 认证通过
                              ▼
┌─────────────────────────────────────────────────────────────────────┐
│  quota/  限额配额                                                    │
│  GatewayApiKey ──受控于──► TokenLimit                                │
│                    ──受控于──► RateLimitConfig                      │
└─────────────────────────────┬───────────────────────────────────────┘
                              │ 限额检查通过
                              ▼
┌─────────────────────────────────────────────────────────────────────┐
│  router/  智能路由（核心）                                           │
│  RouteGroup ──包含──► RouteGroupProvider ──关联──► Provider (supply/)│
│                                                       │              │
│                                                       ▼              │
│                                                    Model (supply/)   │
│                                                                       │
│  RouterDomainService.execute()                                        │
│       │                                                              │
│       ├──► SupplyGateway.getProvider()   ← 通过 Gateway 访问外部资源│
│       ├──► LLMDispatcher 调用 Provider                               │
│       │                                                              │
│       └──► 产生领域事件                                               │
└─────────────────────────────┬───────────────────────────────────────┘
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐
│  session/       │ │  alert/        │ │  audit/         │
│  会话记录        │ │  告警管理       │ │  审计合规        │
│                 │ │                │ │                 │
│ CallLog         │ │ AlertRule ──►  │ │ AuditLog       │
│   │             │ │ AlertNotif.    │ │                 │
│   └──►          │ │                │ │                 │
│ UsageRecord     │ │ 监听领域事件    │ │ 监听领域事件    │
└─────────────────┘ └─────────────────┘ └─────────────────┘
```

### 关键业务语义

| 业务动作 | 关系描述 |
|---------|---------|
| 用户持有凭证 | User 创建/拥有 GatewayApiKey |
| 凭证受限额约束 | GatewayApiKey 被 TokenLimit 限制 |
| 对话产生调用 | Conversation 包含 CallLog |
| 调用消耗 Token | CallLog 产生 UsageRecord |
| 调用触发告警 | CallLog/UsageRecord 触发 AlertRule |
| 路由选择 Provider | RouteGroup 包含 RouteGroupProvider |
| Provider 提供模型 | Provider 提供 Model |
| 凭证用于调用 | ProviderApiKey 被 LLMDispatcher 使用 |
| 操作产生审计 | User 操作产生 AuditLog |
| 告警使用模板 | AlertRule 使用 AlertTemplate 格式化通知 |
