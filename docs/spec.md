## 一、项目概述

### 1.1 项目定位

**LLM-Gateway** 是专注大模型的企业级 AI 网关，定位为 APIPark 的差异化竞品，核心竞争力为 **更合规、更安全、更智能、更易用**。

### 1.2 核心价值主张

| 利益相关者 | 核心价值 |
|-----------|---------|
| **开发者** | 一次接入，通过标准 OpenAI/Anthropic API (Application Programming Interface) 调用 50+ 主流模型，开箱即用 |
| **架构师** | 零信任安全、国密合规、智能降级、全链路可观测、云原生部署 |
| **管理者** | Token 限额控制、用量透明化、合规审计链、ROI 分析 |
| **运维人员** | K8s 原生、智能诊断、Prometheus/Grafana 集成、零停机升级 |

### 1.2.1 目标客户画像

**核心付费客户**（决策者）:

| 客户类型 | 痛点需求 | 付费意愿 | 决策因素 |
|---------|---------|---------|---------|
| **政企客户** | 等保合规、国密算法、审计留痕 | 高（政策刚需） | 合规性、安全性、信创适配 |
| **金融机构** | 数据安全、审计追溯、业务连续性 | 高（监管要求） | 安全认证、SLA 承诺、案例背书 |
| **中大型企业** | 成本控制、多模型管理、统一入口 | 中高（效率提升） | 易用性、ROI 可量化、集成成本 |
| **AI 创业公司** | 快速接入、成本优化、灵活扩展 | 中（预算有限） | 开源免费、社区活跃、文档完善 |

**核心使用者**（影响者）:

| 使用者角色 | 使用场景 | 核心诉求 |
|-----------|---------|---------|
| **开发者** | 调用模型 API 开发应用 | API 稳定、文档完善、调试工具 |
| **架构师** | 技术选型、系统集成 | 架构清晰、扩展性强、技术栈匹配 |

| **安全合规** | 安全审计、合规检查 | 审计完整、日志清晰、合规证明 |

  决策者: 技术总监/架构师
  影响者: 开发负责人、运维负责人

#### 2.2.1 API 网关模块

**功能需求**:

| ID | 功能 | 详细描述 | 验收标准 | 版本 |
|----|------|---------|---------|------|
| GW-001 | OpenAI 端点 | 实现 `/v1/chat/completions`、`/v1/completions`、`/v1/embeddings`、`/v1/images/generations`、`/v1/audio/*`、`/v1/moderations` | 通过 OpenAI 官方 SDK 调用测试 | 标准版 |
| GW-002 | Anthropic 端点 | 实现 `/v1/messages` | 通过 Anthropic 官方 SDK 调用测试 | 标准版 |
| GW-003 | SSE 流式转发 | 支持 `stream: true` 参数，实时转发 | 首 token 延迟 ≤100ms (P95) | 标准版 |
| GW-004 | 非流式响应 | 支持 `stream: false` 参数，等待完整响应后返回 | 响应体完整，无截断 | 标准版 |
| GW-005 | 请求验证 | 验证请求体格式、必填字段、枚举值 | 返回标准错误格式 | 标准版 |
| GW-006 | 错误响应格式 | 所有错误返回 `{"error": {"message": "...", "type": "...", "code": "..."}}` | 符合 OpenAI 错误规范 | 标准版 |
| GW-007 | CORS 支持 | 支持跨域请求配置 | 可配置允许的源、方法、头 | 标准版 |
| GW-008 | 请求超时 | 可配置的请求超时时间 | 默认 30 秒，可配置 | 标准版 |
| GW-009 | 大请求体支持 | 支持最大请求体大小限制 | 默认 10MB，可配置 | 标准版 |

| GW-011 | 自定义响应头 | 支持配置自定义 HTTP 响应头（如 `X-Correlation-ID`） | 支持静态值和变量注入 | 标准版 |

#### 2.2.2 协议转换模块

**需求描述**: 在 OpenAI 和 Anthropic 格式之间进行双向转换，确保上游客户端无需感知下游格式差异。

**功能需求**:

| ID | 功能 | 详细描述 | 验收标准 | 版本 |
|----|------|---------|---------|------|
| PT-001 | OpenAI → Anthropic | 将 OpenAI 请求转换为 Anthropic 格式 | 参数映射准确率 ≥99.9% | 标准版 |
| PT-002 | Anthropic → OpenAI | 将 Anthropic 请求转换为 OpenAI 格式 | 参数映射准确率 ≥99.9% | 标准版 |
| PT-003 | Tool Use 双向映射 | Function Calling ↔ tool_use 互转 | 完整支持多轮工具调用 | 标准版 |
| PT-004 | 多模态转换 | 图片/文件内容格式转换 | 支持 base64 和 URL 引用 | 标准版 |
| PT-005 | 流式事件转换 | SSE 事件格式实时转换 | 转换延迟 ≤5ms (P95) | 标准版 |
| PT-006 | Thinking/Reasoning 转换 | 推理过程标记转换 | 兼容不同厂商的 reasoning 标记 | 标准版 |
| PT-007 | 直通转发优化 | 下游为 Anthropic 兼容端点时零转换转发 | 延迟增加 ≤5ms (P95) | 标准版 |
| PT-008 | 响应元数据透传 | 传递 usage、finish_reason 等元数据 | 数据完整性 100% | 标准版 |

**转换矩阵**:

| 源格式 | 目标格式 | 转换内容 |
|--------|---------|---------|
| OpenAI | Anthropic | messages → messages, tools → tools, temperature → temperature, max_tokens → max_tokens |
| Anthropic | OpenAI | messages → messages, tools → functions, system → system message |
| 各厂商 | OpenAI | 统一转换为 OpenAI 标准格式 |
| 各厂商 | Anthropic | 统一转换为 Anthropic 标准格式 |

#### 2.2.3 密钥池管理模块

**需求描述**: API Key 资源池管理，支持同一渠道下多个 API Key 的自动调度和故障隔离。本模块是渠道管理（2.2.7）中多 Key 管理的独立视图，**功能实现归于 Provider 管理模块**（CH-007~CH-013）。

**功能需求**:

| ID | 功能 | 详细描述 | 验收标准 | 版本 |
|----|------|---------|---------|------|
| KP-001 | Key 池 | 单渠道支持多个 API Key | 系统自动管理可用 Key | 标准版 |
| KP-002 | Key 调度 | 根据配置策略自动选择可用 Key | 支持轮询、随机、加权 | 标准版 |
| KP-003 | Key 健康检查 | 定期检查 Key 可用性 | 自动禁用失效 Key | 标准版 |
| KP-004 | Key 限流 | 每个 Key 独立 RPM (Requests Per Minute) / TPM (Tokens Per Minute) 限制 | 精确控制单个 Key 用量 | 标准版 |
| KP-005 | Key 切换 | Key 失效时自动切换到备用 Key | 切换延迟 ≤100ms | 标准版 |
| KP-006 | Key 恢复 | 被禁用的 Key 定期恢复检查 | 可配置恢复间隔 | 标准版 |
| KP-007 | Key 统计 | 统计每个 Key 的使用量/错误率 | 可视化展示 | 标准版 |

> **说明**: KP-001~KP-007 的功能实现详见 2.2.7 渠道管理模块（CH-007~CH-013），此处仅作为密钥池视角的需求汇总，避免实现细节重复。

#### 2.2.5 Provider 管理模块

**需求描述**: 管理通往各模型提供商的渠道实例，支持多渠道、多 Key、分组、负载均衡。

**功能需求**:

| ID | 功能 | 详细描述 | 验收标准 | 版本 |
|----|------|---------|---------|------|
| CH-001 | 渠道创建 | 创建渠道，配置 Provider、BaseURL、API Key、模型列表 | API Key 加密存储（AES-256） | 标准版 |
| CH-002 | 渠道编辑 | 修改渠道配置 | 热加载，无需重启 | 标准版 |
| CH-003 | 渠道删除 | 软删除渠道 | 不影响进行中请求 | 标准版 |
| CH-004 | 渠道查询 | 按条件查询渠道列表 | 支持分页、排序 | 标准版 |

**智能降级流程**:

```
请求 ──▶ 检查额度/模型可用性 ──▶ 正常模型
              │
              ▼（额度不足/故障）
         按降级链选择备选模型
              │
              ▼
         记录降级原因，通知用户
              │
              ▼
         定期检查原模型恢复
              │
              ▼（恢复后）
         自动切回原模型
```

## 四、安全与合规需求

### 4.1 零信任安全架构

LLM-Gateway 基于"永不信任，始终验证"原则构建，所有请求必须经过 10 层安全检查（**串行执行，任一层失败立即返回对应错误码，后续检查不再执行**）：

| 层级 | 检查项 | 失败响应 |
|------|--------|---------|
| [1] TLS (Transport Layer Security) 验证 | HTTPS + TLS ≥1.2 | 连接拒绝 |
| [2] Token 认证 | Bearer Token 有效 | 401 |
| [3] IP/UA 检查 | 非黑名单 | 403 |
| [4] API Key 状态 | ACTIVE + 未过期 | 403 |
| [5] 模型白名单 | 已授权模型 | 403 |
| [6] IP 白名单 | 授权 IP 段 | 403 |
| [7] 额度检查 | 余额充足 | 402 |
| [8] TokenLimit 检查 | 限额未超 | 执行策略 |
| [9] 限流检查 | RPM/TPM 未超 | 429 |
| [10] 敏感词过滤 | 内容合规 | 400 |

**详细检查标准与延迟要求**：> 参见 [应用架构](./应用架构.md#安全设计)

### 4.2 数据保护要求

| 保护类型 | 要求 | 验收标准 |
|---------|------|---------|
| **传输加密** | TLS 1.3+ / 国密 TLS | 全链路加密 |
| **密钥存储** | AES-256-GCM / SM4 加密 | 密钥与数据分离 |
| **密码存储** | BCrypt (cost≥12) | 不可逆哈希 |
| **日志脱敏** | PII 自动掩码 | 手机号 `138****1234`、邮箱 `a***@example.com` |
| **审计链** | WORM 存储 + 链式哈希 | 7 年保留，不可篡改 |

**PII 检测范围**：请求/响应体、日志；不检测 URL 参数和 HTTP 头。

**合规冲突解决**：GDPR 删除权 vs WORM 审计 → PII 字段使用确定性哈希替换，保留审计记录完整性。

### 4.3 合规与密钥管理

| 合规项 | 适用场景 | 核心要求 |
|--------|---------|---------|
| **等保 2.0 三级** | 政务、央企、金融 | 国密算法 (SM2/SM3/SM4) |
| **GDPR / PIPL** | 欧洲/国内业务 | 数据删除权、PII 脱敏、跨境审计 |
| **SOX / 金融监管** | 金融、上市公司 | 7 年审计日志、不可篡改 |
| **OWASP ASVS L2** | 全行业 | 密码策略、CSRF/XSS 防护 |

**密钥管理**：支持对接 HashiCorp Vault / 云厂商 KMS；密钥自动轮换（默认 90 天）；临时密钥、时间限制、使用次数限制。

**安全评分**：系统内置安全基线评分，<60 分阻止生产部署（CI/CD 卡点）。

> 威胁模型 (STRIDE)、ABAC 属性定义、详细安全检查标准：> 参见 [应用架构](./应用架构.md#安全设计)

## 六、性能需求

### 6.1 核心性能指标

**基准请求特征**（所有性能指标的测试基准）:
- 平均输入 Token: 1,000 tokens
- 平均输出 Token: 500 tokens
- 非流式:流式 = 60%:40%
- Payload 大小: 平均 5KB 请求 / 平均 3KB 响应
- 模型分布: GPT-4o 40%, Claude Sonnet 30%, 其他 30%

| 指标 | 要求 | 测量方法 |
|------|------|---------|
| **首 token 延迟** | ≤100ms (P95) | 从网关接收客户端请求完毕到首字符 SSE 事件发出 |
| **网关处理延迟（非流式）** | ≤10ms (P95) | 网关自身处理时间（协议转换+策略评估+路由决策），含本地 Cache 查询，不含数据库查询和网络 I/O |
| **直通转发延迟增加** | ≤5ms (P95) | 下游为 Anthropic 兼容端点时 |
| **协议转换延迟** | ≤5ms (P95) | 格式转换耗时 |
| **策略评估延迟** | ≤1ms (P95，≤3 节点策略) | 路由决策耗时 |
| **Token 计量延迟** | ≤1ms (P95) | 费用计算耗时 |
| **吞吐量 (v1.0)** | ≥5,000 QPS (单实例) | 基准请求特征下的非流式+流式混合 QPS |
| **吞吐量 (v2.0)** | ≥10,000 QPS (单实例) | 优化后目标，需 JVM 调优 + 异步化改造 |
| **并发流式连接** | ≥1,000 | 同时活跃的 SSE 连接，每连接 10 tokens/s |
| **可用性** | ≥99.9% (月度 SLA) | 外部探针每 30 秒健康检查 |
| **策略热加载** | 0 秒 | 不影响进行中请求 |

**测试硬件配置**（v1.0 性能目标基准）:
- CPU: 8 核（建议 Intel Xeon 或 AMD EPYC）
- 内存: 16GB（JVM 堆 8GB）
- 网络: 10Gbps 内网
- 存储: SSD（日志存储）

### 6.2 容量规划

| 资源 | 单实例 | 集群 (3 节点) | 集群 (10 节点) |
|------|--------|--------------|---------------|
| QPS | 10,000 | ~28,000 | ~85,000 |
| 并发连接 | 1,000 | ~2,800 | ~8,500 |
| 日志存储/天 | 10GB | 30GB | 100GB |
| 数据库连接 | 100 | 300 | 1,000 |

**扩容假设**:
- 网关实例无状态，水平扩展效率接近线性 (90%+ 效率)
- Redis 为单实例瓶颈点（限流原子操作依赖 Redis），集群 QPS 受 Redis 吞吐量限制
- 数据库连接池为共享资源，10 节点集群建议使用数据库连接代理（如 ProxySQL）
- 容量数字为理论上限，实际需在目标硬件上通过基准测试验证（T276）

### 9.9 版本号语义

遵循 Semantic Versioning:

- **主版本号** (v1.x → v2.x): 破坏性变更，需迁移脚本
- **次版本号** (v1.1 → v1.2): 向后兼容的功能增强
- **修订号** (v1.2.1 → v1.2.2): Bug 修复

**版本号格式**:

| 版本类型 | 版本格式 | 示例 |
|---------|---------|------|
| 标准版 | `v{major}.{minor}.{patch}` | `v1.0.0` |

### 9.10 API 破坏性变更迁移策略

当 API 发生破坏性变更时（如端点路径变更、请求/响应格式变更），采用**双版本共存过渡期**策略：

| 阶段 | 时长 | 行为 |
|------|------|------|
| **并行期** | 6 个月 | 新旧版本同时可用，客户端可自由选择 |
| **废弃期** | 3 个月 | 旧版本标记 deprecated，返回 Warning Header |
| **下线期** | - | 旧版本返回 410 Gone，携带迁移指引 |

**迁移保障**:
- ✅ 新版本发布时自动提供向后兼容层
- ✅ 旧版本请求自动添加 `Deprecation: true` 响应头
- ✅ 管理控制台显示 API 版本健康度仪表盘
- ✅ 提供自动化迁移工具（如 API 签名变更检测、客户端代码生成）
