## 2. 层次定义

### 2.1 分层定义

本工程按 COLA 架构框架分层。各层解决不同类型的问题：

| 层 | 解决什么问题 | 核心职责 |
|---|-------------|---------|
| **Adapter（适配层）** | 隔离**外部**变化 | 接入多端（Web/CLI/SDK），协议适配，数据格式转换 |
| **Application（应用层）** | 用例编排与跨域协调 | 编排用例流程，组合领域服务，管理事务边界 |
| **Domain（领域层）** | 业务规则与领域模型 | 封装业务规则，定义领域实体、领域服务、Gateway 接口 |
| **Infrastructure（基础设施层）** | 隔离**内部**变化 | 持久化实现，第三方 API 调用，技术细节 |
| **Common（公共组件）** | 跨层共享 | 基础异常、常量、通用工具 |

**层次关系**：

```
adapter ──调用──► application ──调用──► domain ──依赖接口──► infrastructure
                                                        (Gateway 实现)
```

**禁止事项**：

| 层 | 禁止事项 |
|---|---------|
| **adapter** | 直接调用 infrastructure |
| **application** | 包含业务逻辑 |
| **domain** | 直接访问外部资源 |
| **infrastructure** | 包含业务逻辑 |

### 2.2 分包原则

```
按业务域分包（domain） > 按技术类型分包
按用例分包（application/adapter） > 按实体分包
```

## 3. 核心场景

### 3.1 代理转发请求

**调用链**：

```
请求 → OpenAIController
    → ProxyService.proxy()
        → AuthService.authenticate()           // 认证用户
        → TokenLimitService.check()            // 检查限额
        → RoutingDomainService.select()        // 选择供应商
        → ProxyDomainService.forward()         // 代理转发
            → ProxyGateway.forward()            // 接口
                → OpenAIProxyGateway          // 实现
```

**层次归属**：

| 组件 | 层次 | 说明 |
|------|------|------|
| OpenAIController | adapter | 请求入口 |
| ProxyService | application | 用例编排 |
| AuthService | domain/security | 认证 |
| TokenLimitService | domain/quota | 限流检查 |
| RoutingDomainService | domain/router | 路由选择 |
| ProxyDomainService | domain/proxy | 转发编排 |
| ProxyGateway | domain/proxy | 接口 |
| OpenAIProxyGateway | infrastructure | 实现 |

### 3.3 错误处理策略

基于信息架构的错误类型定义，各业务场景的错误处理策略如下：

| 场景 | 错误类型 | 处理策略 | HTTP 状态 |
|------|---------|---------|----------|
| **认证** | AUTH_001 API Key 无效 | 拒绝请求 | 401 |
| **认证** | AUTH_002 API Key 过期 | 拒绝请求 | 401 |
| **授权** | AUTH_003 IP 被拒绝 | 拒绝请求 | 403 |
| **限额** | QUOTA_001 Token 超限 | 拒绝/降级/切换 | 402 |
| **限流** | QUOTA_002 请求超限 | 拒绝请求 | 429 |
| **路由** | ROUTER_001 无可用 Provider | 故障转移 → 无 Provider 时返回 503 | 503 |
| **路由** | ROUTER_002 路由策略失败 | 返回错误 | 500 |
| **代理** | PROVIDER_429 Rate Limit | 等待后重试，或切换 Provider | 429 |
| **代理** | PROVIDER_401 Unauthorized | 切换备用 Key | 401 |
| **代理** | PROVIDER_503 Unavailable | 故障转移，切换 Provider | 503 |
| **代理** | PROVIDER_TIMEOUT | 重试（按配置次数） | 504 |
| **代理** | PROVIDER_BAD_REQUEST | 不重试，直接返回 | 400 |
| **代理** | PROVIDER_500 | 重试/降级 | 502 |

**错误处理流程**：

```
ProxyService.proxy()
    │
    ├──► 认证失败 → AuthException → 401
    │
    ├──► 限流触发 → RateLimitException → 429
    │
    ├──► Token 超限 → TokenLimitException → 402
    │
    ├──► 路由失败 → RoutingException
    │        ├──► 有备用 Provider → 切换重试
    │        └──► 无备用 Provider → 503
    │
    └──► Provider 调用失败 → ProviderException
             ├──► 超时 → 重试（按配置次数）
             ├──► 限流 → 等待后重试
             └──► 其他 → 降级/返回 502
```

## 4. 应用服务

### 4.1 服务清单

根据 7 个业务域（router/proxy/supply/security/quota/audit/alert），应用层服务映射如下：

| 业务域 | 应用服务 | 类 | 说明 |
|-------|---------|-----|------|
| **router** | 路由服务 | RoutingService / RoutingServiceImpl | 路由选择 |
| **proxy** | 代理服务 | ProxyService / ProxyServiceImpl | 代理转发 |
| **supply** | 模型服务 | ModelService / ModelServiceImpl | 模型 CRUD |
| **supply** | 提供商服务 | ProviderService / ProviderServiceImpl | 提供商 CRUD |
| **security** | 认证服务 | AuthService / AuthServiceImpl | 用户登录、认证 |
| **security** | API Key 服务 | ApiKeyService / ApiKeyServiceImpl | API Key 生命周期管理 |
| **security** | 用户服务 | UserService / UserServiceImpl | 用户管理 |
| **quota** | Token 限额服务 | TokenLimitService / TokenLimitServiceImpl | 限额管理 |
| **audit** | 审计服务 | AuditService / AuditServiceImpl | 审计日志、调用记录 |
| **alert** | 告警服务 | AlertService / AlertServiceImpl | 告警规则、通知管理 |

**与业务域对齐说明**：

- router 域 → RoutingService（路由选择）
- proxy 域 → ProxyService（代理转发）
- supply 域 → ModelService + ProviderService（模型供给管理）
- security 域 → AuthService + ApiKeyService + UserService（安全控制）
- quota 域 → TokenLimitService（限额配额）
- audit 域 → AuditService（审计合规）
- alert 域 → AlertService（告警管理）

### 4.2 服务详情

#### ProxyService / ProxyServiceImpl

**职责**：代理转发请求到 LLM Provider，编排认证、限流、路由流程

**接口定义**：

```java
public interface ProxyService {
    ProxyResponse proxy(ProxyRequest request);
    void proxyStream(ProxyRequest request, Consumer<String> onChunk);

    record ProxyRequest(
            String model,
            List<Message> messages,
            RouteGroup.RoutingStrategy strategy
    ) {}

    record ProxyResponse(String model, String content) {}
}
```

## 5. 各层分包详解 / Package Structure Details

### 9.1 adapter/ — 适配器层（接入层）

**定位**：隔离上层多端和调用方协议差异

**分包原则**：按协议/用例分包，所有 API 集中在 api/ 子包下

```
adapter/
└── api/                              # 所有 API（不再按业务分包）
    ├── OpenAIController.java          # OpenAI 兼容端点（/v1/chat/completions）
    ├── AnthropicController.java       # Anthropic 兼容端点（/v1/messages）
    ├── UserController.java            # 用户管理（/api/v1/users）
    ├── ModelController.java           # 模型管理（/api/v1/models）
    ├── ProviderController.java        # 提供商管理（/api/v1/providers）
    ├── ApiKeyController.java          # 凭据管理（/api/v1/apikeys）
    ├── TokenLimitController.java     # 限额管理（/api/v1/quotas）
    ├── AuditController.java           # 审计日志（/api/v1/audits）
    └── AlertController.java           # 告警管理（/api/v1/alerts）
```

**职责**：
- 接收 HTTP 请求，解析请求参数
- 协议转换（OpenAI ↔ Anthropic 格式互转）
- 认证：使用 `@SaCheckLogin` 等 Sa-Token 注解
- 调用 application 层服务
- 返回统一格式响应

**认证机制**（Sa-Token）：
- `@SaCheckLogin` — 验证请求是否已登录
- `@SaCheckApiKey` — 自定义注解，验证 API Key
- 自定义 `SaTokenDao` 实现 API Key 到用户的映射

**限流机制**：
- 使用 `@RateLimiter` 注解或 `RedisRateLimiter`
- 在 Controller 方法上声明限流规则

**禁止**：
- 直接调用 infrastructure 层
- 包含业务逻辑
- 访问数据库

### 9.6 层间依赖规则总结

```
┌─────────────────────────────────────────────────────────────────┐
│                     依赖方向（从外到内）                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   adapter ──依赖──► application ──依赖──► domain ──依赖──► gateway│
│                                                      │          │
│                                                      │ 接口      │
│                                                      ▼          │
│                                             infrastructure       │
│                                             (Gateway 实现)       │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

禁止的依赖：
❌ adapter → infrastructure
❌ application → adapter
❌ domain → infrastructure
❌ domain → application
```
