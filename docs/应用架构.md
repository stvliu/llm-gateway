## 2. 层次定义

### 2.1 分层定义

| 层 | 解决什么问题 | 核心职责 |
|---|-------------|---------|
| **Adapter（适配层）** | 隔离**外部**变化 | 接入多端（Web/CLI/SDK），协议适配，数据格式转换 |
| **Application（应用层）** | 用例编排与跨域协调 | 编排用例流程，组合领域服务，管理事务边界 |
| **Domain（领域层）** | 业务规则与领域模型 | 封装业务规则，定义领域实体、领域服务、Gateway 接口 |
| **Infrastructure（基础设施层）** | 隔离**内部**变化 | 持久化实现，第三方 API 调用，技术细节 |
| **Common（公共组件）** | 跨层共享 | 基础异常、常量、通用工具 |

**层次关系**：

```
adapter ──调用──► application ──调用──► domain
                                            │
                                      定义接口│
                                            ▼
                                        ┌─────────┐
                                        │ gateway  │ ← 接口在 domain
                                        └─────────┘
                                            ▲
                                      实现接口│
                                            │
                               infrastructure ───────────
```

**禁止事项**：

| 层 | 禁止事项 |
|---|---------|
| **adapter** | 直接调用 infrastructure |
| **application** | 包含业务逻辑 |
| **domain** | 直接访问外部资源 |
| **infrastructure** | 包含业务逻辑 |

### 2.2 分包原则

```
按业务域分包（domain） 
按业务域分包（application/adapter）
```

## 3. 关键场景

### 3.0 核心请求处理总览
```
外部请求
    ↓
[Adapter] OpenAIController （接收，解析）
    ↓
[Application] ProxyService （用例编排入口）
    ↓
[Domain] 1. Access: 认证授权 → 2. Quota: 限额检查 → 3. Proxy: 路由选择 → 4. Proxy: 代理转发
    ↓          ↓                    ↓                   ↓                   ↓
[Infra]   ApiKeyGateway实现     限流实现            路由决策器        ProxyGateway实现
    ↓
    ↓
[Domain] 5. Quota: 计量记录 → 6. Audit: 调用日志 → 7. Alert: 异常检测（可选）
    ↓          ↓                    ↓                   ↓
[Infra]   用量统计实现         调用日志实现        告警触发器
    ↓
外部响应
```

**完整请求处理流程**：

```
请求 → OpenAIController
    → ProxyService.proxy()
        → 1. AuthService.authenticate()           // 认证用户
        → 2. TokenLimitService.check()            // 检查限额
        → 3. SemanticCacheService.findSimilar()   // 语义缓存检查（可选）
        → 4. RoutingDomainService.select()        // 选择渠道
        → 5. DegradationDomainService.check()     // 降级检查（可选）
        → 6. ProxyDomainService.forward()         // 代理转发
            → ProxyGateway.forward()              // 接口
                → OpenAIProxyGateway              // 实现
        → 7. TokenLimitService.recordUsage()      // 记录用量
        → 8. AuditService.log()                   // 记录调用日志
        → 9. AlertService.checkAndTrigger()       // 异常告警（可选）
    → 响应
```

### 3.1 LLM 代理转发

**调用链**：


#### 3.1.1 SSE 流式处理架构

**场景说明**：对于 `stream: true` 的请求，网关需要支持 SSE（Server-Sent Events）流式响应，实现实时内容推送。

**SSE 流式处理流程**：

```
客户端请求（stream: true）
    ↓
[Adapter] OpenAIController.proxyStream()
    ↓
[Application] ProxyService.proxyStream()
    ↓
[Domain] 前置检查（认证、限额、路由选择）
    ↓
[Infrastructure] OpenAIProxyGateway.stream() ──建立上游连接──► Provider SSE
    ↓
    │   ┌─────────────────────────────────────────────────┐
    │   │              SSE 事件流                         │
    │   │  data: {"choices":[{"delta":{"content":"..."}}]} │
    │   │  data: {"choices":[{"delta":{"content":"..."}}]} │
    │   │  data: [DONE]                                   │
    │   └─────────────────────────────────────────────────┘
    ↓
[Adapter] 推送给客户端
    ↓
[Domain] 流式结束后记录用量、日志
```

**SSE 核心接口设计**：

```
┌─────────────────────────────────────────────────────────────────┐
│                      SSE 流式处理接口                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  [Adapter 层]                                                    │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  StreamController                                          │   │
│  │  - 接收 HTTP 请求                                          │   │
│  │  - 创建 SSE 连接                                           │   │
│  │  - 返回流式响应                                            │   │
│  └──────────────────────────────────────────────────────────┘   │
│                              │                                   │
│                              ▼                                   │
│  [Application 层]                                                │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  ProxyService.proxyStream(request, callback)             │   │
│  │  - 编排认证、限额、路由                                    │   │
│  │  - 调用 Infrastructure 层建立上游连接                      │   │
│  │  - 通过回调推送数据                                        │   │
│  └──────────────────────────────────────────────────────────┘   │
│                              │                                   │
│                              ▼                                   │
│  [Domain 层]                                                     │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  SseCallback 接口                                          │   │
│  │  - onChunk(chunk): 收到数据块时调用                        │   │
│  │  - onComplete(usage): 流式结束时调用                       │   │
│  │  - onError(error): 发生错误时调用                          │   │
│  └──────────────────────────────────────────────────────────┘   │
│                              │                                   │
│                              ▼                                   │
│  [Infrastructure 层]                                             │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  ProxyGateway.stream(request, callback)                   │   │
│  │  - 建立与上游 Provider 的 SSE 连接                         │   │
│  │  - 解析 SSE 事件                                           │   │
│  │  - 通过回调传递给上层                                      │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

**接口定义**：

```
// Domain 层：回调接口
interface SseCallback {
    void onChunk(String chunk);           // 收到数据块
    void onComplete(UsageDTO usage);      // 流式结束
    void onError(Throwable error);        // 发生错误
}

// Domain 层：流式请求
record StreamRequest(
    String model,
    List<Message> messages,
    RouteGroup.RoutingStrategy strategy
) {}

// Infrastructure 层：网关接口
interface ProxyGateway {
    ProxyResponse forward(ProxyRequest request, Channel channel);
    void stream(StreamRequest request, Channel channel, SseCallback callback);
}
```

**SSE 错误处理**：

| 错误类型 | 处理策略 | 响应格式 |
|---------|---------|---------|
| 上游连接失败 | 立即返回错误事件 | `event: error\ndata: {"error":"connection_failed"}` |
| 上游超时 | 发送超时事件后关闭 | `event: error\ndata: {"error":"timeout"}` |
| 限流触发 | 发送限流事件 | `event: error\ndata: {"error":"rate_limit","retry_after":30}` |
| Token 限额耗尽 | 发送配额耗尽事件 | `event: error\ndata: {"error":"quota_exceeded"}` |

**SSE 超时配置**：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `sse.connection.timeout` | 30000ms | 上游连接超时 |
| `sse.read.timeout` | 300000ms | 流式读取超时（5分钟） |
| `sse.heartbeat.interval` | 15000ms | 心跳间隔（防止连接断开） |

**SSE 流量控制**：

```
                    ┌─────────────────────────────┐
                    │       流量控制策略          │
                    └─────────────────────────────┘
                                │
        ┌───────────────────────┼───────────────────────┐
        │                       │                       │
        ▼                       ▼                       ▼
┌───────────────┐     ┌───────────────┐     ┌───────────────┐
│  背压控制      │     │  并发限制      │     │  缓冲区管理    │
│  (Backpressure)│     │  (Concurrency) │     │  (Buffer)     │
└───────────────┘     └───────────────┘     └───────────────┘
        │                       │                       │
        ▼                       ▼                       ▼
- 消费者慢时暂停     - 单 Channel 限制      - 输出缓冲区大小
- 动态调整拉取速率   - 全局 SSE 连接数限制   - 背压时丢弃旧数据
```

**SSE 用量统计**：

```
流式结束后统计 Token 用量：
┌─────────────────────────────────────────────────────────────┐
```

### 3.2 认证与鉴权

**场景说明**：用户通过 API Key 访问 LLM-Gateway，所有请求必须经过认证和鉴权。

**认证流程**：

```
请求 → OpenAIController
    → 认证拦截器（验证登录状态）
    → ApiKeyAuthenticationFilter
        → 从 Header/参数提取 API Key（sk-xxx）
        → ApiKeyGateway.findByKey(apiKey)
        → 验证 Key 有效性（未删除、未过期、状态正常）
        → 加载关联的 User 和 TokenLimit
        → 写入安全上下文
    → 放行到业务处理
```

**鉴权流程**（可选扩展）：

```
AuthenticationDomainService.authenticate()
    → 验证 API Key 有效性
    → 加载用户权限
    → AuthorizationDomainService.authorize(user, resource)
        → 检查 IP 白名单
        → 检查模型访问权限
        → 检查额度是否充足
```

**层次归属**：

| 组件 | 层次 | 说明 |
|------|------|------|
| OpenAIController | adapter | 请求入口，触发认证 |
| 认证拦截器 | adapter | 验证登录状态 |
| ApiKeyAuthenticationFilter | adapter | API Key 认证 |
| ApiKeyGateway | domain/security | 接口 |
| ApiKeyGateway实现 | infrastructure | 持久化实现 |
| AuthenticationDomainService | domain/security | 认证领域服务 |
| AuthorizationDomainService | domain/security | 鉴权领域服务 |

**认证方式**：

| 方式 | 使用场景 | Header 格式 |
|------|---------|-------------|
| **API Key** | AI 接口调用 | `Authorization: Bearer sk-xxx` |
| **Bearer Token** | 管控接口调用 | `Authorization: Bearer sk-xxx` |
| **Session Cookie** | Web 控制台 | `Cookie: session=xxx` |

**错误处理**：

| 错误码 | HTTP 状态 | 触发条件 |
|--------|----------|---------|
| AUTH_001 | 401 | API Key 无效 |
| AUTH_002 | 401 | API Key 已过期 |
| AUTH_003 | 403 | IP 不在白名单 |
| AUTH_004 | 403 | 用户无访问权限 |

### 3.3 限流与配额

**场景说明**：通过两级限流（本地限流 + 分布式限流）实现 Token 限额控制和请求限流。

**限流检查流程**：

```
请求 → ProxyService.proxy()
    → TokenLimitService.check()
        → 本地限流检查（JVM 内存）
            → 超限 → 返回 429 + Retry-After
        → 分布式限流检查（共享存储）
            → 超限 → 返回 429 + X-RateLimit-*
        → 记录 UsageRecord
    → 通过后继续路由
```

**Token 限额检查**：

```
TokenLimitService.checkLimit(userId, modelId)
    → TokenLimitGateway.findByUser(userId)
        → 检查是否超限（total_usage < limit）
    → 超限 → 抛出 QuotaExceededException
        → 返回 402 PAYMENT_REQUIRED
        → 错误码 QUOTA_001
```

**限流策略**：

| 维度 | 标准版 | 企业版 |
|------|--------|--------|
| **RPM** | 60/min | 600/min |
| **TPM** | 100,000/min | 1,000,000/min |
| **并发** | 10 | 100 |
| 本地限流 | 内存令牌桶 | 内存令牌桶 |
| 分布式限流 | 共享存储计数 | 集群共享存储 |

**重试策略**：

| 场景 | 策略 |
|------|------|
| **429 Rate Limit** | 指数退避：1s → 2s → 4s → 8s → 16s → 32s，最大 60s |
| **503 Service Unavailable** | 等待 5s 后重试，最多 3 次 |
| **504 Gateway Timeout** | 立即重试 1 次，失败后切换 Provider |

**层次归属**：

| 组件 | 层次 | 说明 |
|------|------|------|
| TokenLimitService | application | 限额服务编排 |
| RateLimitDomainService | domain/quota | 限流规则处理 |
| TokenLimitGateway | domain/quota | 接口 |
| TokenLimitGateway实现 | infrastructure | 分布式限流实现 |
| 本地限流器 | infrastructure | JVM 本地限流 |

**Entity 关联设计原则**:

Domain Entity 应保持纯粹，关联关系通过 ID 引用而非对象引用：

| 原则 | 说明 |
|------|------|
| **统一使用 ID 引用** | Entity 只持有关联对象的 ID，不持有对象引用 |
| **按需加载关联数据** | 通过 Domain Service 或 Gateway 获取关联对象 |
| **避免隐式依赖** | 防止 N+1 查询问题和测试复杂度增加 |

**推荐模式**:

```java
// ✅ 推荐：使用 ID 引用
@Data
public class Model extends BaseEntity {
    private Long providerId;        // ID 引用
    private String displayName;
    // ...
}

// ❌ 不推荐：使用对象引用
@Data
public class Model extends BaseEntity {
    private Provider provider;      // 避免：对象引用带来隐式依赖
    private String displayName;
    // ...
}
```

**关联数据获取方式**:

```java
// 通过 Domain Service 获取关联对象
public class ModelDomainService {
    public Provider getProvider(Model model) {
        return providerGateway.findById(model.getProviderId());
    }
}
```

## 5. 扩展点说明

### 5.1 新增 Provider 扩展

新增一个 AI 模型提供商需要实现以下组件：

```
扩展步骤：
1. [Domain] 定义协议转换器接口（如需要新协议）
   └── domain/proxy/gateway/XxxProtocolConverter.java

2. [Infrastructure] 实现 ProxyGateway
   └── infrastructure/llm/XxxProxyGateway.java

3. [Infrastructure] 实现协议转换器
   └── infrastructure/protocol/XxxProtocolConverter.java

4. [Infrastructure] 注册到工厂
   └── infrastructure/protocol/ProtocolConverterFactory.java

5. [Config] 配置 Provider 元数据
   └── database: INSERT INTO providers (code, name, api_type, ...)
```

**扩展接口定义**：

```
// Domain 层：协议转换器接口（定义在 gateway 包）
interface ProtocolConverter {
    String convertRequest(ProxyRequest request);    // 请求格式转换
    ProxyResponse convertResponse(String response); // 响应格式转换
}

// Domain 层：网关接口
interface ProxyGateway {
    ProxyResponse forward(ProxyRequest request, Channel channel);
    void stream(StreamRequest request, Channel channel, SseCallback callback);
}

// Infrastructure 层：转换器工厂（实现细节）
interface ProtocolConverterFactory {
    ProtocolConverter getConverter(String apiType);
    void register(String apiType, ProtocolConverter converter);
}
```

**扩展实现要点**：

| 组件 | 职责 | 位置 |
|------|------|------|
| ProtocolConverter | 格式转换（OpenAI ↔ Provider 原生格式） | domain（接口）+ infrastructure（实现） |
| ProxyGateway | 建立连接、发送请求、接收响应 | infrastructure |
| ProtocolConverterFactory | 管理转换器注册与获取 | infrastructure |

### 5.2 新增认证方式扩展

新增认证方式（如 JWT、OAuth2.0）需要实现：

```
扩展步骤：
1. [Adapter] 实现认证过滤器
   └── adapter/filter/XxxAuthenticationFilter.java

2. [Domain] 实现认证领域服务（如需）
   └── domain/security/service/XxxAuthenticationService.java

3. [Infrastructure] 实现 Gateway（如需）
   └── infrastructure/gateway/access/XxxGateway.java

4. [Infrastructure] 注册过滤器
   └── infrastructure/config/SecurityConfig.java
```

**扩展接口定义**：

```
// Domain 层：认证服务接口
interface AuthenticationService {
    User authenticate(Credentials credentials);
    boolean validate(Credentials credentials);
}

// Domain 层：凭证接口
interface Credentials {
    String getType();  // api_key / jwt / oauth
    String getValue();
}

// Adapter 层：过滤器接口
interface AuthenticationFilter {
    boolean doFilter(Request request, Response response);
    int getOrder();  // 过滤器顺序
}
```

**扩展实现要点**：

| 组件 | 职责 | 位置 |
|------|------|------|
| AuthenticationFilter | 拦截请求、提取凭证、验证身份 | adapter |
| AuthenticationService | 认证逻辑、用户加载 | domain |
| Credentials | 凭证抽象 | domain |

### 5.3 新增告警渠道扩展

## 7. 安全设计详解

### 7.1 API Key 加密存储

**加密方案**：

```
┌─────────────────────────────────────────────────────────────┐
│                   API Key 加密存储                           │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  存储格式：IV:密文:Tag（Base64 编码）                        │
│                                                              │
│  【标准版】加密算法：AES-256-GCM                             │
│  ├── 密钥长度：256 位                                        │
│  ├── IV 长度：12 字节（每次随机生成）                        │
│  ├── Tag 长度：128 位                                        │
│  └── 编码：UTF-8 + Base64                                    │
│                                                              │
│  【企业版专属】加密算法：SM4-GCM（国密算法）                  │
│  ├── 密钥长度：128 位                                        │
│  ├── IV 长度：12 字节（每次随机生成）                        │
│  ├── Tag 长度：128 位                                        │
│  └── 符合 GB/T 32907-2016 国家标准                           │
│                                                              │
│  加密流程：                                                  │
│  明文 API Key → 生成随机 IV → AES-GCM/SM4-GCM 加密 → 拼接存储│
│                                                              │
│  解密流程：                                                  │
│  存储格式 → 解析 IV/密文/Tag → AES-GCM/SM4-GCM 解密 → 明文   │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

**密钥管理**：

| 要点 | 说明 |
|------|------|
| 密钥来源 | 外部密钥管理服务（Vault、AWS KMS） |
| 获取时机 | 应用启动时获取，内存中缓存 |
| 轮换周期 | 90 天定期轮换 |
| 访问控制 | 限制密钥访问权限，审计访问记录 |

### 7.2 审计日志防篡改

**链式哈希设计**：

```
┌─────────────────────────────────────────────────────────────┐
│                   链式哈希结构                               │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  记录 N-1          记录 N            记录 N+1               │
│  ┌─────────┐      ┌─────────┐       ┌─────────┐            │
│  │ content │      │ content │       │ content │            │
│  │ hash_N  │ ───► │ prev=N  │ ───►  │ prev=N+1│            │
│  └─────────┘      │ hash_N+1│       │ hash_N+2│            │
│                   └─────────┘       └─────────┘            │
│                                                              │
│  哈希计算：hash_N = SHA256(hash_{N-1} + content_N + ts_N)   │
│                                                              │
│  完整性验证：                                                │
│  遍历所有记录，验证每条记录的 prev_hash 是否等于前一条的 hash │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

**数据模型**：

```
AuditLog 实体：
├── id: Long                    # 自增主键
├── previous_hash: String       # 前一条记录的哈希
├── current_hash: String        # 当前记录的哈希（计算后填充）
├── content: String             # 审计内容（JSON）
├── created_at: Instant         # 创建时间
└── created_by: Long            # 操作人
```

**WORM 存储策略**：

| 层面 | 措施 |
|------|------|
| 数据库 | 表权限设为 INSERT ONLY，禁止 UPDATE/DELETE |
| 应用 | 审计日志服务只提供写入和查询，不提供修改 |
| 备份 | 每日增量备份，永久保留 |
| 验证 | 定期运行完整性校验，检测篡改

### 8.2 日志格式规范

**结构化日志格式**（JSON）：

```
日志字段定义：
┌─────────────────────────────────────────────────────────────┐
│                    日志结构化字段                            │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  基础字段：                                                  │
│  ├── timestamp: ISO 8601 时间戳                              │
│  ├── level: 日志级别（ERROR/WARN/INFO/DEBUG）               │
│  ├── logger: 日志记录器名称                                  │
│  └── message: 日志消息                                       │
│                                                              │
│  追踪字段：                                                  │
│  ├── trace_id: 全链路追踪 ID                                 │
│  └── span_id: 当前 Span ID                                   │
│                                                              │
│  业务字段：                                                  │
│  ├── user_id: 用户 ID                                        │
│  ├── api_key_id: API Key ID                                  │
│  ├── request.method: HTTP 方法                               │
│  ├── request.path: 请求路径                                  │
│  ├── request.model: 请求模型                                 │
│  ├── response.status: 响应状态码                             │
│  ├── response.duration_ms: 响应时间（毫秒）                  │
│  ├── usage.input_tokens: 输入 Token 数                       │
│  └── usage.output_tokens: 输出 Token 数                      │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

```json

  "span_id": "span_def456",
  "user_id": 1001,
  "api_key_id": 2001,
  "request": {
    "method": "POST",
    "path": "/v1/chat/completions",

  },
  "response": {
    "status": 200,
    "duration_ms": 1523
  },
  "usage": {
    "input_tokens": 100,
    "output_tokens": 200
  }
}
```

**日志级别使用规范**：

| 级别 | 使用场景 |
|------|---------|
| ERROR | 请求失败、系统异常、Provider 错误 |
| WARN | 限流触发、配额警告、降级触发 |
| INFO | 请求开始/结束、关键业务事件 |
| DEBUG | 详细调试信息（生产环境关闭） |

**日志输出要求**：

| 要求 | 说明 |
|------|------|
| 格式 | JSON 结构化格式 |
| 编码 | UTF-8 |
| 输出位置 | 文件（生产）/ 控制台（开发） |
| 轮转 | 按日轮转，保留 30 天 |
| 追踪信息 | 必须包含 trace_id，支持全链路追踪 |
