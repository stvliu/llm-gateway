## 2. 层次定义

### 2.1 分层定义

| 层 | 解决什么问题 | 核心职责 |
|---|-------------|---------|
| **Adapter（适配层）** | 隔离**外部**变化 | 接入多端（Web/CLI/SDK），协议适配，数据格式转换 |
| **Application（应用层）** | 用例编排与跨域协调 | 编排用例流程，组合领域服务，管理事务边界 |
| **Domain（领域层）** | 业务规则与领域模型 | 封装业务规则，定义领域实体、领域服务、Gateway 接口 |
| **Infrastructure（基础设施层）** | 隔离**内部**变化 | 持久化实现，第三方 API 调用，技术细节 |
| **Common（公共组件）** | 跨层共享 | 基础异常、常量、通用工具 |

**层次关系**：

```
adapter ──调用──► application ──调用──► domain
                                            │
                                      定义接口│
                                            ▼
                                        ┌─────────┐
                                        │ gateway  │ ← 接口在 domain
                                        └─────────┘
                                            ▲
                                      实现接口│
                                            │
                               infrastructure ───────────
```

**禁止事项**：

| 层 | 禁止事项 |
|---|---------|
| **adapter** | 直接调用 infrastructure |
| **application** | 包含业务逻辑 |
| **domain** | 直接访问外部资源 |
| **infrastructure** | 包含业务逻辑 |

### 2.2 分包原则

```
按业务域分包（domain） 
按业务域分包（application/adapter）
```

### 2.3 层间依赖规则

```
┌─────────────────────────────────────────────────────────────────┐
│                        允许的依赖                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   adapter ──调用──► application ──调用──► domain                │
│                                              │                   │
│                                        定义接口│                  │
│                                              ▼                   │
│                                        ┌─────────┐              │
│                                        │ gateway │ ← 接口在 domain│
│                                        └─────────┘              │
│                                              ▲                   │
│                                        实现接口│                  │
│   infrastructure ────────────────────────────────┘              │
│   (Gateway 实现)                                                │
│                                                                  │
├─────────────────────────────────────────────────────────────────┤
│                        禁止的依赖                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   ❌ infrastructure → application（基础设施层不能调用应用层）     │
│   ❌ infrastructure → adapter                                    │

│   ❌ adapter → infrastructure（适配层不能直接访问基础设施层）       │
└─────────────────────────────────────────────────────────────────┘
```

## 3. 关键场景

### 3.1 LLM 代理转发

**调用链**：

```
请求 → OpenAIController
    → ProxyService.proxy()
        → AuthService.authenticate()           // 认证用户
        → TokenLimitService.check()            // 检查限额
        → RoutingDomainService.select()        // 选择供应商
        → ProxyDomainService.forward()         // 代理转发
            → ProxyGateway.forward()            // 接口
                → OpenAIProxyGateway          // 实现
```

**层次归属**：

| 组件 | 层次 | 说明 |
|------|------|------|
| OpenAIController | adapter | 请求入口 |
| ProxyService | application | 用例编排 |
| AuthService | domain/security | 认证 |
| TokenLimitService | domain/quota | 限流检查 |
| RoutingDomainService | domain/router | 路由选择 |
| ProxyDomainService | domain/proxy | 转发编排 |
| ProxyGateway | domain/proxy | 接口 |
| OpenAIProxyGateway | infrastructure | 实现 |

### 3.2 认证与鉴权

**场景说明**：用户通过 API Key 访问 LLM-Gateway，所有请求必须经过认证和鉴权。

**认证流程**：

```
请求 → OpenAIController
    → Sa-Token 拦截（验证登录状态）
    → ApiKeyAuthenticationFilter
        → 从 Header/参数提取 API Key（sk-xxx）
        → ApiKeyGateway.findByKey(apiKey)
        → 验证 Key 有效性（未删除、未过期、状态正常）
        → 加载关联的 User 和 TokenLimit
        → 写入 SecurityContext
    → 放行到业务处理
```

**鉴权流程**（可选扩展）：

```
AuthenticationDomainService.authenticate()
    → 验证 API Key 有效性
    → 加载用户权限
    → AuthorizationDomainService.authorize(user, resource)
        → 检查 IP 白名单
        → 检查模型访问权限
        → 检查额度是否充足
```

**层次归属**：

| 组件 | 层次 | 说明 |
|------|------|------|
| OpenAIController | adapter | 请求入口，触发认证 |
| Sa-Token 拦截器 | adapter | 验证登录状态 |
| ApiKeyAuthenticationFilter | adapter | API Key 认证 |
| ApiKeyGateway | domain/security | 接口 |
| JpaApiKeyGateway | infrastructure | 实现 |
| AuthenticationDomainService | domain/security | 认证领域服务 |
| AuthorizationDomainService | domain/security | 鉴权领域服务 |

**认证方式**：

| 方式 | 使用场景 | Header 格式 |
|------|---------|-------------|
| **API Key** | AI 接口调用 | `Authorization: Bearer sk-xxx` |
| **Bearer Token** | 管控接口调用 | `Authorization: Bearer sk-xxx` |
| **Session Cookie** | Web 控制台 | `Cookie: session=xxx` |

**错误处理**：

| 错误码 | HTTP 状态 | 触发条件 |
|--------|----------|---------|
| AUTH_001 | 401 | API Key 无效 |
| AUTH_002 | 401 | API Key 已过期 |
| AUTH_003 | 403 | IP 不在白名单 |
| AUTH_004 | 403 | 用户无访问权限 |

### 3.3 限流与配额

**场景说明**：通过两级限流（Bucket4j 本地 + Redis 分布式）实现 Token 限额控制和请求限流。

**限流检查流程**：

```
请求 → ProxyService.proxy()
    → TokenLimitService.check()
        → Bucket4j 检查（JVM 本地）
            → 超限 → 返回 429 + Retry-After
        → Redis 检查（分布式计数）
            → 超限 → 返回 429 + X-RateLimit-*
        → 记录 UsageRecord
    → 通过后继续路由
```

**Token 限额检查**：

```
TokenLimitService.checkLimit(userId, modelId)
    → TokenLimitGateway.findByUser(userId)
        → 检查是否超限（total_usage < limit）
    → 超限 → 抛出 QuotaExceededException
        → 返回 402 PAYMENT_REQUIRED
        → 错误码 QUOTA_001
```

**限流策略**：

| 维度 | 标准版 | 企业版 |
|------|--------|--------|
| **RPM** | 60/min | 600/min |
| **TPM** | 100,000/min | 1,000,000/min |
| **并发** | 10 | 100 |
| 本地限流 | Bucket4j | Bucket4j |
| 分布式限流 | Redis | Redis Cluster |

**重试策略**：

| 场景 | 策略 |
|------|------|
| **429 Rate Limit** | 指数退避：1s → 2s → 4s → 8s → 16s → 32s，最大 60s |
| **503 Service Unavailable** | 等待 5s 后重试，最多 3 次 |
| **504 Gateway Timeout** | 立即重试 1 次，失败后切换 Provider |

**层次归属**：

| 组件 | 层次 | 说明 |
|------|------|------|
| TokenLimitService | application | 限额服务编排 |
| RateLimitDomainService | domain/quota | 限流规则处理 |
| TokenLimitGateway | domain/quota | 接口 |
| RedisTokenLimitGateway | infrastructure | Redis 分布式限流实现 |
| Bucket4j | infrastructure | JVM 本地限流 |

## 5. 应用服务

### 5.1 应用服务分类

根据 7 个业务域（router/proxy/supply/security/quota/audit/alert），应用层服务映射如下：

| 业务域 | 应用服务 | 类 | 说明 |
|-------|---------|-----|------|
| **router** | 路由服务 | RoutingService / RoutingServiceImpl | 路由选择 |
| **proxy** | 代理服务 | ProxyService / ProxyServiceImpl | 代理转发 |
| **supply** | 模型服务 | ModelService / ModelServiceImpl | 模型 CRUD |
| **supply** | 提供商服务 | ProviderService / ProviderServiceImpl | 提供商 CRUD |
| **security** | 认证服务 | AuthService / AuthServiceImpl | 用户登录、认证 |
| **security** | API Key 服务 | ApiKeyService / ApiKeyServiceImpl | API Key 生命周期管理 |
| **security** | 用户服务 | UserService / UserServiceImpl | 用户管理 |
| **quota** | Token 限额服务 | TokenLimitService / TokenLimitServiceImpl | 限额管理 |
| **audit** | 审计服务 | AuditService / AuditServiceImpl | 审计日志、调用记录 |
| **alert** | 告警服务 | AlertService / AlertServiceImpl | 告警规则、通知管理 |

### 5.2 服务接口定义

#### ProxyService / ProxyServiceImpl

**职责**：代理转发请求到 LLM Provider，编排认证、限流、路由流程

**接口定义**：

```java
public interface ProxyService {
    ProxyResponse proxy(ProxyRequest request);
    void proxyStream(ProxyRequest request, Consumer<String> onChunk);

    record ProxyRequest(
            String model,
            List<Message> messages,
            RouteGroup.RoutingStrategy strategy
    ) {}

    record ProxyResponse(String model, String content) {}
}
```

## 6. 各层分包详解

### 6.1 Adapter 层

**定位**：隔离上层多端和调用方协议差异

**分包原则**：按协议/用例分包，所有 API 集中在 api/ 子包下

```
adapter/
└── api/                              # 所有 API（不再按业务分包）
    ├── OpenAIController.java          # OpenAI 兼容端点（/v1/chat/completions）
    ├── AnthropicController.java       # Anthropic 兼容端点（/v1/messages）
    ├── UserController.java            # 用户管理（/v1/users）
    ├── ModelController.java           # 模型管理（/v1/models）
    ├── ProviderController.java        # 提供商管理（/v1/providers）
    ├── ApiKeyController.java          # 凭据管理（/v1/api-keys）
    ├── TokenLimitController.java     # 限额管理（/v1/token-limits）
    ├── AuditController.java           # 审计日志（/v1/audit-logs）
    └── AlertController.java           # 告警管理（/v1/alerts）
```

**职责**：
- 接收 HTTP 请求，解析请求参数
- 协议转换（OpenAI ↔ Anthropic 格式互转）
- 认证：使用 `@SaCheckLogin` 等 Sa-Token 注解
- 调用 application 层服务
- 返回统一格式响应

**禁止**：
- 直接调用 infrastructure 层
- 包含业务逻辑
- 访问数据库

---

**定位**：用例编排，跨域协调

**分包原则**：按用例/业务能力分包，服务接口、服务实现、DTO 都在用例包内

```
│   ├── ApiKeyService.java
│   ├── ApiKeyServiceImpl.java
│   └── dto/

│   ├── ModelService.java
│   ├── ModelServiceImpl.java
│   └── dto/
```
