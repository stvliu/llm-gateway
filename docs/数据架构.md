## 概述

本文档定义 LLM-Gateway 的数据架构，包括数据库设计、表结构、索引策略和数据字典。数据架构基于 [需求规格说明书](./spec.md) 和 [信息架构](./信息架构.md) 设计，业务数据按功能域归入对应模块（模块化命名，核心模块 + `-data` JPA 绑定子模块）：

| 业务域 | 核心职责 | 数据模块 | 主要实体/表 |
|--------|---------|---------|------------|
| **iam**（身份与访问） | User/Application/UserApiKey/认证 | gateway-iam/iam-data | `users`、`applications`、`application_channels`、`user_api_keys` |
| **provider**（供给域） | Provider/Channel/Model/Catalog | gateway-provider/provider-data | `providers`、`channels`、`channel_credentials`、`channel_endpoints`、`models`、`model_instances`、`plan_catalogs`、`plan_model_catalogs` |
| **usage**（用量管控） | TokenLimit/配额/用量事件/限流 | gateway-usage/usage-data | `token_limits`、`rate_limit_configs`、`usage_logs` |
| **security**（安全与威胁） | IP 威胁检测 + 数据脱敏 | gateway-security/security-data | `sensitive_data_rules`、`ip_blocklist` |
| **audit**（审计追溯） | 调用日志/审计事件 | gateway-audit/audit-data | `call_logs`、`audit_logs` |
| **alert**（告警通知） | 告警规则/通知 | gateway-alert/alert-data | `alert_rules`、`alert_notifications` |
| **resilience**（韧性） | failover/retry/circuit-breaker | gateway-resilience/resilience-data | `failover_events` |
| **proxy**（模型代理） | ChatDispatch 调度/路由（无独立数据表） | gateway-proxy | 复用上述域数据 |

> 说明：v2.0 草案中的 `proxy`/`model`/`quota` 域命名已随模块化重构调整为 `provider`/`usage` 等；`resilience` 为新增功能域。详细设计章节保留的旧域表设计（如 `route_groups`、`teams`、`semantic_caches` 等）属于设计愿景，实际以 Flyway 迁移脚本为准。

**设计规模基准**：

| 维度 | v1.0 目标 | v2.0 目标 |
|------|----------|----------|
| 用户数 | ~10,000 | ~100,000 |
| Provider 数 | ~100 | ~500 |
| 模型数 | ~1,000 | ~5,000 |
| QPS（单实例） | 10,000 | 10,000 |

## 设计原则

### 核心原则

| 原则 | 说明                                                            |
|------|---------------------------------------------------------------|
| **全实体可审计** | 每张业务表必须包含 `created_by`、`created_at`、`updated_by`、`updated_at` 四个审计字段 |
| **软删除优先** | 核心业务实体使用 `deleted_at` 实现软删除，保留历史数据                            |
| **密钥加密存储** | 所有 API Key、密码等敏感数据使用 AES-256-GCM 加密（`GATEWAY_ENCRYPTION_KEY` 环境变量） |
| **审计链不可篡改** | 审计日志使用 WORM（Write Once Read Many）存储 + 链式哈希（**设计愿景，规划中**） |
| **外键关联使用物理 ID** | 表间关联使用 `*_id` BIGINT 外键                                       |

> **审计字段规范**（架构章程 CLAUDE.md）：所有业务表必须包含 `created_by`、`created_at`、`updated_by`、`updated_at`，其中 `created_by`/`updated_by` 为 BIGINT，外键引用 `users.id`。追加型日志表（`call_logs`、`audit_logs`、`usage_logs`、`failover_events` 等）为系统写入，只需 `created_at`，不强制 `updated_*`。

### DO（Data Object）关联模式

DO 层作为 JPA 实体，负责数据库映射。关联方式按场景选择：

| 场景 | 建议方式 | 说明 |
|------|---------|------|
| **主从关系（强依赖）** | 可用 JPA `@ManyToOne` | 简化查询，但禁用级联删除 |
| **中间表/关联表** | ID 引用 | 避免 JPA 关联带来的复杂性 |
| **弱引用关系** | ID 引用 | 手动 JOIN 查询，更灵活 |

**JPA 关联注意事项**:

- ⚠️ 使用 `FetchType.LAZY` 避免不必要的数据加载
- ⚠️ 在事务外访问 LAZY 属性会抛 `LazyInitializationException`
- ⚠️ JSON 序列化可能导致无限递归，需使用 `@JsonIgnore` 或 DTO 转换
- ❌ 禁止使用级联删除（`CascadeType.REMOVE`）

**推荐示例**:

```java
// 主从关系：可使用 JPA 关联
@Entity
public class ModelDo extends BaseDo {
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "provider_id", foreignKey = @ForeignKey(ConstraintMode.NO_CONSTRAINT))
    private ProviderDo provider;  // 简化查询
}

// 关联表/弱引用：使用 ID 引用
@Entity
public class ProviderApiKeyDo extends BaseDo {
    @Column(name = "provider_id")
    private Long providerId;  // 纯 ID 引用
}
```

### 数据类型规范

| 数据类型 | 使用场景 | 说明 |
|---------|---------|------|
| `BIGINT` | 主键、外键、数量、金额 | 足够大，避免溢出 |
| `VARCHAR(128)` | 名称、标题 | 中等长度文本 |
| `VARCHAR(512)` | URL、描述 | 较长文本 |
| `TEXT` | JSON 配置、大文本 | 无长度限制 |
| `TIMESTAMP WITH TIME ZONE` | 时间戳 | 时区感知，使用 UTC |
| `BOOLEAN` | 布尔标志 | 默认 `false` |
| `DECIMAL(18,6)` | 价格、精确金额 | 避免浮点精度问题 |
| `BYTEA` | 加密数据、向量 | 二进制数据 |

### 字段命名规范

| 字段类型 | 命名格式 | 示例 |
|---------|---------|------|
| 主键 | `id` | `id BIGINT` |
| 外键 | `*_id` | `user_id`, `provider_id` |
| 名称 | `*_name` | `provider_name`, `model_name` |
| 状态 | `status` | `status VARCHAR(32)` |
| 时间戳 | `*_at` | `created_at`, `updated_at`, `expires_at` |
| 软删除 | `deleted_at` | `deleted_at TIMESTAMP` |
| 创建/更新人 | `created_by`, `updated_by` | `created_by BIGINT` |

## 数据库选型

> **现状**：当前实现仅支持 **PostgreSQL 14+（生产）** 与 **H2（开发测试，MODE=PostgreSQL）**，未引入 MySQL 驱动。开发默认 profile 为 `local`，使用 H2 文件库 `jdbc:h2:file:./data/gateway;MODE=PostgreSQL`，零外部依赖；生产使用 PostgreSQL 14+。**MySQL 不支持（规划中）**。

### 主数据库：PostgreSQL 14+（生产） / H2（开发测试）

**选型理由**：

| 特性 | 说明 |
|------|------|
| **JSONB 支持** | 原生 JSON 存储，支持索引，用于 `capabilities`、`config` 等灵活字段 |
| **全文检索** | 内置全文检索，支持日志查询 |
| **向量扩展（pgvector）** | 语义缓存向量存储（**设计愿景，规划中**，当前无 pgvector 依赖） |
| **行级安全** | 多租户隔离（**企业版，设计愿景**） |
| **时区支持** | `TIMESTAMP WITH TIME ZONE` 原生支持 |
| **H2 兼容模式** | 开发测试使用 H2 `MODE=PostgreSQL`，与生产 SQL 兼容 |
| **开源免费** | 无许可证成本 |

> **MySQL 说明**：v2.0 草案曾考虑 MySQL/PostgreSQL 双库，现明确 MySQL 不支持（pom 无 MySQL 驱动），列为「规划中 / Roadmap」。

### 缓存数据库：Redis 7+

**使用场景**：

| 场景 | 数据类型 | TTL | 企业版 | 标准版 |
|------|---------|-----|--------|--------|
| 限流计数器 | String | 按周期 | ✅ | ✅ |
| Token 限额缓存 | Hash | 5 分钟 | ✅ | ✅ |
| 会话缓存 | Hash | 30 分钟 | ✅ | ✅ |
| 分布式锁 | String | 30 秒 | ✅ | ✅ |

### 数据库连接配置

```yaml
# 生产配置

  datasource:
    url: jdbc:postgresql://${DB_HOST:localhost}:${DB_PORT:5432}/${DB_NAME:llm_gateway}
    username: ${DB_USERNAME}

    hikari:
      maximum-pool-size: 100
      minimum-idle: 10
      connection-timeout: 30000
      idle-timeout: 600000
      max-lifetime: 1800000
```

## 核心实体设计

> **重要说明（现状 vs 设计愿景）**：以下 1~6 节为 v2.0 草案的**设计愿景**，其域命名（`proxy`/`model`/`security`/`quota`）与部分表（`route_groups`、`teams`、`licenses`、`semantic_caches`、`alert_templates` 等）已随模块化重构演进或取消。**当前实际表结构与字段以 Flyway 迁移脚本为准**（`gateway-boot/src/main/resources/db/migration/`，V1~V68），实体归属以「概述」章节的功能域划分与「表统计（现状）」为准。本节保留设计愿景供演进参考，并逐条标注「规划中」。

### 1. proxy 域（模型代理）

> **现状**：调度/路由逻辑位于 `gateway-proxy` 模块，无独立数据表；路由分组相关表（`route_groups` 等）为**设计愿景，规划中**。

#### 1.1 route_groups（路由分组）

> 对应信息架构：**RouteGroup** - 一组路由策略配置，支持负载均衡和故障转移（**设计愿景，规划中**）

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `id` | BIGINT | PK, AUTO_INCREMENT | - | 物理主键 |
| `name` | VARCHAR(128) | NOT NULL | - | 路由分组名称 |
| `description` | VARCHAR(512) | NULL | - | 描述 |
| `load_balance_strategy` | VARCHAR(32) | NOT NULL | 'PRIORITY' | 负载均衡策略：PRIORITY/WEIGHT/RANDOM |
| `failover_enabled` | BOOLEAN | NOT NULL | true | 是否启用故障转移 |
| `failover_threshold` | INT | NULL | 5 | 故障转移阈值（连续失败次数） |
| `health_check_interval` | INT | NULL | 60 | 健康检查间隔（秒） |
| `status` | VARCHAR(32) | NOT NULL | 'ACTIVE' | 状态：ACTIVE/DISABLED |
| `created_by` | BIGINT | NOT NULL | - | 创建人 ID |
| `created_at` | TIMESTAMP WITH TIME ZONE | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |
| `updated_by` | BIGINT | NOT NULL | - | 更新人 ID |
| `updated_at` | TIMESTAMP WITH TIME ZONE | NOT NULL | CURRENT_TIMESTAMP | 更新时间 |
| `deleted_at` | TIMESTAMP WITH TIME ZONE | NULL | - | 软删除时间 |

**索引设计**：

```sql
CREATE INDEX ix_route_groups_status ON route_groups(status) WHERE deleted_at IS NULL;
```

**业务约束**：
- `load_balance_strategy` 枚举值：`PRIORITY`（优先级）、`WEIGHT`（权重）、`RANDOM`（随机）
- `failover_threshold` 范围：1-100
- `health_check_interval` 范围：10-3600 秒

#### 1.2 route_group_provider_api_keys（路由关联）

> 对应信息架构：**RouteGroupProviderApiKey** - 路由分组与 ProviderApiKey 的关联，含权重/优先级

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `id` | BIGINT | PK, AUTO_INCREMENT | - | 物理主键 |
| `route_group_id` | BIGINT | NOT NULL, FK | - | 路由分组 ID |
| `provider_api_key_id` | BIGINT | NOT NULL, FK | - | Provider API Key ID |
| `priority` | INT | NOT NULL | 100 | 优先级（数值越大优先级越高） |
| `weight` | INT | NOT NULL | 100 | 权重（权重模式下使用） |
| `enabled` | BOOLEAN | NOT NULL | true | 是否启用 |
| `created_by` | BIGINT | NOT NULL | - | 创建人 ID |
| `created_at` | TIMESTAMP WITH TIME ZONE | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |
| `updated_by` | BIGINT | NOT NULL | - | 更新人 ID |
| `updated_at` | TIMESTAMP WITH TIME ZONE | NOT NULL | CURRENT_TIMESTAMP | 更新时间 |

**索引设计**：

#### 1.3 semantic_caches（语义缓存）

> **规划中 / 设计愿景**：语义缓存为**设计愿景，规划中**（当前无 pgvector 依赖、无对应实现，见事实清单 §8）。规划在企业版（PostgreSQL + pgvector）中提供，标准版不支持。

> 对应信息架构：**SemanticCache** - 相似请求的缓存条目，含向量、响应内容、TTL（规划中）

| `request_hash` | VARCHAR(128) | NOT NULL | - | 请求内容哈希（SHA-256） |

| `similarity_threshold` | DECIMAL(3,2) | NOT NULL | 0.95 | 相似度阈值（0.80-0.99） |

| `expires_at` | TIMESTAMP WITH TIME ZONE | NOT NULL | - | 过期时间 |
| `created_at` | TIMESTAMP WITH TIME ZONE | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |

**索引设计**：


**业务约束**：
- `similarity_threshold` 范围：0.80-0.99
- 默认 TTL：1 小时
- 向量维度：1536（OpenAI text-embedding-3-small）

**现状**：迁移脚本位于 `gateway-boot/src/main/resources/db/migration/`，使用 Flyway 11.0.0，版本 **V1~V68**（含回滚脚本，如 `U25`）。应用启动时自动执行，无需手工建表。

```
├── V35__supply_domain_refactor.sql   # 供给域重构（products→channels 等）
```
