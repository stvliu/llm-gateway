## 概述

本文档定义 LLM-Gateway 的业务概念和信息模型，为后续数据架构设计提供业务语义基础。

### 网关定位

LLM-Gateway 是大模型调用的**反向代理层**，本质职责：

- **代理转发**：将请求准确传递到目标 Provider
- **策略管控**：认证、限流、限额、审计

### 设计原则

| 原则 | 说明 |
|------|------|
| **网关不存储对话** | 不保存对话内容，不维护会话状态，不解析消息语义 |
| **统一入口** | 对外暴露 OpenAI 兼容端点，屏蔽下游 Provider 差异 |
| **策略集中管控** | 认证、限额、审计等策略在网关层统一执行 |

### 划域方法

按**业务能力**划分业务域——每个域回答一个核心问题，拥有独立的实体和生命周期。

|---|---------|--------|---------|------|

| 2 | 模型广场 | **provider** | 有哪些可用？ | 支撑域 |

**域定位说明**：
- **核心域**：网关差异化竞争力所在，缺失则失去存在价值
- **支撑域**：企业级客户刚需，为核心域提供保障机制

## 核心业务链路

```
请求 → access(认证鉴权) → quota(限额限流) → proxy(查provider路由转发) → quota(计量) → audit(记录) → 响应
                                                              ↓
                                                        alert(异常告警)
```

**请求处理流程**：

1. **access**：验证调用者身份，判断是否有权限访问
2. **quota**：检查 Token 额度、RPM/TPM 限制
3. **proxy**：从 provider 域获取可用渠道，执行路由决策、协议转换、请求转发
4. **quota**：记录实际 Token 消耗
5. **audit**：记录调用日志，满足审计需求
6. **alert**：异常情况触发告警通知

## 1. proxy — 模型代理（核心域）

### 责任

回答"**怎么调模型？**"

以标准协议接收请求，选择最优上游渠道，完成调用并返回。

### 子能力

| 子能力 | 说明 |
|--------|------|
| 协议适配 | 接收 OpenAI/Anthropic 格式请求，验证参数 |
| 路由决策 | 根据策略选择目标 Channel/Model |
| 协议转换 | OpenAI ↔ Anthropic 格式互转 |
| 负载均衡 | 多 Channel 按权重分配流量 |
| 故障转移 | 主 Channel 失败自动切换备用 |
| 熔断重试 | 连续失败时熔断，超时/错误自动重试 |
| 流式传输 | SSE 流式响应的分块传输 |

### 实体

| 业务对象 | 英文名 | 说明 |
|------|--------|------|
| RouteGroup | 路由分组 | 一组路由策略配置，支持负载均衡和故障转移 |
| RouteGroupChannel | 路由关联 | 路由分组与 Channel 的关联，含权重/优先级/健康状态 |
| SemanticCache | 语义缓存 | 相似请求的缓存条目，含请求向量、响应内容、TTL |

### 实体关系

```
RouteGroup
├── 聚合 RouteGroupChannel（一个分组包含多个路由关联）
├── 配置负载均衡策略（权重分配）
├── 配置故障转移策略（备用 Channel）
└── 被调用请求引用

RouteGroupChannel
├── 关联 Channel（一个路由关联指向一个渠道）
├── 持有权重配置（用于负载均衡流量分配）
├── 持有优先级配置（高优先级优先使用）
├── 持有健康状态（由健康检查更新）
└── 当 Channel 不可用时自动跳过

SemanticCache
├── 存储请求向量（用于语义相似度匹配）
├── 存储响应内容（命中缓存时直接返回）
├── 持有 TTL 配置（缓存过期时间，默认 1 小时）
├── 持有相似度阈值（默认 0.95，可配置 0.80-0.99）
├── 持有命中率统计（用于评估缓存效果）
├── 支持用户隔离（跨用户缓存不共享）
└── 流式请求可配置跳过缓存
```

## 2. provider — 模型广场

### 责任

回答"**有哪些可用？**"

管理上游模型提供商、渠道、模型及其凭证。

### 子能力

| 子能力 | 说明 |
|--------|------|
| Provider 管理 | 模型提供商（OpenAI、Anthropic 等） |
| Channel 管理 | 渠道实例（一个 Provider 可有多个 Channel） |
| Model 管理 | 模型列表和元数据 |
| ProviderApiKey 管理 | Provider 调用凭证，支持多 Key 轮换 |
| 健康检查 | 定期检测 Channel 可用性 |

### 实体

| 业务对象 | 英文名 | 说明 |
|------|--------|------|
| Provider | 模型提供商 | 模型服务提供方，如 OpenAI、Anthropic |
| Channel | 渠道 | Provider 的具体调用实例，含 BaseURL、API Key、优先级、权重 |
| Model | AI 模型 | 具体的大模型，如 gpt-4o、claude-sonnet-4 |
| ProviderApiKey | Provider 凭证 | 网关调用 Provider 的凭据，管理员配置，支持多 Key 轮换 |

### 实体关系

```
Provider
├── 提供多个 Model（一个 Provider 下有多个可用模型）
├── 配置多个 Channel（一个 Provider 可有多个调用实例）
├── 标识官网、API 文档链接
└── 由管理员创建/启用/禁用

Channel
├── 归属一个 Provider（渠道不能独立存在）
├── 配置 BaseURL（可使用代理地址）
├── 关联多个 ProviderApiKey（支持多 Key 轮换）
├── 持有优先级/权重（用于路由决策）
├── 持有健康状态（由健康检查更新）
└── 可被 RouteGroupChannel 引用

Model
├── 必须归属一个 Provider（模型不能独立存在）
├── 标识模型能力（上下文长度、多模态、Tool Use 支持）
└── 可被路由关联引用

ProviderApiKey
├── 用于访问一个 Channel（凭证绑定到特定渠道）
├── 支持多 Key 轮换（自动选择可用 Key）
├── 加密存储（标准版：AES-256-GCM；企业版：SM4-GCM 国密算法）
├── 状态：ACTIVE / DISABLED / BLOCKED
├── 持有 RPM/TPM 限制（上游 Provider 限制）
├── 持有单 Key RPM 限制（独立限流，可配置）
├── 持有错误计数（用于自动禁用判断）
├── 持有恢复时间（被禁用后的自动恢复时间点，默认 300 秒）
├── 持有禁用原因（INVALID_KEY / RATE_LIMITED / MANUAL）
└── 失效时由健康检查自动禁用
```

### Provider vs Channel

```
Provider（抽象提供商）        Channel（具体渠道实例）
─────────────────           ────────────────────
OpenAI                      渠道1: OpenAI 官方 (key-1, 优先级100)
                            渠道2: OpenAI 代理 (key-2, 优先级50, base_url=代理地址)
Anthropic                   渠道3: Anthropic 官方 (key-3)
```

一个 Provider 可以有多个 Channel，每个 Channel 有独立的 BaseURL、API Key、优先级、权重。这正是**负载均衡和故障转移**的前提。

## 3. access — 访问控制

### 责任

回答"**谁能调？**"

管理调用者身份、凭证、权限，控制谁能以什么条件访问哪些资源。

### 子能力

| 子能力 | 说明 |
|--------|------|
| 身份认证 | 验证请求者身份（Bearer Token） |
| 角色权限 | 管理员/普通用户权限判断（简化双角色模型） |
| 凭证管理 | 网关调用凭证的创建、过期、撤销 |
| IP 过滤 | 黑名单/白名单控制 |
| 敏感数据保护 | PII 检测与脱敏 |

### 实体

| 业务对象 | 英文名 | 说明 |
|------|--------|------|
| User | 系统用户 | 网关使用者，通过 role 字段区分管理员（ADMIN）和普通用户（USER） |
| GatewayApiKey | 网关凭证 | 用户调用网关的凭证，用户自管理 |
| UserOAuth | 用户 OAuth 身份 | 用户的第三方 OAuth 身份标识 |
| IpBlocklist | IP 黑名单 | 系统屏蔽的 IP 地址 |
| SensitiveDataRule | 敏感数据规则 | PII 检测与脱敏规则 |
| License | 许可证 | 企业版授权管理 |

### 实体关系

```
User
├── 持有 role 字段（ADMIN/USER 双角色）
├── 创建多个 GatewayApiKey（用户持有自己的凭证）
├── 操作产生 AuditLog（谁做了什么）
├── 登录触发身份认证
└── 密码 BCrypt 加密存储

GatewayApiKey
├── 被 User 创建（用户生成自己的 Key）
├── 用于请求认证（携带在请求头中）
├── 可设置 IP 白名单（限制访问来源）
├── 可设置模型白名单（限制可用模型）
├── 过期时间可配置
├── 密钥哈希存储（用于验证，不可还原）
├── 创建时返回原始密钥（仅一次，用户需自行保存）
└── 验证方式：请求密钥 → 计算哈希 → 对比存储哈希

IpBlocklist
├── 被系统全局应用（所有请求都检查）
├── 由管理员配置
├── 支持 IP/CIDR 格式
└── 命中时返回 403

UserOAuth
├── 归属一个 User（用户可有多个 OAuth 身份）
├── 存储 OAuth 提供商标识（GitHub/Gitee/飞书/钉钉等）
├── 存储第三方用户标识（OAuth ID）
├── 存储OAuth 令牌（加密存储，用于 API 调用）
└── 支持解绑和重新绑定

License
├── 企业版授权凭证（RSA 签名验证）
├── 包含授权方信息（签发者）
├── 包含被授权方信息（企业名称）
├── 包含有效期（签发时间、过期时间）
├── 包含功能列表（ENTERPRISE、SM_CRYPTO、AUDIT_WORM 等）
├── 包含限制配置（最大用户数、最大节点数）
├── 启动时验证签名和有效期
├── 到期前 30/7/1 天发送告警
└── 过期后降级为标准版功能

SensitiveDataRule
├── 被应用到请求/响应进行脱敏
├── 包含检测规则（正则、关键词）
├── 定义脱敏方式（掩码、哈希、删除）
└── 覆盖 PII 类型：手机号、身份证、邮箱、银行卡等
```

### 角色权限边界

> **简化设计说明**：企业内部网关场景下，两种角色已满足权限控制需求。无需独立的 Role、Permission、UserRole 表，用户表直接包含 `role` 字段。

| 角色 | 权限范围 |
|------|---------|
| **ADMIN** | 全部管理权限：Provider/Model/Channel 管理、用户管理、系统配置、日志查看 |
| **USER** | 个人权限：管理自己的 API Key、调用 API、查看自己的用量和日志 |

## 4. quota — 用量管控

### 责任

回答"**能调多少？**"

计量每次调用的 Token 消耗，按层级限制用量，防止超额使用。

### 子能力

| 子能力 | 说明 |
|--------|------|
| Token 计量 | 分别统计输入/输出 Token |
| Token 限额 | 用户/Key/用户×渠道多级限制 |
| 请求限流 | RPM/TPM 令牌桶控制 |
| 预扣与结算 | 请求前预扣，实际消耗后调整 |
| 超限策略 | 拒绝/降级/切换 |

### 实体

| 业务对象 | 英文名 | 说明 |
|------|--------|------|
| TokenLimit | Token 限额 | 用户/Key/渠道的 Token 用量上限 |
| RateLimitConfig | 限流配置 | RPM/TPM 请求次数限制 |
| UsageRecord | 用量记录 | API 调用消耗的 Token 统计记录（计量视角） |

### 实体关系

```
TokenLimit
├── 约束 User（用户级限额）
├── 约束 GatewayApiKey（Key 级限额）
├── 可选约束 Channel（用户×渠道限额）
├── 超限时触发预设策略（REJECT → 402 / DOWNGRADE / SWITCH）
├── 支持周期重置（天/周/月/总量）
└── 预扣机制：请求前预估用量并冻结

RateLimitConfig
├── 约束 GatewayApiKey（Key 级 RPM/TPM）
├── 超限时返回 429 + Retry-After 头
├── 独立于 TokenLimit（两种不同的限制机制）
└── 支持 RPM（每分钟请求数）和 TPM（每分钟 Token 数）

UsageRecord
├── 归属 GatewayApiKey（记录 Key 的用量）
├── 记录输入 Token 数量
├── 记录输出 Token 数量
├── 用于限额计算和报表生成
├── 支持按时间聚合（天/周/月统计）
├── 由 proxy 域执行调用后产生
└── 职责边界：计量视角，关注 Token 数量消耗
```

### 限额层级

```
TokenLimit 层级关系
├── 用户级: User（单用户总限额）
├── Key 级: GatewayApiKey（单个凭证限额）
└── 用户×渠道级: User × Channel（精细化配额控制，企业版）
```

## 5. audit — 审计追溯

### 责任

回答"**谁做过什么？**"

记录管理操作和 API 调用，满足合规审计需求。

### 子能力

| 子能力 | 说明 |
|--------|------|
| 操作审计 | 记录所有管理操作 |
| 调用记录 | 记录 API 调用元数据 |
| 不可篡改性 | 链式哈希，WORM 存储 |
| 合规报告 | 满足 SOX/GDPR/等保要求 |

### 实体

| 业务对象 | 英文名 | 说明 |
|------|--------|------|
| AuditLog | 审计日志 | 管理操作记录 |
| CallLog | 调用日志 | API 调用元数据记录（审计视角） |

### 实体关系

```
AuditLog
├── 记录操作者（User）
├── 记录操作类型（操作码）
├── 记录操作内容（变更前后数据）
├── 记录操作时间（时间戳）
├── 记录操作结果（成功/失败）
├── 记录客户端 IP（来源追溯）
├── 使用链式哈希（每条包含前一条哈希值）
├── WORM 存储（不可修改/删除）【企业版专属】
└── 满足 SOX/GDPR/等保合规要求

CallLog
├── 归属 GatewayApiKey（记录凭证的调用）
├── 归属 User（记录用户的调用）
├── 记录调用元数据：
│   ├── Channel / Provider / Model
│   ├── 请求时间、响应时间
│   ├── 输入/输出 Token 数量
│   ├── 状态码、错误信息
│   └── Trace ID（追踪标识）
├── 用于用量统计和审计追溯
├── 由 proxy 域执行调用后产生
└── 职责边界：审计视角，关注调用元数据和全链路追溯
```

## 6. alert — 告警通知

### 责任

回答"**出了什么问题？**"

定义异常条件，发现问题后通知责任人。

### 子能力

| 子能力 | 说明 |
|--------|------|
| 规则定义 | 告警触发条件 |
| 模板管理 | 通知格式模板 |
| 通知发送 | 邮件、Webhook 等 |
| 历史记录 | 告警发送历史 |

### 实体

| 业务对象 | 英文名 | 说明 |
|------|--------|------|
| AlertRule | 告警规则 | 告警触发条件定义 |
| AlertTemplate | 告警模板 | 通知格式模板 |
| AlertNotification | 告警通知 | 告警发送记录 |

### 实体关系

```
AlertRule
├── 定义触发条件（阈值、表达式）
├── 关联 AlertTemplate（使用模板格式化通知）
├── 由领域事件触发（调用日志、用量数据、健康检查结果）
├── 触发后产生 AlertNotification
├── 可属于不同业务场景：
│   ├── 安全告警（登录异常、额度超限）
│   ├── 路由告警（Channel 不可用、失败率上升）
│   ├── 供给告警（Key 余额不足、模型下线）
│   └── 系统告警（服务异常、配置变更）
└── 支持静默期配置（避免重复告警）

AlertTemplate
├── 定义通知格式（标题、内容结构）
├── 被多个 AlertRule 引用（模板复用）
├── 支持多种渠道（邮件、Webhook、短信）
├── 包含变量占位符
└── 支持多语言（中文/英文）

AlertNotification
├── 由 AlertRule 触发产生
├── 使用 AlertTemplate 格式化
├── 记录：
│   ├── 触发时间
│   ├── 告警内容
│   ├── 通知渠道
│   ├── 发送状态（成功/失败）
│   └── 确认状态（已确认/未确认）
└── 可被用户确认（Ack）
```

### 告警场景

| 场景 | 触发条件 | 级别 |
|------|---------|------|
| Channel 失败率 | >5% (5 分钟内) | WARN |
| Channel 失败率 | >20% (5 分钟内) | ERROR |
| Token 限额使用率 | >80% | WARN |
| Token 限额耗尽 | ≥100% | ERROR |
| 平均延迟 | P95 > 500ms | WARN |

### 业务一致性约束

| 约束 | 说明 |
|------|------|
| RouteGroup 必须关联至少一个 RouteGroupChannel | 路由分组不能为空 |
| RouteGroupChannel 引用的 Channel 必须存在 | 路由关联必须指向有效渠道 |
| Channel 必须归属于一个 Provider | 渠道不能独立存在 |
| Model 必须归属于一个 Provider | 模型不能独立存在 |
| ProviderApiKey 必须关联一个 Channel | 凭证不能独立存在 |
| TokenLimit 必须指定限制类型和周期 | 限额不能无限制 |
| GatewayApiKey 必须归属于一个 User | 凭证不能是无主之物 |
| AuditLog.previous_hash 必须指向前一条记录 | 形成链式校验 |
| AlertRule 必须关联一个 AlertTemplate | 告警必须有格式化模板 |

### 错误分类

| 错误域 | 核心问题 | 错误类型 |
|--------|---------|---------|
| **proxy** | 代理转发失败 | Provider 调用超时、响应格式错误、连接失败 |
| **provider** | 资源不可用 | 无可用 Channel、所有 Channel 均不可用 |
| **access** | 访问被拒绝 | 认证失败、授权失败、IP 被屏蔽 |
| **quota** | 用量超限 | Token 限额超限、请求限流触发 |
